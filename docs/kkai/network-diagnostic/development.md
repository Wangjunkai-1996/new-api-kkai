# KKAI 网络诊断浮窗开发文档

状态：实现与验收基线，发布状态以部署记录为准。日期：2026-11-04。设计基线为 [交互预览](./design-preview.html)，角色参考为 [四态透明图集](./assets/kkai-network-atlas.webp)。预览里的延迟、检测进度与结果均为演示数据；产品浮窗由真实请求驱动。当前选定“信号仪表”方向；“云朵陪伴”保留在预览中供视觉对照。

## 1. 目标与范围

用户在控制台点击 KKAI 云朵悬浮入口，主动检测**当前浏览器访问 `https://api.kkrich.ltd` 的 HTTPS 响应耗时**。结果突出成功请求的平均延迟、五次采样反馈及审慎的连接判断。该功能不发送模型请求、不消耗额度、不读取用量日志，也不自动在用户打开页面时发起探测。

浏览器不能执行 ICMP Ping；页面中的“延迟”不是 IP RTT、纯网络 RTT，也不能单独判断 VPN 节点、校园网、Cloudflare 或模型首字慢的根因。浏览器与用户的 API 客户端可能使用不同网络出口。本期只测主 API 域名，不将备用域名、DNS/IP 选择、测速上传下载或自动上报诊断记录纳入首版。

## 2. 交互与视觉

| 状态 | 面板内容 | 角色与动作 |
| --- | --- | --- |
| 收起 | 桌面显示云朵头像、“网络诊断”标签和状态点；手机为紧凑圆形头像和状态点。桌面默认距底部至少 112px，手机至少 96px 加安全区，避开分页区 | 待机每约 6 秒轻微浮动一次，悬停/聚焦挥手；不自动展开、不持续跳动 |
| 待检测 | 标题、固定目标域名、`-- ms`、五个空采样位、“开始检测” | 使用待机姿态 |
| 检测中 | `已完成 n/5`，每次请求结束后才更新一个采样位；按钮禁用 | 扫描姿态与柔和信号弧循环；不可用假定时器推进真实进度 |
| 完成 | 成功采样的平均毫秒数、结论、五次柱形记录、失败次数、“重新检测” | 顺畅用成功姿态；波动/偏慢用担忧姿态；失败位独立标记 |
| 无法判断 | 无成功样本显示 `-- ms`；限频、服务错误和浏览器访问受限显示明确原因 | 担忧姿态，仍可关闭或重试 |

默认浮窗桌面宽约 360–380px，最多占可视高度，数值是第一视觉重点；图集不要遮盖标题、关闭键或结论。沿用现有主题的浅/深色 token 和文字对比度，角色为现有白色云朵、蓝色挎包、粉色脸颊，不换成另一种形象。设计稿的颜色、阴影和模拟控制台仅供视觉参考，不应整段复制到正式应用。状态不能只靠颜色区分。

收起入口在桌面和手机均可直接拖动；约 5px 后认定为拖动，松手不误触展开，轻点仍可打开。桌面入口宽 104px、角色 88px；手机入口为 68px 圆形、角色 56px，按钮的可访问名称仍为“打开网络诊断”。入口位置独立保存在本地，关闭或刷新后恢复；视口缩小时重新约束边界。桌面面板在入口附近展开，允许拖动**面板标题栏/抓手**，不允许从数字、采样图或主按钮起拖。两种状态尽量完整留在视口内并保留约 12px 边距。无需缩放尺寸或第二种“折叠药丸”状态。手机展开后仍为底部弹层，顶部抓手可下滑收起；内容与安全区、软键盘和 320px 窄屏兼容。

打开/关闭约 200ms，检测中信号弧约 1.2s 周期，采样柱在请求完成后约 300ms 更新；成功姿态只做一次短反馈。页面隐藏时暂停纯装饰动画；`prefers-reduced-motion` 下取消位移和循环，但保留可见状态、数值及采样变化。关闭面板、离开页面或重新检测时取消上一轮未完成请求，禁止旧结果覆盖新结果。支持键盘打开/关闭、Esc、可见焦点与结果 `aria-live`；桌面抓手可用方向键移动。角色纯装饰时不应重复朗读状态文案。

## 3. 探测接口契约

新增 `GET /api/network-probe`，目标固定为 `https://api.kkrich.ltd/api/network-probe`。成功响应为 `204 No Content`、零长度正文及 `Cache-Control: no-store`；不查询数据库、不访问上游、不鉴权、不计费、不重定向，也不返回 IP、地理位置或服务器时间。可复用现有 [禁缓存中间件](../../../middleware/disable-cache.go)。CDN/Edge 对该路径也须绕过缓存与挑战；正式验收应检查公网实际响应，不能只测试 Gin handler。

该公开端点独立限频，即使全局 API 限频被关闭也生效。当前按出口 IP 每进程 120 次/分钟限频，不依赖 Redis；多实例之间不共享计数预算，需在生产流量观察中复核阈值是否兼顾校园 NAT 共享出口。`429` 必须成为“检测受限”，不能误判成用户网络差。已有 `/api/status` 返回配置，`/api/status/test` 会查数据库且只对管理员开放，均不用于本功能。[路由中间件](../../../router/api-router.go)与[租户入口](../../../middleware/tenant_features.go)保持首版仅主站可用，不向代理租户放开端点。

前端所在控制台域名可能与 `api.kkrich.ltd` 不同。[当前 `/api` 路由](../../../router/api-router.go)没有通用 CORS 中间件，因此只给**这个探测路径**允许 `https://api.kkrich.ltd` 与平台备用控制台 `https://api.kkai.win` 两个 Origin，并配置 `GET`/必要的 `OPTIONS` 与 `Vary: Origin`；`credentials: omit`，不返回通配凭据许可。必须使用可读取响应状态的 CORS 请求，禁止 `mode: no-cors`。若浏览器仍无法读取响应，显示“浏览器访问受限或连接失败，无法判断”，不能记录为有效延迟。

请求示例：

```ts
const started = performance.now()
const response = await fetch(`${probeUrl}?n=${nonce}`, {
  method: 'GET',
  mode: 'cors',
  credentials: 'omit',
  cache: 'no-store',
  signal,
})
const elapsedMs = Math.round(performance.now() - started)
// 只有 response.status === 204 才保留 elapsedMs。
```

`probeUrl` 必须由已确定的主 API HTTPS origin 生成，不沿用当前页面相对路径，也不接受任意用户输入 URL。`nonce` 只用于避免中间缓存，不作为诊断 ID 或日志键；避免额外自定义请求头。`performance.now()` 从请求发出到收到 204 响应头，包含浏览器调度、DNS/连接复用、TLS、CDN/Edge、回源及少量服务处理时间。首次连接的耗时也计入平均值，因为这是用户感受到的一部分；界面不要把结果称为“网络纯延迟”。

## 4. 采样与判读

一次点击串行发 5 个请求，每个最多等待 4 秒，间隔约 150ms。请求成功仅指可读取的 `204`；超时记为失败样本并继续采样。浏览器拒绝请求时无法区分 CORS 与连接错误，停止本轮并显示“无法判断”；`403`、`429`、`5xx`、重定向或 HTML 挑战也停止本轮，记为“检测不可用/受限”，不纳入网络诊断。失败次数、成功次数始终保留在界面中。

平均延迟 = **所有成功样本毫秒值的算术平均，四舍五入到整数**。超时/错误不记为 0，也不填入超时上限。零个成功样本显示 `-- ms`。五个柱形位置各对应一次实际请求：成功显示相对高度及可访问的毫秒值，失败显示失败标记；没有发出的剩余位置保持未采样状态。

按以下顺序判读。延迟档位是本产品对浏览器 HTTPS 往返的提示标准，不是 ICMP Ping 的行业评分；失败与明显波动优先于平均延迟：

| 条件 | 结论 | 说明 |
| --- | --- | --- |
| `429` | 检测受限 | 不评价网络 |
| 非 204 HTTP 或 CORS/连接错误 | 暂时无法判断 | 不评价网络；必要时提示稍后重试 |
| 成功少于 3 次 | 无法完成检测 | 可展示已成功样本平均值，但不判断稳定性 |
| 3–4 次成功 | 连接有波动 | 显示实际失败次数，不推断具体原因 |
| 5 次成功，`max - min > max(250ms, 平均值 × 0.8)` | 连接波动明显 | 比单次高值更关注波动 |
| 5 次成功，平均值 `> 1000ms` | 当前连接偏慢 | 不声称用户自身网络故障 |
| 5 次成功，平均值 `> 500ms` | 当前连接良好 | 建议只在明显卡顿时对照其他网络重测 |
| 5 次成功，平均值 `≤ 500ms` | 当前连接优秀 | 包含浏览器与 Cloudflare 的 HTTPS 往返，293ms 属于此档 |

短文案控制在一至两行。可建议用户关闭 VPN、换节点或切换手机热点后**重新测量**，但不直接宣布“校园网不行”“Cloudflare 有问题”或“首字慢由用户造成”。

## 6. 验收与发布边界

前端定向验证：5 次 `204` 的平均值与柱形顺序；单次超时、全部失败、`403/429/5xx`、CORS 失败；关闭/重开/重测与旧请求取消；拖动边界、窗口缩小后位置复位、键盘抓手、320px/390px 手机下滑收起；浅/深色、长翻译、减少动态效果、后台标签页暂停。测速断言使用受控时钟/请求替身，不依赖真实公网耗时或睡眠断言。

后端定向验证：`204` 空正文、禁缓存、无数据库/模型调用；限频及 `429`；允许和拒绝的 Origin、非主站租户边界。集成验收须从实际控制台 Origin 打开页面，确认公网 `api.kkrich.ltd` 返回可读取的 `204` 且不被 Edge 缓存或挑战，再用两种明显不同的本机出口做人工对照。设计预览的按钮和数字不构成上述验收证据。
