## 数据与事务

采用 8 张增量伴随表，保持旧订阅表和旧订阅金额含义不变：

| 表 | 用途 |
| --- | --- |
| `kkai_membership_catalog` | 当前发布指针、销售开关、充值优惠切换状态 |
| `kkai_membership_releases` | 不可变完整目录与折扣版本，含发布人和时间 |
| `kkai_membership_groups` | 稳定组标识、停用墓碑；首次发布字段仅保留历史，不决定当前折扣 |
| `kkai_membership_users` | 每个用户唯一当前账户与待付订单指针 |
| `kkai_membership_accounts` | 独立会员额度、已结算、暂占、等级和到期时间 |
| `kkai_membership_orders` | 不可变购买条款、支付发起状态和订单处理结果 |
| `kkai_membership_payments` | 独立核实收款事实，包括成功订单的额外收款 |
| `kkai_membership_billing` | 请求资金来源、完整价格快照、预留、实计、实扣、平台差额及核账状态 |

新购、升级、预留和最终结算以数据库为准。升级保持账户 ID、已消费和在途预留不变，
增加新套餐完整额度，换为目标订单条款并重新计算 30 天。到期或耗尽后重购创建新账户，
旧请求返还不会进入新账户。稳定 tier ID 相同的有效会员不能借修改 rank 重复购买。

MySQL/PostgreSQL 的更新锁统一经 `lockForUpdate`；SQLite 使用条件更新及有限整事务重试。
折扣发布对当前目录指针加更新锁，预扣及付款开通通过 `lockForShare` 读取当前目录，
允许请求并发读取，并与发布互斥；MySQL 5.7 由驱动转换为 `LOCK IN SHARE MODE`。
新预扣核对报价的目录版本，版本过期则要求重新报价；已有预扣重放仍返回原记录。
资金变化、账本幂等状态和普通请求消费统计同事务提交。图片、Midjourney 与原生 Task
通过 `billing_scope` 隔离并接入各自账务流程。原生 Task 普通完成先原子保存终态及应计
金额，再由原生结算和 outbox 恢复推进，不能概括成所有完成状态与资金同事务；人工结案
则通过所属任务的事务钩子，将任务状态、资金、统计、审计及 outbox 一起提交。

旧有效订阅走原计费路径。新旧有效订阅和待付订单在创建及付款时互斥；切换前旧订单已到账
但无法履约时保存 `paid_exception`，重复回调仍幂等确认，不能回滚已收款事实。

## 定价与扣费

在实际可用组上计算：正式优惠 `D < 1` 时取 `min(U, B × D)`，否则使用 `U`。
钱包始终按 `U`。订阅预算不足时整笔按钱包价格重新授权，不能沿用订阅价格或混扣。

请求预留成功后冻结模型价、组倍率、会员折扣、表达式、工具价、其他倍率和 quota 单位。
价格、原资金来源及计费组在内部重试时保持不变。后台改价、会员升级及到期不追改在途请求。
所有有效新老会员的新请求通过当前已发布目录读取其档位折扣，包含已有组和新增组的后续
调价；不再由账户购买版本或组首次发布版本决定系数。不可变目录版本继续用于审计，
订单金额、额度和有效期保持原条款；已预扣请求的完整价格快照不因目录发布改写。

最终结算：

```text
实际扣款 = min(冻结规则计算的应计额, 已授权预留)
平台差额 = max(应计额 - 实际扣款, 0)
```

超额保留应计与实扣两个值、管理员审计和告警；不继续扣钱包，不形成负余额。
违规费用使用授权时冻结的费用规则，与已知部分用量在同一授权内结算，不另跨来源扣款。

## 最大费用契约

本地 token 估算只作估价辅助，不能作为图片、音频、服务端历史和工具调用的最大量证明。
管理员在 `model_limits` 为模型登记上游强制的整次请求累计上界，并填写核实依据：

- `max_input_tokens`、`max_output_tokens`：包含历史上下文、缓存、多模态和内部工具循环。
- `max_tool_calls`：没有客户端次数参数的搜索等调用所需上游硬上限。
- `task_usage_limits`：按任务表达式 `u("字段")` 登记每任务累计使用量上界。
- `evidence`：上游文档或可核实的强制配置依据。单次 context window 不能冒充多次内部调用的累计量。

普通生成请求仍要求显式有限输出参数，真实上游转换后的输出、份数和工具次数会再次校验。
音频及原生图片没有同样的输出参数时使用已核实的上游累计边界。没有依据的 token/任务模型
会在调用上游前明确拒绝；填写一个偏低数值并不能把正常费用变成“异常超额”。

表达式先冻结请求及时间派生的数值/布尔条件，再以区间运算覆盖所有计费分支。
支持算术、条件、`tier`、`fixed`、`abs`、`ceil`、`floor`、`min`、`max` 和有界 `u`。
分母可能为零、不支持的运算或无上界的用量会在发送前拒绝。不会以单次最大 token 样例
代替上界证明，也不会持久化原始请求正文、请求头或令牌秘密。

参数覆盖不能在授权后改写已计价的请求正文；`stream` / `stream_options` 传输设置除外。
模型限额与价格应对所有可能路由的上游成立，而不只是某个渠道。

### Realtime

每个 `response.create` 有独立预留、冻结报价、截止时间和终态结算；不同轮可以自动从订阅
转为钱包，同一轮不能混扣。写出上游帧前记录 dispatch，匹配的 `response.done` 且用量
完整合法才结算，断线后在原截止时间内继续接收晚到的用量或可信策略事件。

安全接口约束显式返回错误：要求手动响应模式并等待上游确认；禁止并发响应、独立转写、
托管工具、图片输入、显式无限输出、额外倍率，以及依赖请求/请求头/时间的 Realtime 表达式。
Beta 的 `turn_detection: null` / `create_response: false` 与 GA `audio.input` 对应设置均支持。
客户端函数工具可用。未提供输出参数时发送目录中的有限最大值；显式 `"inf"` 不会被偷偷截短。

这些是本分支的调用契约；依赖自动 VAD 或独立转写的现有客户端不能直接启用此路径，
应在上线前完成适配或补齐对应事件的预授权实现。运行开关默认关闭，不会静默回退旧钱包扣费。

### Midjourney 与原生 Task

Midjourney 使用既有任务行及会员账本，不新增 MJ 表或字段。发送上游前在同一事务创建
本地任务和完整固定价预留，使用 `mj:<本地任务 ID>` 关联；会员额度不足则整笔按钱包价
授权。受理码 1/21/22 继续保留预留，可信渠道轮询的 `SUCCESS` 按冻结价结算，明确
`FAILURE` 返还原来源；已完成的免费操作可直接结束。未认证的旧通知不能结算会员任务。
不明确响应仅提交上游一次，返回 502 和 `X-Midjourney-Task-Id` 供查询，并进入人工核账。
缺少上游 ID、缺少渠道或超过一小时都不能自动退款；人工结算保持结果未知，不伪造图片成功。
旧有效订阅及功能关闭时保持原路径，历史任务查询不依赖会员表存在。

原生 Task 复用既有任务账务和恢复机制，未知提交、缺失上游 ID 或超时保留原预留。
只有真实上游 ID 才能用于轮询；仍有可信 ID 的未知任务可继续安全查询，不重新提交。
任务恢复流程确认不确定状态后才开放人工核账，不能单凭账本年龄处理仍在提交的任务。
已人工结案的任务拒绝晚到受理、轮询终态及费用重算再次改账。

## 未知结果与恢复

普通 HTTP 与 Responses WebSocket 发送前记录渠道和实际强制的截止时间。
普通请求默认总上限为 1 小时；已有更长 Relay/Streaming 配置继续保留，已有更早 context
截止时间优先。安全重试不会延长同一请求的授权时间。Realtime 使用逐轮有界时间。

只有明确结构化、无用量迹象的预执行拒绝或确认尚未发送，才允许清除当次 dispatch 并重试。
5xx、重定向、不明确响应和发送后断线保持预留，禁止盲目重新调用。

流式文字片段和本地 token 估算不证明上游已停止收费。没有可确认终态的中断保留预留；
Responses 区分终态上游 usage 与本地估算，显式零费用不会被 prompt 估算覆盖。

Image Studio 保留既有的按安全交付图片收费契约：只有归档且可交付的结果计费，部分
交付按实际张数折算。恢复时无法安全交付的资产先被丢弃，再把预留返还原来源；这类
未交付的上游成本由平台承担，不能误退到钱包，也不会重新发起供应商请求。普通图片
API 的未知上游结果仍走普通 relay 核账规则，不能把两条入口混为同一种退款条件。

进程中断后的孤立预留按持久化截止时间及结算宽限进入人工列表；查询列表不改钱。
管理员凭核实结果在原来源释放或在原授权内结算，必须填写幂等操作号、原因和实计金额。
共享人工核账覆盖普通 relay / Responses WebSocket、Realtime 响应轮、Midjourney 和原生
Task，按各自状态限制可处理范围。进行中的普通/Realtime 调用及仍在提交的原生任务
不能人工处理；异步任务超时只触发核查，不证明零费用。确认用量只在原预留内结算，
确认零费用失败才释放原来源。Image Studio 继续按上述安全交付契约自行恢复。

普通请求公共消费日志仍沿用既有独立日志写入，因此资金事务成功后进程中断可能缺少一条
公共展示日志；资金账本、冻结价格和用户/渠道统计不会因此重复或丢失。该日志原子性边界
需纳入发布验收，不能把展示日志当作唯一资金凭证。

## 支付、接口与页面

支付复用 Epay、Stripe 单次 payment、核实后的 Creem/Pancake 一次性产品。
浏览器返回不代表付款成功。checkout 发起采用持久化 claim/save：外部创建结果未知时不会
重发新交易。重复通知、额外收款、迟到收款、金额/币种/模式不符均保留交易事实及处理记录。

`/api/membership` 提供目录、本人账户、订单和继续支付；Root 管理接口提供整批发布、
订单异常处理和 `billing-reviews` 人工核账。发布校验每组 `王者 ≤ 钻石 ≤ 黄金 ≤ 1`、
稳定键、版本并发和有效条款覆盖。新充值移除折价/赠额，旧待付条款与已有余额保留。

default 前端新增 `/membership`，沿选定卡片布局呈现三档、本人当前权益、在售权益、
剩余/可用/暂占额度和全价升级确认；钱包保留入口。现有订阅管理新增会员配置及核账页签。
价格展示使用服务端会员价与钱包价，不在前端再叠乘折扣。首发配置为 CNY ¥600/¥2000/¥5000，
额度显示值为 600/2000/5000（沿用现有额度显示单位，默认 USD），内部 quota 按当前
`QuotaPerUnit` 换算。支持 7 种现有 locale、明暗主题、手机及键盘操作。具体测试与截图见
`subscription-membership-frontend-validation.md`。
