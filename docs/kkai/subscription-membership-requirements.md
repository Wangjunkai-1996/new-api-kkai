# KKAI 订阅会员需求定稿

确认日期：2026-10-17。本文记录本轮逐项确认的最终业务规则，供后续实现和验收使用。
本文不是功能已实现、已测试或已上线的证明。后续明确修改优先于本文；本轮早期被覆盖的
方案不得重新作为开发依据。

2026-10-22 规则变更：后台发布折扣后，所有有效新老会员的后续新请求统一采用当前档位
的最新折扣，不再按购买版本或新增组首次发布版本锁定系数。已预扣请求继续按其完整
请求快照结算；订单实付金额、额度、有效期及历史记录不追溯改写。以下条款已同步此规则。

2026-10-26 计费规则变更：新请求按请求信息估算预扣，实际费用超过预扣的部分由平台
承担。已受理请求继续按各自冻结的报价结算；以下计费条款已同步此规则。

## 1. 目标与首发参数

目标是让常用用户预付调用额度，提高月度复购与收入。沿用现有订阅、钱包、支付和计费
基础，支持后台动态管理会员档位及计费分组，不写死 VIP、SVIP 或分组名称。

2026-10-18 补充：首发按黄金、钻石、王者三档规划，等级依次递增。名称仍通过后台配置，
不写死在计费逻辑中。用户已选择第一种「会员卡片」布局：当前会员状态、三档卡片、
逐组优惠对照。黄金用香槟金、钻石用冰蓝、王者用紫金；页面细节在实现中完善。

首发三档正式售价与额度如下，币种为人民币，额度沿用现有充值的站内额度显示单位，
按 1:1 配置；不赠送额外额度，优惠只体现在逐组倍率：

| 档位 | 售价 | 额度显示值 | `price_minor` | 默认 `QuotaPerUnit=500000` 时的内部 `quota` |
| --- | ---: | ---: | ---: | ---: |
| 黄金 | ¥600 | 600 | 60000 | 300000000 |
| 钻石 | ¥2000 | 2000 | 200000 | 1000000000 |
| 王者 | ¥5000 | 5000 | 500000 | 2500000000 |

后台额度输入必须沿用当前全局额度显示配置；默认显示 USD 时直接填 600、2000、5000，
后端按当前 `QuotaPerUnit` 换算成内部 quota。不要把原始 600/2000/5000 直接写入
数据库，也不要因为单次预扣上限为 `int32` 而把套餐总额截断。各档逐组相对折扣系数仍由
管理员自行配置，并遵守同组高档不高于低档的校验。

## 2. 会员档位与购买

- 档位独立配置名称、售价、额度、等级顺序及各计费组折扣。
- 等级顺序显式配置，不根据名称或价格推断；允许跨级升级。
- 一个用户同一时间只有一个有效会员等级，会员身份与原用户基础分组分离。
- 一次性外部付款，支付确认成功后立即生效；不提前发放权益。
- 会员不能使用钱包余额购买，不做自动续费、自助取消或主动退款功能。
- 会员有效且尚未耗尽期间，只能升级到更高档，不能购买同档、降档或创建并行会员。
- 不做提前续期排队、按日折价、差价退款或旧有效期叠加。
- 到期或额度实际耗尽后，可以立即重新购买任意档位，无需等待旧的计划到期时间。
- 新购买产生新的额度和有效期，不恢复旧套餐。
- 下架档位只停止新购，不取消已购会员权益。

购买互斥必须覆盖下单、支付确认及并发场景。不能把历史累计购买次数限制当作有效期内
重复购买限制，也不能收款后仅拒绝回调而丢失异常收款记录。

## 3. 有效期与额度

- 每次开通按固定 `30 × 24` 小时计算，从支付确认成功的生效时刻开始。
- 使用服务器时间，到期精确到秒，无额外宽限期。
- 套餐额度一次性发放，不每日、每周或每月重置。
- 各计费组共用会员额度，不拆成不同模型的专用额度余额。
- 会员额度与钱包余额分开管理，不互相兑换。
- 订阅额度实际耗尽或有效期到期，任一发生即结束会员权益。
- 到期剩余额度失效，不结转、不提现、不转入钱包；历史记录仍保留。
- 已有钱包余额不因会员到期、耗尽或新制度上线被清零或追溯修改。

### 状态

| 状态 | 业务含义 |
| --- | --- |
| `active` | 未到期、未撤销且额度尚未实际耗尽 |
| `exhausted` | 最终结算确认额度已用完，会员优惠结束 |
| `expired` | 有效期已到，剩余订阅额度不可继续使用 |
| `cancelled` | 管理员取消或经核实的支付异常导致权益撤销 |

预扣占用全部可用额度不等于实际耗尽，不能提前把会员判为 `exhausted`。
升级后旧会员不再有效，历史与结算记录保留；具体存储方式由实现确定，不恢复旧等级。

## 4. 升级

- 升级支付目标高档套餐全价，旧会员立即被替换。
- 目标档位完整额度正常发放，原会员剩余额度原数保留并合并。
- 不按折扣比例换算原额度，不折现、不退差价。
- 新额度和原剩余额度统一在升级成功后 30 天到期，不再沿用旧到期时间。
- 升级后，新请求采用目标档位当前已发布的各组折扣；后续发布与该档其他有效会员同步生效。
- 不继承、不比较旧会员折扣，不做购买版本或跨版本升级保价。
- 合并额度统一使用新等级计费规则，仍与用户原有分组优惠比较取低。
- 新会员到期或耗尽后，不回退到升级前的会员等级。

示意：原剩余 200，新套餐包含 1000，则升级后合并为 1200，统一使用新的有效期。
示例不是正式套餐参数。

## 5. 分组与使用权限

- 计费分组动态读取，不写死数量、名称或固定分组清单。
- 每个分组使用稳定标识关联折扣和历史记录，该标识创建后不可修改、不可复用。
- 显示名称可修改，改名不丢失已配置折扣或历史计费记录。
- 停用分组后不能调用，但保留历史账单和折扣记录。
- 恢复同一分组时继续按原规则；重建的同名分组是新分组，不继承旧标识的折扣。
- 订阅额度适用于用户原本有权使用的全部计费组，包括没有会员折扣的组。
- 新增分组只要对用户开放，就支持订阅额度支付。
- 会员不额外解锁模型、渠道或分组权限；访问权限与价格优惠分别判断。

## 6. 各组相对折扣及原用户组优惠

每个会员等级对应一张按计费组配置的相对折扣表，不使用一个全局折扣覆盖所有线路。
未配置折扣时按 `1.00`，高成本线路可以不提供额外优惠。

对本次实际使用的计费组 `g`：

```text
B(g) = 该计费组当前基础倍率
U(u,g) = 用户不使用会员优惠时，按原用户组规则得到的倍率
D(m,g) = 本次新请求授权时，该会员当前档位最新已发布的该组相对折扣系数

会员候选倍率 = B(g) × D(m,g)
有会员优惠时：订阅扣费倍率 = min(U(u,g), B(g) × D(m,g))
无会员优惠时：订阅扣费倍率 = U(u,g)
钱包扣费倍率 = U(u,g)
```

- `B(g)` 不是用户已经享受特惠后的倍率；不能对特惠倍率再乘会员折扣。
- KK 座上宾等原有用户组优惠保留，与会员候选价取低，不折上折。
- 钱包不享会员额外折扣，即使会员尚有额度、尚未到期也一样。
- 无会员额外优惠的线路，订阅按用户原有倍率扣费。
- 未配置或系数为 `1.00` 时属于无额外优惠，直接使用原有倍率；不能因为用户原有倍率
  高于基础倍率，就通过 `min(U, B × 1)` 意外降价。
- “钱包按普通价”指按用户原有非会员计费规则，并非强行取消其原有用户组优惠。
- 展示、预扣和最终结算采用同一套价格规则，不维护独立的展示价格副本。

示意：基础倍率 `0.2`，会员系数 `0.95`，会员候选倍率为 `0.19`；若用户原有倍率为
`0.15`，订阅实际使用 `0.15`，钱包也使用原有 `0.15`，不会再乘一次 `0.95`。

### 同一版配置的等级校验

每个计费组分别满足：

```text
高等级折扣系数 ≤ 低等级折扣系数 ≤ 1.00
```

相等允许，高等级更贵则标出冲突分组及档位并拒绝保存。未配置按 `1.00` 参与比较。
前后端都必须校验，不能绕过页面提交非法配置。

上述排序约束针对同一版配置；所有有效新老会员的新请求均使用最新发布值，不按购买版本保价。

## 7. 折扣版本与新增分组

- 后台发布逐组折扣后，所有有效新老会员的后续新请求统一采用当前档位最新发布值；
  折扣提高或降低均生效，不受购买日期、订单版本或分组首次发布版本限制。
- 基础倍率变化后，新请求按当前基础倍率及最新折扣系数重新计算，并保留第 6 节的原用户组取低规则。
- 新增分组尚未正式发布折扣时按 `1.00`；首次及后续正式发布都同步适用于有效新老会员，
  不再维护首发折扣永久锁定规则。
- 升级改变当前档位，新请求采用目标档位最新已发布折扣，不继承旧档历史折扣。
- 目录发布版本、购买条款和历史账本保留用于审计，不重写订单实付金额、额度、有效期
  或已授权请求的计价快照。已预扣请求跨发布仍按其原快照结算和返还。

## 8. 资金选择与预扣

首发对外约定为订阅优先、钱包自动接续，不要求用户另行开启接续。

1. 存在有效会员且剩余额度足以覆盖本次订阅预扣：整笔使用订阅额度。
2. 订阅已到期或耗尽：自动使用钱包，按用户原有非会员倍率计算。
3. 订阅仍有余额但不足本次预扣：剩余额度保留，不取消会员；本次整笔切换钱包，按钱包
   价格重新计算预扣，不能沿用会员折扣后的金额。
4. 钱包预扣仍不足：在发往上游前拒绝，不欠费、不透支、不部分扣款。
5. 后续较小请求仍优先尝试剩余订阅额度。

单请求不做订阅与钱包混扣。不能把“本次预扣不够”当作“订阅已经耗尽”，也不能用钱包
充值恢复已耗尽的会员；恢复会员需要重新购买。

## 9. 请求快照与失败额度返还

- 预扣成功时锁定本次计价规则和扣费来源。
- 请求处理中发生调价、升级、会员到期或状态变化，不改变已受理请求的计价规则。
- 新请求按当时有效档位、最新发布折扣和当前基础价格处理。
- 文本、流式、图片及视频等异步任务遵守同样原则。
- 最终费用按实际应计用量和已锁定规则结算，预扣金额不是最终费用。
- 2026-10-26 调整此前的最大费用预留规则：正常请求按可见输入、请求参数和冻结的
  价格规则估算预扣，不要求为全部模型配置上游强制的累计用量上限。显式数量和输出
  限制须验证；未显式指定输出量的请求按明确的缺省估值预扣。隐藏历史、内部工具调用
  等不可见用量可能使最终应计费用超过预扣，估值不能称为最大费用。
- 用户实际扣款最多为原预扣额；超额由平台承担，保留实际应计额、实扣额和平台差额
  并记录告警，不透支订阅或钱包，也不向另一资金来源补扣。
- 未产生费用的失败请求释放原预扣；实际费用小于预扣时，差额退回原订阅或钱包来源。
- 订阅额度返还不转钱包、不延长有效期；未到期的可用权益按有效状态继续使用。
- 已到期订阅收到返还也不能重新获得有效期。
- 预扣、结算与额度返还均必须防重复，不能重复扣费或多退。

此处返还是请求计费调整，不是退还购买会员的付款。

## 10. 订单快照与异常付款

- 下单冻结售价、币种、额度、有效期和等级，并保留目录版本用于审计；目录版本不承诺长期锁定折扣。
- 支付确认按订单条款开通，不能用管理员后来修改的售价、额度或有效期替换原购买条款；
  开通后的新请求统一采用该档最新发布折扣。
- 修改套餐售价、额度或有效期只影响新订单；折扣发布按第 7 节影响有效新老会员的新请求。
  下架档位只停止新购，不取消已付款订单的权益。
- 同一订单的重复支付通知直接幂等忽略，不重复发额度、不取消已成功订单。
- 未收款且支付失败或超时的订单关闭，不发权益。
- 已确认收款但不能正常开通的订单标记“异常待处理”，不重复发权益，不静默丢单。
- 关闭后又确认到账的订单也进入异常待处理，不直接当作未付款忽略。
- 异常订单保留交易号、实收金额及处理记录，由管理员人工处理。
- 异常付款立即进入异常列表；收到客户提供的交易号后，建议 1 小时内完成首次响应或确认
  已收单，目标在 24 小时内完成核实与处理。客户未联系前不自动退款、取消或发放权益；
  这是一项运营 SLA，不改变订单的幂等和人工核账规则。
- 不新增复杂的自动退款系统；正常购买不提供自助退款或取消。
- 经核实的强制退款、拒付等异常按关联订单处理，不误撤其他正常订单权益。

## 11. 取消充值优惠的范围

- 上线后取消新充值的折价及额外赠额。
- 已有钱包余额不追溯修改。
- KK 座上宾等原有用户组倍率优惠保留。
- 邀请返佣、兑换码不随本次变更自动取消。
- 禁止钱包购买会员的规则保持不变。

## 12. 最小验收清单

| 场景 | 必须成立的结果 |
| --- | --- |
| 两档或更多档、动态新增分组 | 不依赖固定名称和数量 |
| 用户已有更低的组倍率 | 订阅取低，不二次打折；钱包保留原倍率 |
| 订阅不足但余额非零 | 整笔钱包重算预扣，原订阅余额保留 |
| 钱包预扣不足 | 上游请求未发出，不混扣、不透支 |
| 实际应计费用超过请求估算预扣 | 仅扣原预留，平台承担差额并留存审计和告警 |
| 最后一笔预扣后请求失败 | 不提前永久耗尽，准确释放预扣且不重复返还 |
| 升级 | 全价、全额发放、剩余原数合并、新 30 天，新请求采用目标档最新折扣 |
| 已预扣请求跨发布、升级或到期完成 | 按请求原计价快照结算，不临时换价 |
| 会员实际耗尽 | 结束会员权益，钱包自动接续且无会员额外折扣，可重新购买 |
| 会员到期 | 立即停止新请求享受会员权益，剩余额度失效，钱包不受损 |
| 已有组会员折扣提高或降低 | 有效新老会员后续新请求统一采用当前档最新发布值，历史订单和在途快照不改 |
| 新分组首次及后续发布折扣 | 有效新老会员同步采用最新值，不按首次发布永久锁定 |
| 高档某组比低档更贵 | 前端标明冲突，后端也拒绝保存 |
| 分组改名、停用、恢复或同名重建 | 稳定标识和历史权益不串用 |
| 重复回调、关闭后到账、并发付款 | 不重复开通，不丢异常收款，不误撤其他权益 |
| 取消充值优惠 | 新充值无折价和额外赠额，历史余额、原用户组优惠、邀请及兑换码保留 |

## 13. 实现阶段需要验证的边界

以下是技术验证与设计工作，不是新增套餐规则，不能假设现有代码已经具备：

- **请求估算与异常超额**：逐调用类型核查估算预扣、实际费用、封顶扣款及平台差额。
  不能以事后报错代替已发生的上游成本记账，也不能静默改用钱包补差；没有上游累计
  用量上限的路径仍须估算、校验可见数量并记录超额，不能暗中遗漏调用类型。
- **升级及重新购买与在途请求并发**：准确归属原请求的占用、结算和返还；不重复发放
  合并额度，不复活已替换的旧等级，不形成两个有效会员。
- **到期与缓存**：报价、鉴权及预扣使用同一有效权益判断，缓存不能让新请求跨到期
  继续享会员价；后台维护只作为一致性补偿。
- **订单与支付通道**：验证真实金额、币种、支付模式及订单身份；只启用符合一次性
  付款规则的通道，不把自动订阅支付接口直接当作单次月卡。
- **动态分组身份及历史规则**：核实现有分组是否有不可变标识，确定兼容方式；已有组及
  新增组的多次发布均须覆盖有效新老会员，不能误改历史表。
- **折扣发布和授权时点**：校验整批发布及并发预扣的版本一致性；新请求采用最新发布值，
  已授权请求保留完整原快照。支付前后调价不改变订单金额、额度或有效期。
- **上线切换**：核查切换前未完成充值订单及原有订阅数据的实际存在情况，保留原订单
  已承诺条款，不根据历史聊天推断线上状态。本轮尚未授权生产访问、迁移或上线。
