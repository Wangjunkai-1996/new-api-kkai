## 2. 基线与实施现状

- 最终视觉源是 [prototype.fragment.html](design/prototype.fragment.html)，原名 `video-works-complete.html`。六张最终截图与原文已归档；[manifest.json](design/manifest.json) 记录源文件名、尺寸、大小、分类和 SHA-256。早期单插画版本不再作为开发基准。
- 文档以本地源码快照为依据；基线 HEAD 为 `4a863100250fc0232abebf296dd8506341fbf705`。任务相关控制器、DTO、计费、前端列及翻译已有未提交草稿，均须对照本包重新评审，不等于最终方案已实现或已上线。
- 原型检查属于设计证据。实际 React 页面已另做本地浏览器夹具检查，后端使用 SQLite/HTTP 夹具验证公开契约与权限；两者的证据和环境联调缺口分别记录在实现报告。
- 文档中的筛选、金额有效性、媒体投影和附件下载已落地；部署是否支持真实视频托管、封面处理和签名存储没有在本轮检查。读取源码及本地夹具通过均不证明生产能力。

## 3. 已固定的技术决策

| 决策 | 对实现的约束 |
| --- | --- |
| 入口名为“视频作品” | 沿用 `/usage-logs/task` 与权限配置键，仅改任务视图；普通日志、绘图日志保留各自语义 |
| 真实封面是核心内容 | 复用现有 Video Studio 输出资产与封面链路，按任务权限批量投影；正常托管成功视频不得全部退化为占位图 |
| 生成进度不显示百分比 | 当前 `progress` 混有阶段占位，第一版仅显示排队/生成中等状态；生成或托管媒体处理中每 10 秒刷新，仅剩待计费记录时每 15 秒刷新，不承诺实时进度 |
| 生成、媒体、计费相互独立 | 失败不等于已退款，成功不等于已结算，签名过期不等于视频永久失效 |
| 账务只读且可追溯 | 只用当前额度和冻结计费快照；没有可靠原预扣/退款流水就明确缺失；`completed` 默认“计费已处理”，未知金额显示 `—` |
| 媒体按需加载 | 列表批量给出媒体摘要和获授权封面；打开作品再取播放/下载地址；不逐行查制品、不下载全部视频抽帧 |
| 复用已有应用体系 | React、TanStack Query、Base UI、Hugeicons、现有货币格式器及七语言 i18n；不引入新播放器、状态管理或图标库 |
| 高还原验收独立进行 | 固定数据、视口、字体和主题做实现截图对照；视觉、功能、权限三项均通过才可交付 |

## 4. 开发顺序与完成门槛

| 阶段 | 责任 | 输入与产出 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| D1 契约落地 | 后端主责、前端复核 | 当前任务模型 → 视频查询、状态统计、金额有效性、获授权媒体摘要/制品响应 | 字段有来源、权限有测试方案；缺失态/历史兼容明确；不扩展计费写入或数据库结构 |
| D2 视觉实现 | 前端主责、设计验收 | 固定且明确标识的夹具 + 归档资源 → 桌面/手机、深浅色、预览/扣费/所有空错态 | 对照截图通过；信息顺序、尺寸、主题、图标、动作与最终稿一致；真实壳层差异记录清楚 |
| D3 数据联调 | 前后端共同负责 | D1 接口 → 真封面、权限、筛选分页、受控刷新、播放下载、账务缺失态 | 移除生产中的样例数据；正常路径能看到真实作品和真实金额；不把原型 toast 当功能 |
| D4 定向验证 | 测试主责、开发修复 | 真实 React 夹具证据 + 本地/测试后端证据 → 验收记录 | 视觉及功能阻断项清零，相关测试/lint/类型检查通过，未覆盖项明确 |

D1 与 D2 可并行，但 D2 必须使用同一版契约，不自行猜字段。D3 完成前不得以“视觉已还原”代替开发完成。实现中的临时降级必须写入未完成清单；不得用更新设计基准掩盖偏差。

## 5. 当前验证边界

页面、契约、媒体投影和扣费展示的实现差距已落地，交叉审查问题已修复。当前未覆盖真实 PostgreSQL/MySQL、R2/CORS/线上素材、完整应用路由类型图及手机 Safari；本地浏览器使用固定 API 和 MP4 夹具，不能替代目标环境验收。详细结果及截图见 [实现与验证记录](implementation-review/README.md)。

不新增数值进度协议、媒体永久留存承诺、批量重新生成、退款功能、数据库迁移或生产配置操作。全量测试、全站 lint/typecheck/build 未运行；生产发布需另按既有 runbook 和授权范围执行。
