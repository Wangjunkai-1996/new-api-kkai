# 视频作品：产品需求基线

本文把用户已确认的入口名称、最终设计稿和实际数据约束整理为本次开发需求。它是本功能的统一交接基线，不代表所有界面已实现。

## 1. 用户目标与范围

用户进入“视频作品”后，应能快速找到自己生成的视频，识别使用的模型和生成状态，播放/下载结果，并理解这次生成的扣费。管理员可在已有权限范围内查看全部作品或仅看自己的作品。

| 项目 | 本期要求 |
| --- | --- |
| 入口与路由 | 菜单、标题、相关设置显示“视频作品”；沿用 `/usage-logs/task` 与原权限配置键，旧深链仍可用 |
| 数据范围 | 页面只展示视频生成任务；服务端在分页前过滤，不能用当前页浏览器过滤伪装完整视频列表 |
| 目标用户 | 普通用户查看本人；平台管理员查看全部/本人；root 额外信息仍受现有权限控制，不新增租户跨用户查看能力 |
| 核心任务 | 找作品、看模型与状态、预览/下载、看扣费、查看失败原因、复制任务 ID |
| 视觉基准 | 完整设计稿的桌面行、手机卡片、深浅色、插画/工具、预览、扣费与空错态 |
| 影响边界 | 任务视图及其入口文案；普通使用日志、绘图日志、视频工作室生成流程不重做 |

不在本期新增收藏/重命名/分享/批量导出、重新生成、退款操作或素材留存设置。视频作品页面中的重试仅重新加载数据或媒体。

## 2. 信息结构与优先级

| 优先级 | 界面信息 | 规则 |
| --- | --- | --- |
| 第一层 | 真实视频封面、模型名、生成状态、扣费金额、查看作品 | 成功作品可直接辨认并打开；金额明显；生成状态不被插件/渠道信息淹没 |
| 第二层 | 文生/图生等生成类型、可信成片规格、提交时间、任务 ID、扣费明细 | 参数缺失不造值；ID 视觉省略但可完整复制；金额对应明确账务状态 |
| 第三层 | 用户、渠道、失败原因、计费规则、管理详情 | 用户/渠道按权限显示；长原因/规则进入弹层，保留列表简洁度 |

桌面按“作品 / 生成状态 / 提交时间 / 扣费 / 操作”排列；手机用顶部视频、下方模型与金额、卡内底部工具条。作品是主内容，页头插画用于识别主题。页头和四种状态使用不同专用插画；工具使用统一矢量图标。

模型以任务保存的原始请求模型优先，必要时回退保存的上游模型；仍缺失显示“未知模型”。不能用渠道或插件名代替。分辨率、时长、生成耗时仅在有对应来源时显示，不能把计费倍率当媒体规格。

## 3. 页面与操作需求

| 编号 | 需求 | 验收对应 |
| --- | --- | --- |
| P01 | 入口和标题一致；普通用户本人列表、管理员全部/本人范围切换清晰；身份变化清掉旧数据和弹层 | V01、权限门槛 |
| P02 | 支持任务 ID/模型查询、日期范围、状态、管理员渠道、重置与分页；条件可组合，变更回到第一页；旧深链仍能解释 | V02 |
| P03 | 标签含全部、已完成、生成中、失败；数字来自后端同一范围统计，不能只数当前页；未知状态保留在全部中 | V02 |
| P04 | 点击成功封面或“查看作品”进入同一预览；视频可播放、暂停、拖动、静音与全屏；多个制品可切换 | V04、V05 |
| P05 | 下载是真实文件下载；复制得到完整任务 ID；任务详情与扣费详情有明确入口，失败操作有反馈 | V07 |
| P06 | 进行中显示可信阶段并自动刷新；没有可信进度来源时不显示百分比/预计剩余时间 | V08、V09 |
| P07 | 列表和扣费抽屉使用同一金额；规则解释来自提交时冻结快照；未知或缺失字段有清楚说明 | 账务门槛 |
| P08 | 首次空态引导有权限的用户去视频工作室；筛选无结果保留条件和重置；请求失败独立展示错误和重试 | V03 |
| P09 | 桌面、手机、深浅色保持同一信息优先级；小屏无横向表格；键盘和触屏可完成全部动作 | 高还原度、无障碍门槛 |

默认最近的时间范围沿用现有页面约定；日期可选今天、最近 7/30 天和自定义范围。快捷日期按用户时区确定，使用提交时间筛选；不因设计稿展示“今天”而把历史视频永久藏起。每页默认 20 条，精确参数见后端契约。

## 4. 三类状态分别表达

| 情形 | 主展示与插画 | 可执行动作 | 扣费处理 |
| --- | --- | --- | --- |
| 生成成功，真实视频可用 | 真实封面、已完成、查看作品 | 预览、下载、复制、详情、扣费 | 按真实计费状态；不因生成成功自动写已结算 |
| 排队/生成中 | 对应阶段文字、生成中插画 | 查看状态、复制、扣费、刷新 | 有预扣事实才显示已预扣；终态金额未定不伪造 |
| 生成失败 | 失败插画、简短原因 | 查看原因、复制、扣费 | 有退款事实才显示已退款；失败本身不证明免费 |
| 成功但无封面 | 中性视频占位，保留真实任务信息 | 实际视频可用时仍可预览/下载 | 不受封面失败影响 |
| 临时网络/播放错误 | 暂时无法加载、重试 | 重新加载、可用时下载 | 不改变生成或计费结果 |
| 获授权签名 URL 到期 | 重新获取地址，必要时提示重新加载 | 续取授权地址后预览/下载 | 不标记作品永久过期、不退款 |
| 媒体明确过期/已不可恢复 | 专用失效插画与准确原因 | 详情、复制、扣费；不下载失效媒体 | 保留生成结果及原扣费；不可用不是退款依据 |
| 结果明确未保存 | “结果未保存”，不伪造封面 | 详情、复制、扣费 | 独立显示真实账务 |
| 首次无作品 | 空态插画、简洁引导 | 有入口权限时去视频工作室 | 不显示假统计或示例账单 |
| 筛选无结果 | 搜索图标、重置条件 | 修改/重置筛选 | 不覆盖筛选器 |
| 列表请求失败 | 加载失败、重试 | 重试原查询 | 不把错误显示为空列表/零消费 |

通用 HTTP 404 或播放器 `onError` 不足以判断“链接已过期”。具体状态和错误码以后端契约为准。状态文字始终独立存在，插画和颜色不能代替信息。

## 5. 扣费明细的可解释范围

列表突出可信当前扣费/当前预扣，抽屉展示其状态、来源及可公开的冻结价格、计费单位、用量和倍率。使用用户现有货币/额度显示设置，设计中的美元只是样例。

- `reserved` 可以表示当前已预扣；`refunded` 表示已退款事实；底层 `completed` 默认只显示“计费已处理”。“已结算/实扣”必须额外具备真实结算证明。
- 金额未知显示 `—`，不把缺字段/转换失败显示为 0。已知 0 可以显示为 0，但不能据此推断已退款或模型免费。
- 原预扣、累计退款、最终扣费的完整流水当前没有可靠公开契约。本期不补写账本；缺失时明确“暂无完整流水”，保留有依据的金额和计费规则。
- 不能用“预扣减当前扣费”倒推退款，也不能把会员节省当退款。历史规则缺失时说明缺失，不拿今日价格补算。
- 动态表达式、内部渠道成本、管理审计遵循已有公开/管理字段边界，不向普通用户输出私有数据。

这些约束会使部分真实记录的文案不同于设计里的演示“已结算”；保持金额、状态和明细区域的视觉层级，不为了逐字相同而写入错误事实。

## 6. 素材与质量要求

正常托管成功任务必须使用该作品对应的真实封面。归档的海景/汽车图片仅用于带标记的设计审查和固定测试夹具，禁止用作真实任务的默认图。历史没有封面或封面加载失败才使用中性降级；“全部用占位图”不算完成批准的视觉方案。

五组插画和完整工具图标规则见素材规范。图标不需要低分辨率切图；沿用项目矢量系统能保证深浅色、缩放和交互状态一致。文案、Tooltip、aria 标签覆盖现有七语言；长语言不靠缩小字体或隐藏金额适配。

必须同时交付真实功能与高还原截图证据。精确尺寸、主题和基准见设计与前端文档；误导账务、假进度、示例图冒充作品、权限泄露、核心操作失效及明显布局偏差均阻断交付。
