# 钱包充值订单 UI 设计说明

**2026-10-23 生效修订：** [本站超时与废单规范](./wallet-payment-local-timeout-spec.md)已获用户确认，统一规定本站 30 分钟期限、本地结束／超时结果及“返回充值”、废单禁止继续支付／人工补单、晚到款继续处理。本文下方与修订冲突的“仅本地超时不能结束、未知永久锁定、30 分钟仅期望、废单仍可人工核实”条款停止适用；其余资金、权限和互斥布局要求保留。

日期：2026-10-23。状态：已确认的开发基线；当前本地实现、验证与渠道限制见 [实施记录](./wallet-payment-implementation.md)。下文“本轮只编写文档”等内容保留为设计阶段记录。
本稿与 [产品 PRD](./wallet-payment-lifecycle-prd.md)、[技术方案](./wallet-payment-lifecycle-plan.md) 配套。

本轮按用户纠正更新：主流程必须在钱包页直接成立。支付在外部新标签页打开，关闭支付标签页后，
用户回到钱包即可对有效当前订单“重新打开支付页面”“结束本次充值”，或按渠道能力“取消订单”，无需先进订单记录。
这项明确要求取代前版默认同标签支付、以订单记录为主入口的设计建议。

最新布局约束进一步明确：**钱包主区采用互斥阶段，当前订单存在时只显示订单详情，不叠加独立余额卡、充值表单或购买入口。本站期限为创建后 30 分钟，已知渠道截止更早则取更早值；没有已确认收款时，到期即显示“本次充值已超时”及明确主按钮“返回充值”，主动结束显示“本次充值已结束”。用户点击并经服务端确认精确流程后才恢复表单，原记录保留；本地结束不宣称外部支付页已关闭。** 已到账、用户主动取消和可靠失败同样保留结果确认。前版订单卡与表单并存、到期后自动跳回表单的要求均已作废。

## 设计方向

沿用现有钱包，将主区设计为单一阶段容器：空闲时展示余额与充值表单，购买后整区切换为当前订单详情。
订单阶段不在上方额外堆叠余额卡，也不在下方保留充值表单或购买按钮。
页面保持中性卡片、细边框、简单圆角，让用户在同一位置完成购买、重开支付、取消、结果核实和查看明细。
订单记录弹层是其他订单与历史的二级入口；桌面使用宽弹层，手机使用全屏记录。
详情与取消确认在当前所在订单卡片内展开，不叠加第二层抽屉或二次全屏弹窗。

只有这一套设计。普通用户、管理员以及手机、桌面是同一设计的权限与响应式状态，不是不同方案。

## 信息布局

钱包页面标题与“订单记录”二级入口保留，主区只能处于以下一个阶段：

| 阶段 | 主区显示 | 表单与购买入口 |
| --- | --- | --- |
| 空闲 | 余额与充值表单 | 可见，可提交一次购买 |
| 创建中 | 创建进度或创建结果核实 | 完全隐藏 |
| 当前订单 | 冻结订单详情与重开／结束本次充值／按能力取消／刷新 | 完全隐藏 |
| 支付／取消处理中、待核实 | 订单详情、进度与按能力结束／核实／客服 | 完全隐藏；未结束且未到期无返回充值，已确认收款继续核实 |
| 本地超时／结束结果 | “本次充值已超时／已结束”、主按钮“返回充值”和查看原记录 | 无须等待渠道关单；结果保留，点击主按钮并经服务端确认才出现表单 |
| 其他结果 | 已到账、用户主动取消或可靠失败的结果、查看记录和返回充值 | 点击返回充值后才重新出现 |

主流程为“空闲 → 创建中 → 当前订单 → 处理／结果 → 返回充值 → 空闲”。本站到期或主动结束后同样保留结果并明确显示返回主按钮，不自动跳转。各阶段互斥，不是多个模块同时堆叠。
订单阶段主区仅展示一块订单详情：应付金额与币种、充值额度、付款方式、订单号、创建时间、可靠截止时间、状态和进度。
待付款且能力允许时展示主按钮“重新打开支付页面”、次按钮“结束本次充值”、按渠道能力显示的“取消订单”和轻按钮“刷新结果”；
不能用一条“查看订单”提示或跳往列表的按钮替代当前卡的直接操作。

提交购买即隐藏表单并进入创建中；创建成功后显示订单详情，再在外部新标签页打开支付，钱包自身不跳离。
切标签页、关闭支付标签页、关闭记录弹层和刷新钱包都不清除未完成订单；
重新进入或跨设备登录时，依服务端恢复本次当前充值阶段，不能凭浏览器偏好清除当前流程。
恢复查询期间仅显示“正在恢复订单”，不提前放出购买表单，查询失败不等于没有订单。首次恢复读取最多等待20秒；超时后显示可重试的失败状态，继续隐藏购买表单并保留已知订单。

有多个历史未完成单时，优先聚焦服务端确定的当前可处理对象；卡片内以“另有 N 笔未完成订单 · 查看其他订单”进入二级记录。
数量只包含当前用户和租户的真实未完成订单，排除本地超时／结束废单，已确认收款待入账仍计入核实；不能混入全平台数据，也不能把待核实单称作可付款单。
存在本次未完成当前流程时，不能通过选择另一记录清除它或解锁购买。无当前流程时才可选择可靠可处理的旧订单继续。
缺乏证据的历史待核实单保留在记录与后台核实队列，不无差别自动绑定为当前阶段而永久锁账户；
本次未结束当前订单转待核实仍保留流程；未确认收款可按后端能力结束或到期，已确认收款继续到账核实。前端不能擅自移入历史来解锁购买。

本站期限到达且无已确认收款时，主区保留“本次充值已超时”结果；主动结束保留“本次充值已结束”。两者均显示主按钮“返回充值”和次入口“查看订单记录”，说明原支付页可能仍可付款、已付款将继续核实，请关闭旧支付页并避免重复支付。主按钮直接可见，不藏在详情或记录里。点击后由服务端校验并结束对应当前流程，再恢复表单及新报价，不自动创建订单。旧响应不能覆盖随后建立的新当前流程。
当前单变为已到账、用户主动取消已可靠关闭，或支付失败且无可付款会话后，原位置保留结果与“查看订单记录”“返回充值”；这些路径仍由用户明确返回后恢复表单和新报价。
未结束且未到期的未知／处理中订单，以及已确认收款的到账核实，不提供直接购买捷径；本地结束／超时提供精确确认后的返回充值。关闭支付页或记录弹层不触发返回。
钱包没有本次当前流程或需恢复的可靠可处理对象时才进入空闲；纯历史核实记录不自动触发阶段锁定。

订单记录按以下层次呈现：

1. 标题“订单记录”，简短说明和关闭按钮。
2. 状态筛选：全部、待付款、处理中、待核实、已完成、已关闭。
3. 订单号搜索与刷新。搜索可精确定位旧订单，不因为超过普通列表时间窗口就拒绝本人查询。
4. 订单列表。原型每页 4 条，有可操作分页；实际产品分页以 PRD 和接口约定实施。
5. 记录保留提示、结果总数和分页。

每条订单展示支付方式、完整中文状态、订单号、创建时间、应付金额与币种、充值额度、简短进度说明及允许的操作。
订单号可复制；长订单号在窄屏允许换行。主要操作始终可见，不依赖悬停。
金额不再使用无币种的裸数字。应付、实际收款和到账额度分别展示，不能互相冒充。

## 状态与操作

| 状态 | 筛选归属 | 主要操作与说明 |
| --- | --- | --- |
| 正在创建／核实创建结果 | 处理中 | 展示进度、刷新或帮助；正在提交时禁重复操作，结果未知可按能力结束；尚未确认可付款前不显示续付 |
| 待付款 | 待付款 | 钱包直接提供重新打开支付页面与结束本次充值；记录内对应继续支付；按渠道能力取消；显示本站截止或剩余时间 |
| 支付确认中 | 处理中 | 刷新结果，提示请勿重复付款 |
| 取消处理中 | 处理中 | 刷新结果，说明已提交取消请求、仍待渠道确认；停止继续支付 |
| 本次充值已超时／已结束 | 已关闭 | 当前显示返回充值与查看记录；历史只读／客服，无续付、取消、恢复、补单或人工核实；不宣称渠道已关闭 |
| 支付结果待核实 | 待核实 | 期限内且未结束可按能力核实／结束、联系客服；不展示付款按钮，不直接宣称渠道已关闭 |
| 已收到付款，到账核实中 | 待核实 | 说明已收到付款、额度尚未核实到账，提供订单信息与客服入口，提示请勿重复付款 |
| 已到账 | 已完成 | 主区保留成功结果和查看记录／返回充值；返回前不显示表单 |
| 已取消（主动取消） | 已关闭 | 主区保留可靠关闭原因和查看记录／返回充值；记录内重新充值也须检查当前阶段 |
| 已过期（渠道到期关闭） | 已关闭 | 仅可靠确认未付款且原会话关闭时使用，保留渠道关闭事实；主按钮返回充值及查看原记录，确认后才恢复表单 |
| 支付失败 | 已关闭 | 可靠确认无可付款会话后保留失败原因和返回充值；不能显示成待付款或直接恢复表单 |
| 状态暂不可用 | 全部 | 刷新、联系客服；不回退为待付款，也不伪造已建立处理责任的待核实状态 |

按钮能力由后端返回，前端不能仅凭状态或创建时间推测。
无在线取消能力的待付款订单在钱包卡保留“重新打开支付页面”（记录内为“继续支付”），提供“结束本次充值”及期限内的“核实支付结果”，并显示
“此付款方式暂不支持在线取消。结束本次充值不会关闭原支付页，请避免重复付款。”不展示一个点击后虚假成功的取消按钮。

支付确认中、取消中与待核实直接在钱包当前卡反馈并停止本单重开付款；未确认收款时，主动结束或本站到期转结果。
查询、取消或收款结果更新时同步钱包余额、当前卡和二级列表，不以旧按钮保留原状态。
尚未结束的当前流程不显示购买表单或报价确认；本地结束／超时结果仅经服务端精确确认后返回充值，已确认收款继续核实。

## 钱包购买与外部标签页流程

1. 用户在钱包充值表单和支付明细核对充值额度、冻结报价及币种、付款方式，单击“核对并支付”即提交下单；不再展开“确认充值订单”或要求再点“创建订单并支付”。Creem 先选产品查看报价，再单击支付按钮；选产品不直接下单。报价已失效则刷新明细，不能沿用旧报价或刷新后自动下单。
2. 提交后主区切换为“正在创建订单…”，在线充值表单和购买入口完全隐藏；结果不确定时保留核实反馈。
3. 原订单与支付会话已可靠保存后，主区仅显示订单详情，再打开外部新标签页支付；不叠加余额卡或购买表单。
4. 钱包原页始终留有当前订单；用户关闭支付页或主动切回钱包后，期限内可重开原支付页、结束本次充值或按能力取消。
5. 钱包重新获得焦点或从隐藏变为可见时核实后端结果，合并重复触发。关闭支付标签页不是支付成功或取消凭据。
6. 新标签页被拦、未出现或无法确认打开结果时，当前卡显示：“订单已创建。如支付页面未打开，请点击‘重新打开支付页面’。”手动入口一直可见，不要求进入历史列表。
7. 未确认收款时，本地到期／主动结束即保留超时／结束结果及主按钮“返回充值”，不等待渠道关单；用户点击并经服务端精确确认后才恢复表单。已到账、可靠取消和可靠失败同样保留结果；已确认收款未到账继续核实。

产品不能可靠读取跨域付款标签页的内容或承诺检测它何时关闭；不能把关闭检测作为当前卡出现的前提。
新标签页是否可自动关闭也不属于承诺，用户可手动关闭并返回钱包。
即使没有接收到回跳事件，钱包仍能通过服务端状态查询恢复这笔订单。

## 继续支付

钱包当前卡已完整展示冻结订单信息，点击“重新打开支付页面”直接请求恢复原会话并打开外部新标签页，
无需再进入订单记录或打开第二层确认。记录列表的“继续支付”则在原订单内展开冻结的订单号、
应付币种金额、充值额度和支付截止，让用户确认后选择“前往支付”；“返回订单”关闭该确认区域。
确认文案：“将打开原订单的支付页面，不会重复创建充值订单。”

正式产品由服务器再次鉴权并检查截止与关闭请求，返回原会话；付款在外部新标签页打开，钱包当前卡保留。
用户关闭支付网页或返回钱包后可在原位置操作。重复操作不创建第二笔订单或第二个可付款会话；
浏览器标签页数量不等于支付会话数量，恢复不能创建第二个可付款会话。
页面回跳、重新获得焦点或重新可见只触发查询，不作为已付款或已取消依据。

## 取消订单

用户在钱包当前卡即可点击“取消订单”，在本卡片展开确认，保留本单订单号及应付金额，无需打开记录。
在二级记录发起相同动作时遵循同一资金规则。

确认标题：“取消这笔充值订单？”

确认文案：“系统将核实支付结果并尝试关闭付款入口。若已完成付款，将以实际付款结果处理。取消充值不等于退款。”

按钮为“返回订单”和“确认取消”。点击确认先进入“取消处理中”，停止本单续付；
取得渠道关闭结果后才显示“已取消”。渠道确认已付款时，按真实付款结果继续入账或进入到账核实。
查询或关单失败不得显示“取消成功”。

钱包当前卡在取消中和关闭后持续反馈结果，保留“刷新结果”或终态后续操作，不因进入终态消失。
二级记录中，状态转换导致订单离开当前筛选时，给出明确提示，例如
“取消请求已提交，订单已移至‘处理中’。渠道确认前不会显示已取消。”
记录中可切到对应分组并保留该订单的详情；钱包主卡不需要跳入该分组。正式实施时需保留可预测焦点，不能让操作后焦点丢失。

## 本地结束、自动到期与结果页返回按钮

本站期限为创建后 30 分钟，已知渠道截止更早则取更早值；创建时间未知不伪造期限，显示状态暂不可用。服务端到期即停止本单续付并派生 timed_out，主动结束派生 ended，二者独立于渠道关闭；不依赖页面或后台扫描先写回。客户端倒计时仅触发刷新，不自行确认资金状态。

没有已确认收款时，主区保留“本次充值已超时／已结束”、订单详情、显眼主按钮“返回充值”和次入口“查看订单记录”。说明原支付页可能仍可付款，已付款将继续核实，请关闭旧支付页并避免重复支付；不宣称“渠道已取消／无法继续付款”。用户点击后由服务端校验精确流程及最新付款事实，才恢复表单和新报价；刷新、重登、换设备保留尚未确认的结果，不自动下单。

渠道关单仍按真实能力和可靠证据独立处理；查询失败、关单未知不阻止无已确认收款订单按本站期限结束。已确认收款／credit_review 优先于本地期限，显示实际到账或到账核实；不能被本地结束或迟到关闭响应覆盖。

废单保留只读历史／客服，不提供续付、恢复、再取消、人工核实或补单入口，旧链接及直接 API 同样受限。可信晚付款继续核实并按原订单幂等入账；A 结束并返回后新建 B，A 的晚付款不得替换或清除 B。

## 待核实与旧订单

创建时间已知的老 pending 按本站相同期限显示已超时、归已关闭并保留历史，不再计入其他未完成；这不证明渠道未收款或会话关闭。创建时间未知则显示状态暂不可用。缺少币种或会话时明确未取得，保留订单号、原有展示及客服，不用当前配置补造快照。
历史待核实单若是最近操作的当前单，钱包直接显示核实状态与帮助；其他旧单通过记录查询，不能冒充可付款订单。
只有未结束且未到期的可操作订单或实际收款待核实单可按能力触发限速核实；废单不提供人工核实／补单，可信回调及自动收款处理继续。
联系客服在原订单内展示需要提供的订单信息和付款凭据要求，不自动向外部发送消息。

本地结束／超时即保留说明与返回主按钮，无须等待渠道关闭；与已到账、可靠取消和可靠失败相同，均由用户点击并经服务端精确确认后恢复空闲表单。再次确认新报价才创建新订单号，原记录保留。
二级记录的“重新充值”不能绕过本次当前流程锁定；不复用旧订单号，也不因未绑定当前流程的历史核实记录永久封锁账户。

## 管理员视角

管理员标题为“全平台充值订单”，显示必要的用户 ID，计数和结果范围均为全平台。
普通用户只看本人订单，不提供产品内的角色切换开关，也不展示补单按钮。

管理员对仍可操作或已确认收款待核实单的操作统一叫“核实支付”；废单与创建时间未知且无收款证据的订单不显示补单、人工核实或恢复入口。展开详情可查看脱敏凭据、最近核实时间和处理说明。
核实操作不会凭空发放额度；只有后端已验证付款并通过既有账务规则，才可核实入账。
无付款凭据的人工额度调整属于独立权限与审计流程，不放在普通充值记录的快捷按钮里。

## 视觉与响应式

- 主色使用中性明暗反转按钮；橙色用于待付款／待核实，蓝色用于支付确认中，绿色用于已到账，红色用于确认失败。
- 状态使用颜色、圆点和完整中文同时表达，不能只靠颜色。
- 主标题、金额和主要动作保持清楚的层级；订单内部以分隔线组织，避免重复堆叠厚重卡片。
- 桌面为约 940px 宽弹层，手机为全屏内容；筛选换行，金额、进度和操作按空间重排。
- 320px 下长状态与支付方式可换行，订单号可断行；触控目标保持可操作尺寸，搜索输入至少 16px。
- 支持浅色、深色及跟随系统，遵循减少动态效果偏好。
