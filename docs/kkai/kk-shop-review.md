# KK 商城产品与设计审核入口

版本：V2 / 开发规格D2，2026-10-28。状态：产品文档、设计原型及首版应用代码均已落地；商城尚未上线。当前实现、定向验证及剩余验收见[实施状态](./kk-shop-implementation-status.md)。

交付顺序为产品文档 → 高保真交互设计稿 → 开发规格 → 本地应用实现。下面的静态原型继续作为设计审核入口，原型演示不能替代真实业务验收。

## 已确认的产品方向

- 自营虚拟商品商城，销售账号、卡密等数字商品。
- 自动发货与人工交付同时具备。
- 在现有 KKAI 网站增加商城入口，共用登录与管理后台。
- 复用现有支付渠道；商城独立管理付款、订单、库存和交付。
- 无实物、无物流、无收货地址。

首版建议单商品、单规格、单件直接购买，按订单付款。首版不建设购物车、多商家、商城储值、分销或复杂促销；这些属于本次提交审核的范围建议，不是用户此前逐项确认的事实。

## 建议审核顺序

1. 浏览商城首页：确认整体风格、分类、商品信息密度及站内入口。
2. 打开商品详情：确认规格、交付内容、适用范围和售后说明是否清楚。
3. 查看结账：确认商品、金额、交付方式、付款入口及购买须知。
4. 查看已交付订单：确认凭据领取、使用说明与售后入口。
5. 查看人工交付订单：确认补充资料、处理时限与进度展示。
6. 查看付款核实、迟到付款缺货及退款状态：确认用户能够理解现状和下一步。
7. 查看后台：确认商品编辑、库存导入、待交付和售后处理符合日常操作习惯。
8. 切换手机尺寸和深色主题：确认信息与主要操作保持完整。

建议反馈时提供“页面名称 + 想调整的内容”，例如“商品详情：购买按钮更突出”“后台库存：批次信息需要更明显”。

## 演示与真实业务的边界

设计稿中的商品、金额、库存、账号、订单、渠道选项、服务时限及售后期限均为演示素材，不表示实际在售商品或已开通渠道。所有账号域名使用保留的测试域名；原型不连接支付和业务 API，不会扣款或发货。

原型提供单独的审核工具条，用来切换页面、主题和模拟状态。该工具条不属于最终买家界面，模拟付款也不能出现在正式产品的付款确认逻辑中。

静态原型可展示加密/权限要求对应的交互，但不能证明服务端已实施加密、鉴权、并发控制或支付验签。详细行为及验证要求保留在业务规则中。

## 开发前需要冻结的运营配置

| 输入 | 当前状态 | 对设计与开发的影响 |
| --- | --- | --- |
| 首批真实商品、规格与可交付资料 | 待提供 | 确定商品文案、凭据字段和导入模板 |
| 首发支付渠道及收款币种 | 待核实 | 确定支付选项、价格展示和退款核实方式 |
| 商品售价与税费展示方式 | 待确认 | 结账以服务端真实应付金额为准 |
| 人工交付服务时间、时区、承诺时限 | 待确认 | 页面展示明确预计完成时间，不能用虚构的秒发承诺 |
| 质保、补发、退款与凭据保留期限 | 待确认 | 商品详情、订单快照、售后入口和历史内容保留 |
| 库存预留时长、未付款单数与限购 | 待确认 | 防止库存被长期占用，并匹配渠道能力 |

这些配置缺失不影响本次审核布局和流程。正式上架必须具备必要配置；缺失时不使用演示值兜底。
