# KKAI 调用量与调用趋势看板开发文档

- **需求**：工单 #31，支持按日、周、月查看调用量及调用趋势。
- **版本**：MVP 开发基线，2026-11-18。
- **面向角色**：产品、技术负责人、前端、后端/API、测试、代码评审和发布负责人。
- **状态**：开发前冻结方案。
- **生产说明**：本文只描述本地开发和验证，不授权构建、部署、迁移或生产操作。

截图中的工单状态、反馈框和时间线是工单系统元数据，不属于本功能实现要求。本文只落实截图中的原始需求。

## 1. 冻结决策

以下决策采用默认推荐方案，开发过程中不能由单个角色自行删减：

1. 主要入口是用户首页 `/dashboard/overview`；模型分析页 `/dashboard/models` 同步补齐按月能力。
2. 首页新增完整的调用趋势模块；现有首页摘要卡片的“今日用量”语义不改变。
3. 快捷范围为“近 24 小时、近 7 天、近 30 天、自定义”。现有 14 天选项可以保留，但不是本需求验收重点。
4. 统计粒度为“小时、日、周、月”。
5. 首页默认使用“近 7 天 + 按日”；模型分析页首次访问继续使用现有默认值，用户已有偏好不能被覆盖。
6. “按周”使用周一至周日的自然周；“按月”使用自然月，不等同于滚动 30 天。
7. “近 30 天”是滚动查询范围；用户可以在该范围内手动选择日、周或月粒度。
8. 调用次数是主指标，Token 使用量和 Quota 消耗作为辅助指标。
9. 趋势图、占比图和排行图复用现有 VChart 能力，不新增图表依赖。
10. MVP 不新增数据库表、不修改计费逻辑、不新增独立统计服务。
11. MVP 复用现有 `/api/data/self` 和 `/api/data` 接口，由前端对小时数据进行日、周、月聚合。
12. 普通用户只能看到自己的数据；管理员可以查看全局数据并按用户名筛选。
13. 时间口径延续当前 KKAI 的 UTC+8 逻辑，时间处理集中在 `web/default/src/lib/time.ts`，不能在新组件中散落固定偏移量。

## 2. 当前代码基线

### 2.1 已有能力

| 位置 | 当前能力 | 本次处理 |

| `web/default/src/features/dashboard/components/models/models-filter-dialog.tsx` | 时间范围、粒度和管理员用户名筛选 | 扩展月份粒度和近 30 天范围 |
| `web/default/src/features/dashboard/lib/charts.ts` | 按时间和模型聚合，生成趋势、饼图、排行图 | 统一并扩展周、月桶逻辑 |
| `web/default/src/features/dashboard/components/models/model-charts.tsx` | 趋势、占比、排行切换 | 复用现有图表容器 |

| `web/default/src/features/dashboard/components/overview/summary-cards.tsx` | 今日用量、历史用量、累计请求摘要 | 保持原语义，不改成趋势模块 |
| `model/usedata.go` | `quota_data` 按小时写入和查询 | 不改表结构，验证数据契约 |
| `controller/usedata.go` | `/api/data`、`/api/data/self` | 默认不改接口行为 |

### 2.2 当前缺口

- `TimeGranularity` 只有 `hour | day | week`，没有 `month`。
- 快捷范围使用 `29 Days`，产品文案不符合“近 30 天”的用户认知。
- 当前周标签根据记录时间直接加 6 天，不是严格的自然周桶。
- 首页概览只请求最近 24 小时数据，没有独立的趋势模块和范围筛选。
- 当前图表聚合同时使用显示文本作为桶 key；新增月粒度时必须避免跨年、跨语言或同名标签碰撞。

## 3. 用户、权限和数据边界

### 3.1 普通用户

- 可访问 `/dashboard/overview` 和 `/dashboard/models`。
- 只能请求 `/api/data/self`。
- 只能查看自己的调用次数、Token、Quota、模型分布和趋势。
- 不显示用户名筛选器。
- 查询范围继续受后端日志范围限制。

### 3.2 管理员

- 可访问现有管理员数据看板。
- 默认请求 `/api/data`，保持当前项目管理员权限判断。
- 可以按用户名筛选。
- 用户筛选必须同时影响统计卡片、趋势图、饼图和排行图。
- 不得通过前端隐藏控件实现安全隔离，后端权限仍是最终边界。

## 4. 产品功能契约

### 4.1 首页调用趋势模块

在 `/dashboard/overview` 中新增独立面板，建议落点：

```text
web/default/src/features/dashboard/components/overview/
```

模块必须包含：

1. 范围选择：近 24 小时、近 7 天、近 30 天、自定义。
2. 粒度选择：小时、日、周、月。
3. 调用次数、Token 使用量、Quota 消耗摘要。
4. 调用次数趋势折线图或面积图。
5. 模型调用次数占比饼图。
6. 加载中、无数据、失败和刷新状态。
7. 桌面端和移动端可用，不能出现横向溢出或控件重叠。

现有 `SummaryCards` 的“今日用量”继续表示当前自然日，不得因首页新增筛选器而变成“选定范围用量”。

### 4.2 模型分析页

保留现有 `/dashboard/models` 的结构和用户偏好能力，补充：

- `month` 粒度选项；
- “近 30 天”范围文案；
- 自然周和自然月聚合；
- 与首页相同的时间桶规则；
- 现有趋势、占比、排行、消费分布图不回归。

### 4.3 时间选择交互

快捷范围选择后，自动设置建议粒度，但允许用户再次修改：

| 选择范围 | 默认粒度 |
| --- | --- |
| 近 24 小时 | 小时 |
| 近 7 天 | 日 |
| 近 30 天 | 日 |
| 自定义 | 沿用当前粒度 |

时间范围和粒度是两个独立概念。自定义范围的结束时间不能早于开始时间。前端传递 Unix seconds，继续遵守现有接口的包含式结束时间约定。

### 4.4 图表规则

趋势图：

- 横轴显示按项目时区格式化后的时间标签；
- 纵轴默认显示调用次数；
- 以模型为系列时，最多展示 Top 20，其余合并为“其他”；
- 悬停显示时间、模型、调用次数和总量；
- 没有调用的时间桶显示为 0；
- 跨月、跨年排序必须稳定。

占比图：

- 按模型调用次数计算占比；
- Top 10 模型之外合并为“其他”；
- 总数与趋势图、统计卡片一致；
- 模型名只作为文本渲染，不能被当作 HTML 注入。

## 5. 数据和接口契约

### 5.1 现有接口

普通用户：

```text
GET /api/data/self
```

管理员：

```text
GET /api/data
```

查询参数沿用现有实现：

```text
start_timestamp: number
end_timestamp: number
default_time: hour | day | week | month
username?: string
```

说明：当前后端查询主要依据 `start_timestamp`、`end_timestamp` 和权限，统计桶由前端聚合。`default_time` 可以继续发送以保持契约兼容，但不能把它当作后端已经完成日、周、月聚合的证明。

### 5.2 数据字段

前端使用现有 `QuotaDataItem`：

```text
created_at
model_name
count
quota
token_used
cache_read_tokens
cache_creation_tokens
username
user_id
```

缺失的可选数值字段按 0 处理。`created_at` 无效时不能静默归入当前时间桶，应过滤并在开发日志或测试中暴露问题。

### 5.3 后端职责

后端本期职责：

1. 保持现有接口和权限行为。
2. 确认普通用户查询仍经过 `limitLogTimeRange`。
3. 确认管理员数据不会错误走普通用户过滤。
4. 确认 `QuotaData` 字段和小时写入粒度没有变化。
5. 评估 30 天及管理员全量数据返回规模。

本期禁止：

- 新增统计表；
- 修改 `quota_data` 写入粒度；
- 在查询接口中复制一套前端聚合逻辑；
- 修改计费、扣费、额度结算或日志写入逻辑。

只有在定向验证确认返回量不足或性能不可接受时，才另立后端聚合接口设计。

## 9. 测试方案

### 9.1 时间桶测试

必须覆盖：

1. 同一小时多条记录合并。
2. 同一天多小时记录合并。
3. 周一和周日归入同一自然周。
4. 跨周记录归入不同周。
5. 同一月份多条记录合并。
6. 12 月和次年 1 月不能合并。
7. 跨年排序正确。
8. 没有数据的时间桶补 0。
9. 输入数组顺序打乱后结果仍按时间升序。
10. 原始输入数组不被修改。
11. 无效时间戳不会进入有效统计。

### 9.2 图表不变量

- 趋势图调用总数等于所有模型调用数之和。
- “其他”加 Top N 等于全部模型总数。
- 饼图总数等于统计卡片总数。
- Quota、Token 和调用次数分别聚合，不能相互替代。
- 空数据不会抛异常或渲染错误图表。

### 9.3 组件行为测试

- 默认筛选器显示近 7 天、按日。
- 切换范围会重新请求数据。
- 切换粒度不会丢失当前时间范围。
- 自定义时间范围可以打开、修改、应用和重置。
- 请求切换时旧请求不会覆盖新请求结果。
- 加载、空数据、错误和刷新状态可见。
- 普通用户调用 `/api/data/self`。
- 管理员调用 `/api/data` 并可传 `username`。
- 语言切换后新增文案同步更新。

### 9.4 推荐验证命令

在 `web/default` 目录执行：

```sh
bunx --no-install vitest run \
  src/features/dashboard/lib/__tests__/charts.test.ts \
  src/features/dashboard/components/overview/__tests__/summary-cards.test.tsx
```

根据新增文件补充对应测试路径：

```sh
bunx --no-install vitest run src/features/dashboard
bunx --no-install oxlint -c .oxlintrc.json src/features/dashboard src/lib/time.ts
bun check -b
bun run i18n:check
bun run format:check
bun run build
```

验证规则：

- 先执行受影响模块的定向测试；
- TS/TSX 修改后必须执行 `bun check -b`；
- 只对改动范围执行 lint，不把无关历史错误归入本需求；
- `build` 作为前端发布前检查执行；
- 未经明确授权，不执行全仓 Go 测试或生产部署。

## 10. 代码质量要求

1. 不新增重复的 API 请求封装，优先复用 `getUserQuotaDates`。
2. 不新增图表依赖，优先复用 VChart 和已有图表组件。
3. 聚合逻辑必须是纯函数，便于单元测试。
4. 机器桶 key 和显示 label 必须分离。
5. 不使用 `any` 扩大类型缺口；已有 VChart 类型兼容代码除外。
6. 不在组件内硬编码面向用户的文案。
7. 不用浏览器时区替代项目已约定的 UTC+8 统计时区。
8. 不在 `useEffect` 中制造未取消的请求或竞态更新。
9. 不改变现有摘要卡片、日志、计费和权限语义。
10. 不为了实现月统计修改数据库写入粒度。
11. 图表数据量较大时使用现有 Top N 合并规则，避免渲染过多 series。
12. 所有新增交互具备键盘操作和可读的 aria 标签。

## 11. 手工验收场景

### 普通用户

1. 登录普通用户账号，打开 `/dashboard/overview`。
2. 默认看到近 7 天按日趋势。
3. 切换到近 30 天，图表和统计卡片更新。
4. 切换到按周，确认周一至周日聚合。
5. 切换到按月，确认跨月数据分开。
6. 打开 `/dashboard/models`，确认原有趋势、占比、排行和消费图均可用。
7. 打开使用日志，确认本需求没有影响日志查询。

1. 登录管理员账号，打开模型看板。
2. 确认可以使用用户名筛选。
3. 修改时间范围和粒度，确认所有图表同步更新。
4. 清空用户名筛选，确认恢复全局数据。
5. 使用不存在的用户名，确认显示空状态而不是旧数据。

### 异常场景

1. 接口加载中显示骨架屏。
2. 接口失败显示错误状态和重试入口。
3. 时间范围内无数据时显示空状态。
4. 只有一个小时或一个月数据时，图表仍然有稳定尺寸。
5. 关闭网络后切换筛选器，不出现旧请求覆盖新请求的问题。
6. 切换浅色和深色主题，图表颜色和文字保持可读。
7. 使用移动端宽度，筛选器、统计卡片和图表不发生横向溢出。

## 13. 性能升级触发条件

MVP 先使用现有小时数据和前端聚合。只有出现以下任一情况，才单独设计后端聚合：

- 30 天普通用户请求返回明显过大；
- 管理员全局数据导致浏览器主线程阻塞；
- 图表首次渲染超过可接受阈值；
- 数据传输量明显影响移动端使用；
- 需要支持更长时间范围的高频刷新。

后端升级必须单独定义接口契约、缓存策略、权限测试和性能基线，不能在本需求中临时混入。

## 15. 风险与后续事项

| 风险 | 处理方式 |
| --- | --- |
| 管理员全局数据量过大 | 先监测返回量和渲染耗时，必要时另立后端聚合任务 |
| 浏览器时区与 UTC+8 不一致 | 统一由时间工具处理，不在组件中直接使用浏览器本地桶 |
| 旧用户本地偏好包含 29 天 | 解析时兼容旧值，显示文案统一为近 30 天 |
| 模型数量过多导致图表拥挤 | 继续使用 Top N 和“其他”合并 |
| 首页和模型页出现两套聚合规则 | 两者必须复用同一纯函数和同一测试用例 |
| 需求后续扩展为账单报表 | 另立产品和技术方案，不把计费逻辑塞入本需求 |
