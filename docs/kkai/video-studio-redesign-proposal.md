**视频工作室优化重构方案 · 产品 / UI / 前端联合评审稿**

日期：2026-10-28。状态：建议方案，供讨论；尚未制作新视觉稿、修改业务代码或执行上线。

**一、推荐结论**

采用“精致创作台”方向：延续图片工作室的冷灰背景、白色卡片、靛蓝强调色与克制留白；桌面以左侧创作设置、右侧当前成果为核心，提交后在当前页面等待和查看结果，灵感样片作为随时可用的辅助内容。

“高级美观”具体落在四件事：明确的视觉重心、稳定的比例与间距、真实视频内容的良好呈现、完整且平静的状态反馈。评价应覆盖空态、等待、失败、竖屏内容和移动端，不能只用一张完成状态的大屏截图判断。

目标用户假设：已有生成意图、需要反复调整提示词和参数的控制台用户，同时照顾通过样片寻找灵感的新用户。当前没有用户访谈、行为统计或本轮运行页面的证据；下文体验判断来自本地源码，实际效果需在设计与实现阶段验证。源码配置不代表生产配置。

**二、三个角色的讨论与取舍**

| 角色 | 核心意见 | 合并后的决定 |
| --- | --- | --- |
| 产品经理 | 当前样片是主角，创作与结果分散；等待时间长，需要连续创作闭环 | 创作页就地看结果，保留作品库和任务页的职责 |
| UI / 视觉 | 图片工作室已有合适的色系；空播放器和信息堆叠都会削弱质感 | 延续现有视觉基线，右侧按无作品、处理中、已完成适配内容 |
| 前端架构 / 交互质量 | 原有报价、上传、轮询和用户隔离已有复杂保障，重写风险大 | 以页面组合和表现层调整为主，复用原有业务与查询能力 |

三个方向经过比较：

- **沉浸影院型**：大幅深色播放器具有视频感，但无作品时空洞，表单容易退居次要位置，与图片工作室的整体气质存在距离。
- **灵感画廊型**：适合浏览，但接近当前主结构，难以解决“自己的创作不突出”和提交后的来回切页。
- **精致创作台型，推荐**：设置与结果并列，兼顾创作、等待和回看；通过色彩、排版、媒体呈现获得质感，最适合当前功能和代码。

采用第三种。灵感仍保留动态预览、筛选和套用；作品库和任务页暂不合并，避免损失已有浏览和排查能力。

**四、产品结构与主流程**

保留现有三个用户路由及深链接，降低迁移成本：

| 页面 | 主要职责 | 信息重点 |
| --- | --- | --- |
| 创作 | 编辑、提交、当前任务反馈、近期结果切换、找灵感 | 当前输入与当前成果 |
| 作品库 | 回看工作室生成记录、播放、下载、删除终态记录 | 画面与内容 |
| 任务 | 集中查看生成进度、失败原因和任务号 | 状态与排查信息 |

工作室作品库继续对应工作室 generation。全站 `/usage-logs/task` 的视频作品还包含其他公共 API 视频任务；本次不合并这两份业务数据。

桌面区域关系：

| 左侧创作卡 | 右侧成果区域 |
| --- | --- |
| 模型及可用模式 | 当前任务 / 作品标题与状态 |
| 提示词 | 视频播放器或对应任务状态 |
| 当前模式所需素材 | 播放 / 下载 / 详情等适用操作 |
| 常用输出参数 | 最近任务与作品缩略列表 |
| 高级设置 | 可展开的灵感样片 |
| 预计费用与生成按钮 | 更多历史通往作品库 |

模型仍决定可用模式与字段。不要在视觉稿中固定画出每个模型都支持的三种模式或全部参数。默认保持模型优先的依赖关系，再展示模式；只有一项的模式无需伪装为多选控件。

交互决策：

1. 用户主动提交后，当前任务成为右侧焦点；输入仍保留，方便继续修改。
2. 用户正在查看其他作品时，后台任务完成仅更新近期列表与状态，不自动切走播放器、不自动发声。
3. 切换近期作品只切结果，不静默覆盖正在编辑的提示词、参数或素材。
4. 套用样片是明确的编辑动作；若会覆盖已经修改的草稿，应先给出可取消的覆盖确认。单纯切换结果不触发确认。
5. 生成提交受理后不因为上游仍处理中就锁住整个创作页；允许继续准备下一次请求，沿用既有费用和提交保护，不新增并发承诺。
6. 近期列表是有限的工作集，不显示未经完整查询的“全部任务数”或全站统计。

**五、色系、风格与组件规格**

以下颜色直接来自图片创作页，是当前已存在的基线：

| 用途 | 浅色 | 深色 |
| --- | --- | --- |
| 页面背景 | `#f6f7fa` | `#101217` |
| 卡片表面 | `#ffffff` | `#1a1e26` |
| 次级控件背景 | `#f2f4f8` | `#242a34` |
| 正文 | `#222833` | `#edf0f7` |
| 辅助文字 | `#657182` | `#a7b1c2` |
| 分隔与边框 | `#e2e7f0` | `#303744` |
| 强调色 | `#4c63da` | `#b0beff` |
| 轻选中背景 | `#edf0ff` | `#2a3351` |

建议延续的视觉规范：

- **空间**：桌面内容外边距约 22–24px，栏间距 22–24px；创作卡宽约 380–420px，结果区自适应。最终断点看可用内容宽度，计入控制台侧栏。
- **表面**：核心卡片约 16px 圆角、细边框、极轻阴影；内部主要依靠留白分组，避免每个字段再套一张卡。
- **排版**：页标题约 20–22px，分区标题 14px，正文 13–14px，标签约 12px。重要说明不可为了精致压缩到难读的小字；沿用项目字体及图标体系。
- **控件**：输入和选择器约 42px，主按钮约 46px；提示词初始高度约 150–180px。手机输入文字 16px，触控目标至少 44px。
- **色彩分配**：靛蓝用于生成主操作、焦点和关键选中态；状态色只表达状态。媒体本身承担画面丰富度，页面背景保持安静。
- **主次**：每个任务区域只保留一个明确主操作；技术标识进入详情。作品卡优先封面、两行以内提示词摘要、必要状态。
- **动效**：150–200ms 的颜色与透明度反馈；避免循环装饰动画、整页切换位移和刷新时反复闪烁。尊重减少动态效果设置。
- **主题**：跟随现有系统浅/深主题；浅色保持冷灰与白卡，深色使用分层灰蓝表面。播放画面可以使用深底，但不会强制整页影院黑。

这些规格是设计建议，不意味着原样复制图片 CSS 的所有规则。图片页现有样式存在多处追加覆盖；实现应只继承经过确认的视觉变量和有效几何规则。

**六、状态设计决定最终质感**

| 情况 | 页面应呈现 | 不能误导用户的地方 |
| --- | --- | --- |
| 首次无作品 | 右侧紧凑创作引导、可套用的样片；编辑器直接可见 | 不放占满半屏的黑色空播放器；无样片也能开始创作 |
| 正在准备令牌/模型 | 布局稳定的准备状态，失败可重试 | 不提前显示“无模型”空态 |
| 上传中 / 媒体校验中 | 在对应素材位展示进度或检查状态，保留恢复操作 | 上传完不等于视频素材已 ready |
| 报价中 / 报价失败 / 已过期 | 独立费用区说明，支持刷新；主按钮明确可用性 | 不显示伪造的费用，不沿用失效报价提交 |
| 提交中 | 按钮反馈，禁止同次重复提交，保持输入 | 不用上传/提交进度冒充模型生成进度 |
| 已受理但记录尚未定位 | 显示正在获取任务、可核对任务号和刷新 | 30 秒定位超时不是上游生成失败；不诱导再次扣费提交 |
| 排队 / 生成中 | 当前任务状态，只有可信进度才显示百分比 | 不制造倒计时、预计完成时间或本地假百分比 |
| 归档中 | 明确生成已完成、正在准备可播放文件 | 尚未 ready 不提供播放和下载 |
| 已完成 | 完整画面的播放器、清晰下载入口、近期作品 | 横竖画面不拉伸、不裁掉有效内容 |
| 失败 / 提交结果未知 | 安全的原因说明和与错误类别对应的恢复路径 | 结果未知维持防重提交锁；刷新状态不等于重新生成 |
| 媒体链接失效 | 局部恢复签名与播放，不清空作品或输入 | 不无限重试，不重新生成视频 |
| 历史读取失败 | 保留已读结果、展示局部刷新失败 | 不把请求错误呈现成“没有作品” |

无作品与有作品可以有不同的右侧构成，但生成到完成阶段应保持舞台边界稳定，避免页面跳动。用户上一次作品仍在展示时，必须标明它是已有作品，并将新任务状态单独表达，不能让人误以为旧画面是本次结果。

视频显示规则：主播放器 `object-fit: contain`，横竖视频完整显示，允许自然留边；缩略封面可使用裁切。播放器提供原生播放、音量、进度与全屏能力；不新增剪辑时间线。开始主作品播放应停止样片预览，移动端不自动播放有声视频。

**七、作品库、任务页和移动端**

作品库沿用同套色系和卡片语言，按已加载记录做日期分组，提供真实的“全部 / 可播放”筛选。日期分组不能暗示已加载全部历史；加载更多要延续现有游标。封面优先、正文摘要收敛，详情承载任务号、模型、参数与错误信息；若显示额度，按现有货币配置格式化，不硬编码金额。

任务页保留偏紧凑的列表，突出状态、时间、进度和失败原因；任务 ID 可保留复制能力。删除仍为终态记录操作，需要明确确认，不能把删除包装成取消上游生成。

移动端按内容容器不足约 850px 时切为单栏：编辑在上、结果在下，提供“查看结果 / 返回编辑”定位。高级字段折叠，必要素材与主要参数直接可达，灵感入口始终可发现。避免依靠小图标打开整个编辑器，也避免多层内部滚动。

桌面与移动端使用同一个编辑器实例，通过 CSS 调整布局；跨断点时不能重建 Uppy 上传会话、丢失草稿或中断上传。定位滚动尊重减少动态效果，不抢夺正在输入或播放的用户焦点。

最小技术路线：

1. 使用现有 `useVideoGenerations({}, true, targetTaskId)` 发现新任务并跟踪状态；不要另造 WebSocket、轮询定时器或全局任务状态机。
2. 正确区分字符串 task ID 与数字 generation ID。复用现有定位超时和重试；只有获得作品数字 ID 才调用对应详情。`useVideoGeneration` 本身不是持续轮询方案，不能替代原有活跃任务跟踪。
3. 初期按当前列表发现机制实现，有明确限制：未曾被发现且已离开最新页的任务不能保证精确定位。出现这一情况应保留任务号、提供历史/任务入口和重试；不能轮询所有历史直到命中。
4. 页面只保存必要的选择信息；需要刷新后恢复时按用户保存稳定 ID，沿用版本化存储模式，不保存签名 URL、File/Blob 或密钥。
5. 费用仍经服务器报价、请求签名、有效期与 max_quota 校验。每次新的明确提交使用正确幂等生命周期；结果未知不能因切换布局或重新挂载而解除保护。
6. 常用参数按现有规范中的语义字段归类，剩余字段仍能动态渲染。必填但没有有效值的高级项应主动展开并显示错误；不能为了简洁隐藏关键条件，也不能丢掉显式 false/0。
7. 媒体继续通过 `useStudioMediaUrls` 获取并续签。仅签名/加载当前需要的素材，列表优先 poster；签名刷新不应无故重置正在播放的视频，需在实现时核验生命周期。
8. 暂不抽象统一图片/视频工作台框架，不重写整个 `queries.ts`。先实现视频局部组合；只有明确重复且稳定的视觉变量才考虑小范围共享。

**九、一期与后续需求分界**

推荐一期以完整的前端创作闭环交付，包括创作页、必要结果区、样片入口、核心媒体交互和移动端；作品库/任务页在同一视觉方向下分步统一。无需数据库迁移、替换模型适配器、变更计费或另建存储系统。

以下能力只有明确纳入产品目标后再扩展，不能在视觉稿中假装已有：

| 扩展项 | 最小依赖 | 建议 |
| --- | --- | --- |
| 按 task_id 精确定位工作室作品 | 仅当前用户、仅工作室记录、只读的精确查询能力，或兼容的提交响应补充 | 若需要高并发、多窗口下可靠直达，这是优先补足项；两种方案择一评估 |
| 全历史进行中/失败筛选和全文搜索 | 服务端过滤、游标语义与必要索引核查 | 在用户确有筛选需求时单独设计 |
| 历史完整再次生成 | 经过所有权/有效性检查的原始参考素材与角色，过期恢复策略、新报价 | 后续能力；首期不要用一个按钮承诺完整复刻 |
| 取消、批量生成、剪辑、素材管理中心 | 新业务能力及其权限/计费/上游支持 | 本次视觉与交互重构不承载 |

一期方案中不依赖上述接口扩展才能成立；其已知局限必须在目标定位与错误状态中诚实表达。

**十、交付顺序与验收**

1. **视觉定稿**：按本方案制作桌面浅色、桌面深色、移动端及关键状态稿。使用同一真实模型能力组合，覆盖无作品、生成中、归档中、完成和失败；历史数据/价格如为示意应在设计交付说明中标注。
2. **创作外观与响应式**：先统一配色、几何、输入层级、费用区与移动端；保持业务契约可回归。
3. **创作闭环**：接入当前任务发现、状态舞台、近期作品与灵感区域，取消提交后的强制跳转。与上一步一起达到核心可用交付，不能只完成换色就宣称重构结束。
4. **历史页面与收尾**：统一作品卡、作品库和任务页；验证深链接、播放与签名、上传恢复、用户切换、多语言与键盘操作。

设计验收标准：

- 在 1440、1024、768、390、320px 视口及侧栏展开/收起条件下检查，所有关键控件不溢出，长模型名和翻译不破版。
- 首屏能找到创作入口和提示词；一处明确生成主操作，费用与不可提交原因可读。
- 16:9、9:16、1:1 主视频完整显示；无作品不留巨大无意义黑框。
- 正文对比度至少 4.5:1，状态不只依赖颜色；键盘可达、焦点明确，触控目标至少 44px。
- 任务刷新不夺走当前作品选择，轮询不导致整区闪烁；后台页沿用现有暂停轮询策略。
- 样片预览与主播放器互相协调，切走时释放媒体；减少动态效果设置有效。

行为验收标准：

- 模型/模式变化后参数和素材角色仍合法；首尾帧顺序、参考视频、显式 false/0 继续正确。
- 样片套用、草稿恢复、断点切换、分片续传和素材失效恢复不丢数据。
- 报价刷新、价格变更、过期、防重提交和未知结果保护保持有效。
- 接受回执但暂未找到 generation、历史页滚动后活跃任务移出首页、后台恢复、删除后的迟到响应都有确定处理。
- HTTP/媒体失败不会伪装成空列表；签名到期可以局部恢复；账号切换不泄漏上一用户数据。
- 作品库筛选在服务端分页前发生，不能用局部过滤伪装全库结果；不将删除解释为取消任务。

实现阶段优先使用创作页、composer、queries、domain、generation-card、上传与草稿恢复相关的定向 Vitest；只为新增真实交互补测试，并对改动文件做 lint/格式检查及适用的类型验证。前端测试不能代替真实支付/生成链路验证，必要业务验收单独明确执行环境，不自动对生产发起付费生成。
