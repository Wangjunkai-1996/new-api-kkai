# 代理站请求兼容与计费修复方案

日期：2026-10-21。范围：当前代理站普通推理请求与主站的差异、代理 Key 权限、租户 Edge 和 Responses WebSocket。本文取代此前审计中“启用 compact”的建议。**不恢复 compact/上下文压缩功能，不以压缩绕过请求体问题。**

## 1. 目标和正确的职责边界

代理站与主站共用 NewAPI Relay、提供商适配器、公共请求校验、计量和实际价格计算。域名并不增加一次“代理站后端再请求主站域名”的模型转发。

代理层只增加必要的业务差异：按 Host 和 Key 识别租户、隔离客户与日志、限定主站公开供给、应用代理商分组倍率，以及记录客户扣款和代理结算。普通合法请求不应因为身处代理域名而被额外的文本类型白名单、会员产品配置、可选参数强制填写或漏配的 Nginx 默认值拒绝。

验收目标是完整请求成功及账务正确；首页可打开、模型列表可返回、进程健康，都不能代替真实推理验收。

## 2. 已核实的问题及修复

| 问题 | 证据 | 修复方向 | 验收要求 |
| --- | --- | --- | --- |
| 长请求 413 | 租户 TLS vhost 未配置大小限制，继承 Nginx 默认 1 MiB；主站为 500m。只读日志中有 9 次约 28.4 MiB 的 Responses 拒绝。无 Key 的 1 MiB 边界探测，代理 413、主站 401 | business renderer revision 2 严格核对唯一主站 HTTPS vhost 的显式 500m，再给租户相同的 500m；其他值拒绝生成计划。保留共同的 CDN、解压和应用资源边界 | 2 MiB/约 30 MiB 原文完整转发；超共同上限拒绝；不依赖上下文压缩 |
| 正常消息/工具/图片输入误拦 | 租户内容白名单拒绝 refusal、历史 compaction、媒体及 hosted tools | 删除重复的租户内容分类器，复用公共 DTO、适配器和公共参数验证。历史块原样回放不等于启用 compact | 普通文本、拒答历史、工具往返、历史 opaque 内容、图片输入均走共享链路；未知字段保留原有透传语义 |
| 已展示模型却因会员配置失败 | 公网代理定价返回 48 个 Token 模型，线上会员 model_limits 为空 | 代理钱包复用 ModelPriceHelper 的主站预估预扣；删除对会员发布目录和 verified aggregate bounds 的强制依赖 | 未建会员表/未发布会员目录，也能准备普通代理推理账务；不通过隐藏全部模型“修复” |
| 可选输出上限被强制要求 | Chat/Gemini 未填可选参数时租户预算拒绝 | 保留客户端和主站相同语义，不添加内部猜测的模型上限，不改写透传请求 | 省略、显式 0、显式有效值分别保留；公共超大数值校验仍生效 |
| 取消旧预算验证后可能遗漏数量边界 | 旧预算包含出站数量检查；直接删除会让渠道覆盖、透传及多候选数量绕过安全边界 | 将已知 token/count 的非负整数及上限检查放到共享请求校验和最终出站 JSON；主站与代理站使用同一规则，不要求参数存在，不遍历工具 schema 或用户正文 | 超大数值、负值、重复相关字段在派发前 400；正常缺省、0、合法扩展及大请求不改写 |
| 分组展示、Key 保存和请求权限不一致 | 可保存 auto/private；请求却不支持，或被主站身份专属权限二次拒绝 | 统一使用公开租户供给解析；创建、全量修改、分组 patch 和启用历史 Key 都校验 | 列表可选 → 保存 → Key 模型列表 → 真实选路一致；私有/不存在/不支持的 auto 在写入时拒绝 |
| 兼容路径缺失 | /responses、原生 /v1beta 在代理域名落入静态页，POST 405 | Edge 镜像主站公共 API 路径和 implicit-v1 重写；应用 gate 补齐 Gemini 文本端点 | 原始 Host、鉴权头、方法、请求体和 query 不丢失；重写仅作用于规定的兼容入口 |
| 原生 Gemini/Codex 渠道被遗漏 | 两者使用公共 DoApiRequest，但租户渠道列表遗漏 | 纳入已集成共享请求和账务路径的 HTTP 渠道；Gemini 作为文本供给识别 | 渠道级选路和公共出站检查均通过；未接入账务的 SDK 渠道不能假装支持 |
| Responses WS 直接被封禁且身份丢失 | Edge 无 Upgrade/Connection；内部每轮 Gin 请求未重建 Host 租户上下文 | 完整打通 Edge、GET gate、每轮 Host 解析、TokenAuth、供给和 pin 检查、预扣和未知结果处理后才启用 | 两轮以上对话、跨租户 Key 拒绝、租户/域名停用、Key/供给撤销、断流/取消/缺 usage 均验证 |
| 非文本结算快照不完整 | 音频/实时部分仍只读取会员快照；持久化报价未保存完整辅助价格 | 共用 RequestBudget/HasDurableBilling，持久化完整计费事实，不记录请求正文或 Key | 改价后仍按请求开始时的价格、工具价和换算单位结算；统计只写一次 |

## 3. 计费方案及必须保留的约束

1. 用主站共享计数和 ModelPriceHelper 得到预估预扣。代理商不需要先配置会员、逐模型限额或客户请求上限。
2. 在 TenantBudget 中冻结价格、分组倍率、工具价格、音频输入价、QuotaPerUnit 和表达式；冻结表达式的请求相关条件，重试使用原报价。TenantBudget 是价格快照，不再声称是提供商整次请求的最坏费用上限。
3. 继续通过持久化 Reserve 扣除预扣，保留客户、Key、Host 和租户的交叉校验，以及真实支付批次对额度的资金覆盖检查。非免费请求即使预估为 0 也不能走免费旁路。
4. 按真实 usage 计算最终 quota。实际高于预扣且余额足够时原子补扣；低于预扣退差额。支付批次、代理收入、客户余额和统计在同一事务中结算，幂等重试不重复扣款。
5. 余额不足时，不允许负余额或凭空增加代理利润；保存 actual 和原报价为 settlement_pending。该客户后续付费 Reserve 在 user 行锁下检查未结清记录，后台重试，充值补足后恢复。测试必须覆盖该完整过程。
6. 已派发但缺少最终 usage、取消或传输异常时保留资金与待核对事实，不能误退款；明确未执行的拒绝才走退款。WebSocket 每轮同样执行。
7. 真免费请求保留零余额可用；基础模型免费不等于收费工具、音频等附加项免费。按真实声明识别辅助费用，工具调用计数和结算共用冻结工具价，不能因请求中途改价漏记。
8. 这是与主站一致的**预估预扣**，不是零坏账担保：第一笔超出预扣的费用，以及在待结算记录形成前已经授权的并发请求，仍存在差额敞口。不能把 pending 记录描述成已追缴；也不以全站单请求串行、巨额最坏预扣或新增模型配置重新制造使用障碍。
9. 公共计费安全校验始终保留：已知 token/count 参数必须在现有共享上限内；渠道参数覆盖后的最终 JSON 也验证。它不分类消息内容，不限制工具 schema，不强制客户端提供可选上限。

本次不修改模型费率、现有价格表达式含义、客户充值换算或代理商销售倍率。验收对相同价格快照和 usage 输入比较实际 quota。

## 4. 压缩与其他 API 的范围

- `/v1/responses/compact` 及隐式等价路径继续关闭，不新增压缩按钮、后台压缩调用或压缩计费。
- 已存在于普通对话中的 opaque 历史项可原样发送；不在本地解密、重算或生成该内容。
- HTTP gzip 解码属于共享传输兼容，与上下文压缩功能分开；不重新启用已停用的前端/Worker 自动压缩组件。
- 普通文本模型中的图片输入、工具声明和工具结果复用共享推理路径。图像/视频生成任务、第三方任务插件、传统实时音频等独立 API 仍需要各自完整的租户资金映射和端到端验收；本轮不能仅删除路由 gate 就宣称全部任务 API 已支持。此边界不能反过来拦截普通 Codex 请求。
- 租户后台、平台管理、支付和数据导出等权限继续按身份隔离；公共推理协议兼容不意味着代理客户获得主站管理权限。

## 5. Edge 更新和发布顺序

1. 完成本地应用修复、基础设施 revision 2、定向回归和独立代码审查。
2. 运行基础设施强制 `make policy`。只有改变 Ansible 行为才追加 `make check` 和对应主机 check；本次不为脚本变更顺带全量部署平台。
3. 提交精确 infra 版本，排除活动 candidate/rollout/maintenance，安装该版本 controller 并通过 self-test；应用 contract pin 与安装版本同步。保留旧版本可恢复。
4. 用现有业务父事务生成新的 `prepare --mode business` 计划。旧计划无 revision 时按原 revision 1 字节验证，不能用新渲染器否定历史父事务。
5. 展示真实 plan.json SHA-256、完整 config.diff 和通过的门禁。runbook 24 要求对部署目录内 bind source 的 inode 保留热加载取得该差异的明确例外授权；不能用“修复了代码”替代此授权。
6. 通过 controller apply 审核后的精确计划；保留四把锁、CAS/digest/inode、frontend 状态同步、journal 和回退。主站 vhost 字节保持原样，不直接编辑线上文件。
7. 从干净的 production/kkrich 精确提交构建后端 external 产物；根据当次 live schema 证据选择契约，不顺带 schema 迁移。未修改前端则复用已兼容前端产物。
8. stage 精确 metadata，候选验证 → 10%/50%/100%（各至少 120 秒）→ promote → 即时和延迟状态、有效路由、脱敏 Relay 错误窗口、回滚资产验证。已授权完整上线后不再重复询问普通晋级。
9. 全链路验收才报生产完成。无关上游 502 先按路由/模型/请求窗口归因，不自动回滚；候选自身失败不能跳过。

## 6. 验收矩阵

| 层次 | 场景 | 成功标准 |
| --- | --- | --- |
| Edge | 1 MiB 边界、2 MiB、约 30 MiB、超共同大小 | 普通请求完整转发；超过共同边界才 413；无 Key 的 401 仅作为到达鉴权的证据 |
| 路径 | /v1/responses、/responses、chat、messages、原生 Gemini | Host、路径重写、query、body 与主站约定一致 |
| 传输 | SSE、Responses WS、gzip 请求 | SSE 不缓冲到结束；WS 101 和消息转发正常；共享解码不被租户额外破坏 |
| 请求 | 长历史、refusal、普通工具往返、图片、opaque 历史；数量缺省/0/越界/重复 | 不被租户类型白名单误拒，未知合法扩展保持公共透传行为；越界已知数量在共同边界拒绝 |
| 压缩关闭 | compact 两种路径 | 保持关闭，不被新 implicit rewrite 意外开放 |
| 权限 | 分组列表、所有 Key 写入口、模型列表、供给撤销 | 可见/可选/可保存/可调用一致，旧 Key 和 pinned WS 不能绕过撤销 |
| 计费 | 无会员配置、报价后改价、重试、低余额、免费 | 使用共享估算，价格冻结，余额不负，免费不能变成正费用 |
| 结算 | actual > reserved、差额不足、充值后重试、重复 settle | 完整 usage 留账，pending 阻断后续付费，补足后只结算一次，账本与统计一致 |
| 异常 | 取消、断流、usage 缺失、明确拒绝 | 不因 tenant 未设置 membership ID 而误退款或重复统计 |
| 隔离 | Host、租户、Key 不匹配；停用域名/站点 | 拒绝且不回落到主站，WS 每轮重新检查 |
| 生产 | 当前用户真实客户端/真实模型 | 真实成功响应、日志和扣费一致；不公开 Key、正文或个人信息 |
