## 1. 基线与优先级

原始预览用于确认信息层级、轻量摘要、三步申请、主次按钮、列表选中态和列表/详情并排结构。正式业务规则以开发技术文档为准；本附录补足原型没有覆盖的界面与操作。任何未实现功能不得用可点击的假按钮代替。订单、金额、状态、数量、权限和文件一律来自服务端。

以下对照初始预览的演示简化与正式基线；冻结参考已修复部分状态/数据问题，其余交互由本附录补全，不要求复制初始演示缺陷：

| 原型表现 | 正式页面基线 |
| --- | --- |
| 摘要宽约 236px、管理列表约 237px | 原型在 1024px 嵌入容器中，扣除 164px 导航和内容 padding 后业务宽约 804px；正式页面在该业务宽度保留 236px/237px，宽容器按第 3 节增长，上限分别 320px/360px。 |
| 560px 以下才堆叠 | 采用第 3 节内容容器断点，空间不足时提前堆叠，手机固定金额操作栏。不能因浏览器宽度足够而忽视展开侧栏占用的空间。 |
| 原型独立 sidebar、Lucide 图标、固定颜色 | 沿用现有产品 shell、Hugeicons 和主题 tokens；不新增第二套全局导航、图标库或主题。 |
| 主申请已占用的订单仍可勾选 | 只展示服务端资格；已占用行显示关联申请入口，不重复计算可申请金额。 |
| `approved`、回复后直接待确认 | 分别映射为 `approved_for_issue`、`awaiting_reconfirmation`，按规范状态显示。 |
| 重新开票复用第 1 版、拒绝也能显示演示附件 | 当前版与历史版分开；只有已交付附件显示文件卡，拒绝申请无虚构附件。 |
| 仅来源筛选、全部勾选、无下载和佐证入口 | 补齐本附录定义的搜索/筛选/分页、选择本页、下载和异议佐证。 |
| 常用抬头仅单条企业演示 | 一期支持个人/企业、多条、新建、选择、编辑、删除；资料与申请快照分开。 |

除以上修订及既有产品 shell 外，不自行改变三步结构、摘要顺序、状态操作区域、管理列表/详情结构；如需变化，同步更新此表和对应验收图。

## 2. 路由、页签与草稿

| 页面/操作 | 路由与行为 |
| --- | --- |
| 发票中心默认入口 | `/invoices` 无 `tab` 时 replace 到 `/invoices/new`，保持原型默认申请页。 |
| 申请开票页签、顶部主按钮 | `/invoices/new`，三步共用一个申请表单，步骤不另建持久状态。 |
| 申请记录页签 | `/invoices?tab=records`；筛选、页码可放经过校验的 search 参数。 |
| 常用抬头页签 | `/invoices?tab=profiles`。 |
| 用户详情 | `/invoices/:public_id`；提供返回申请记录入口。 |
| 管理端 | `/invoice-admin` 与 `/invoice-admin/:public_id`。桌面选择列表项更新 URL；窄屏进入独立详情并能返回原筛选位置。 |

中心的三个页签共用标题、三个摘要和 shell。三步切换、返回已完成步骤、在中心内查看记录后返回申请时保留内存草稿；刷新、退出登录或切换 host/tenant 会清空。草稿未提交时离开中心使用项目现有未保存提示方式，不把税号、邮箱、订单列表或草稿放入 URL、localStorage、分析事件。直接从钱包/会员订单预选时，先请求资格，失败保留页面并解释原因。

## 3. 尺寸与组件映射

| 项目 | 实现约束 |
| --- | --- |
| 页面 | 内容最大宽约 1240px、居中；桌面 padding 28–32px，手机 16px。shell 高度和 sidebar 宽度直接继承项目。 |
| 内容容器 | 页面去掉 shell 和左右 padding 后的内宽记为 C；页面内层设置 `container-type: inline-size`，以下 `cqw` 指该层。尺寸按 C 判定，不按整个浏览器视口猜测。 |
| 用户三步 | C≥760px 时 `grid-template-columns: minmax(0,1fr) clamp(236px,29.35cqw,320px)`，gap 18px；在 C=804px 时左约 550px、右 236px，与原型一致。C<760px 单列。桌面摘要 sticky 顶部为既有 header 底部 + 16px。不能用 `62% + 38% + gap` 造成溢出。 |
| 管理工作台/记录主从视图 | C≥800px 时左列表 `clamp(237px,29.48cqw,360px)`、右详情 `minmax(0,1fr)`，gap 17px；C=804px 时左 237px、右约 550px，与原型一致。C<800px 列表与详情分路由显示。 |
| 卡片 | 边框使用 `border`、表面使用 `card/background`，圆角约 12px；卡片内部间距 16–20px，分组间距 16–24px。 |
| 文本 | 页标题 26px（手机 24px）、中等字重；卡片标题 16px；数据行 13px、表单 14px、辅助文字至少 12px（这是原型 10–11px 辅助字的可读性修订）；手机输入 16px 避免浏览器缩放。金额使用 tabular nums；长订单号/抬头可换行，金额不拆字。 |
| 按钮 | 主操作仅一项；审核拒绝为 danger 次操作。手机触控区域至少 44px；loading 阻止重复操作，但保留有含义的文案。 |
| 状态 | 文字 + 图标/圆点 + 色彩；审核/暂停琥珀、成功绿色、异议/拒绝按语义使用警示色；不把颜色作为唯一差异。 |
| 底部操作栏 | `<768px` 固定底部，第一行显示已选笔数与CNY金额，第二行显示当前步骤主按钮；步骤2/3返回与主操作按1:2两列排列，按钮可换行且至少44px，防止320px/长翻译裁切。含安全区padding，正文预留176px加安全区，浮层打开时不能盖住弹窗操作。 |

复用 `AuthenticatedLayout`、`SectionPageLayout`、`AppHeader`、`AppSidebar`；业务表单用 React Hook Form + Zod。组件从 `@/components/ui` 复用 `tabs`、`card`、`table`、`checkbox`、`field/form`、`input`、`select`、`textarea`、`calendar/popover`、`pagination`、`badge`、`alert`、`skeleton`、`empty`、`dialog/alert-dialog`、`sheet` 和 `sonner`。项目是 Base UI，不套用 Radix 的 `asChild` 示例；选择/确认事件按已安装组件 API 编写。图标使用项目 Hugeicons。

## 4. 状态、数量与可见操作

| 状态 | 用户标签与可见操作 | 管理员操作/归属 |
| --- | --- | --- |
| `pending_review` | 待审核；查看资料/进度 | 通过、拒绝、财务暂停；待审核队列 |
| `approved_for_issue` | 待开票；查看资料/进度 | 上传校验、确认交付、财务暂停；待开票队列 |
| `delivered` | 待确认；预览、下载、确认无误、发票有问题 | 查看当前/历史票据、必要时财务暂停；全部队列 |
| `disputed` | 异议处理中；查看附件、问题与回复；补充说明/佐证，无旧版确认主按钮 | 回复并请求重核、补发更正、财务暂停；异议队列 |
| `awaiting_reconfirmation` | 待重新确认；查看回复、预览、下载、确认无误、继续反馈 | 查看回复，必要时补发或财务暂停；全部队列 |
| `confirmed` | 已确认；预览、下载、查阅历史、反馈问题 | 查阅历史、必要时财务暂停；用户再反馈后进入异议队列 |
| `finance_hold` | 财务待核查；显示用户可见原因和既有交付历史，无推进按钮 | 显示暂停来源阶段、原因，按权限恢复或执行合法财务结论；全部队列的财务待核查状态筛选 |
| `rejected` | 已拒绝；显示原因与重新申请入口，无未交付附件 | 只读；全部队列 |

摘要和分组统一使用以下集合，互不重叠：处理中 = `pending_review + approved_for_issue + disputed + finance_hold`；待确认 = `delivered + awaiting_reconfirmation`；已完成 = `confirmed + rejected`；全部包括所有状态。可申请金额为全部符合资格且未占用订单的服务端全量汇总，与当前页条数无关。管理员队列数量采用当前q/日期/币种/来源筛选，但忽略queue/status/分页；结果total采用全部当前条件。计数与列表总数各有明确含义，不能从当前页计算。

`confirmed` 的「反馈问题」仍绑定当前交付版本，提示“确认收票不影响后续更正反馈”，提交后进入 `disputed`；不撤销既有确认事件，不用“确认”文案表达放弃权益。`awaiting_reconfirmation` 的再次确认仍针对原版本，不能伪造一个新附件版本。

## 5. 逐屏交付清单

### U01：选择订单

显示三步进度、订单号搜索、来源切换、付款日期范围、币种和重置筛选；筛选作用字段明确为付款时间。列表分页，默认 20 条。表头显示「选择本页」并有部分选中的 indeterminate 状态；无可选行时禁用。跨页保留已选，摘要可查看/移除已选清单；50 笔上限同时由前后端校验。首次选择确定合并分组；点击不兼容行时解释币种/卖方/税目原因，允许保留选中但禁止下一步，提供移除或分开申请入口。下一步及提交前用quote重核，不能根据旧列表继续。

「暂不可开票订单」独立折叠区或抽屉有自己的计数和分页：缺凭证金额为“待核验”；已占用且属于本人才显示申请号和查看申请；其他占用不泄露编号；余额付款提示原充值；退款/拒付与未开放币种显示对应原因。不把这些行混为“缺少凭证”。筛选无结果与全无可申请订单使用不同空态。

### U02：发票信息

个人/企业切换、常用抬头选择器、必要字段与票种依赖显示；企业税号、邮箱等错误在字段下。切换个人后税号不提交，切回企业可恢复未提交输入。保存常用抬头明确选择“另存新抬头”或“更新当前抬头”，失败不能伪装保存成功；保存与申请是独立结果，申请成功不因抬头保存失败回滚。资料最大长度与服务端一致。返回 U01 保留输入。

### U03：核对提交与提交结果

展示卖方、票种、抬头、税号脱敏尾号、接收邮箱、逐笔订单号/来源/实付总额以及说明；有“修改订单”“修改资料”入口。确认框必选。网络未知结果以同一操作 ID 重试；冲突指出变更订单并保留其余草稿，不静默扣减金额后提交。成功显示服务端申请编号并进入详情。只有财务已配置时才显示预计时效。

### U04：申请记录与详情

记录包含全部/处理中/待确认/已完成视图、状态筛选、申请号/订单号搜索、创建日期及分页。桌面列表可并排当前详情；小屏列表和详情分开，不能把全部记录和超长详情连续堆叠而无返回路径。

详情显示当前状态操作区、申请资料、订单快照、票据版本与时间线。文件卡展示净化文件名、真实类型/大小、版本、发票号、开票日期和金额；提供预览、下载。已被替代的历史版明确标注“历史版本，请以当前版为准”，可经授权下载查阅，不能再确认旧版。预览失败提供重新加载与下载，不仅显示白框。

确认弹窗提示核对抬头、税号、金额和文件，按钮统一为「确认无误」。异议弹窗五类：抬头/税号错误、金额不符、附件打不开、信息不全、其他；说明 1–1000 字；佐证可选，单个不超过 20 MiB 的 PDF/PNG/JPEG，显示上传进度、失败、移除。继续反馈绑定同一当前版本与既有异议处理链；提交后回到异议处理中。

### U05：常用抬头

卡片含个人/企业、抬头、脱敏税号和邮箱；新建、选择、编辑、删除。个人无需税号；表单与 U02 使用同一规则。删除需确认且说明不影响已提交申请。空态引导新建，保存中禁止双击，版本冲突保留输入；未经本人或管理员详情授权不在列表暴露完整资料。

### U06：进度通知

用户中心和管理员工作台在标题区增加轻量“进度通知”入口与未读badge，点击打开drawer/弹层，显示事件摘要、时间、申请号及已读状态；打开一项进入申请并标记该项已读，另提供全部已读。仅显示当前身份允许的事件；加载/空/失败可重试。通知不含完整税号/邮箱/附件链接，不以打开通知代替确认收票。该入口是原型未覆盖的补充，采用同一按钮/弹层组件体系，不新增全站通知导航。

### A01：管理员工作台

待审核、待开票、异议、全部四队列；财务待核查在全部中用状态筛选，并显示相应计数/提醒；搜索申请号/订单号/用户名/账号邮箱，另有日期、来源、状态、币种筛选及分页。税务抬头加密保存，一期不承诺对抬头或申请接收邮箱做模糊检索。左列表选中态保持原型强调条与轻背景；右详情基于当前申请，不用列表上一行的缓存拼出用户资料。队列完成后清楚显示空态或自动选择下一项，不能保留失效操作按钮。

### A02：审核与财务暂停

逐笔付款核验摘要、抬头/税号和申请金额可见。审核通过弹窗说明通过仅进入待开票；拒绝说明 1–1000 字、用户可见，内备注分开。首期为主站平台管理员操作，不新建独立 finance 角色。暂停弹窗记录原因与用户可见说明；恢复按钮展示将返回的阶段。已交付阶段暂停后当前/历史文件保持可见，不能用“拒绝”释放曾经开具的订单。

### A03：上传交付

文件上传与最终交付分开：待上传 → 上传中 → 已校验暂存/校验失败 → 元数据核对 → 确认交付。显示单文件限制 20 MiB、PDF/PNG/JPEG；文件错误原位呈现，允许移除重传。发票号、开票日期必填；申请金额/币种只读；补发时显示版本号及旧版留存提示。确认交付前汇总抬头、税号尾号、金额、文件和通知邮箱。业务成功邮件失败时显示“已交付，邮件提醒待重试”。不保留演示文件按钮。

### A04：异议与补发

显示分类、说明、用户佐证、提出时间及对应版本。回复说明必填；“回复并请用户确认”转待重新确认；“补发更正发票”进入 A03 的新版本上传流程。打开上传、上传暂存或校验失败均不修改申请状态，也不隐藏原已交付文件；只有新版本正式交付才切换当前指针并转待确认。财务离线处理用暂停操作并保留旧票。管理员没有代用户确认或任意状态下拉框。

## 6. 控件与 API 动作对照

表中路径均带 `/api` 前缀；业务 payload、版本、幂等键与错误码沿用开发技术文档。本表不允许前端自行增加 `status` patch 或模拟资格。所有写操作至少失效当前详情、候选资格/汇总、用户记录与管理队列中受影响的查询。

| 屏幕 / 控件 | API | 成功或失败后的界面 |
| --- | --- | --- |
| 中心初始化、票种和字段约束 | `GET /api/invoices/policy`、`GET /api/invoices/summary` | 返回主站开关、支持的来源/币种/票种、卖方/合并规则、税号和资料约束、数量上限、时效（未配置为 null）。关闭时展示原因和支持入口，不渲染可提交的假表单。 |
| U01 搜索/筛选/翻页 | `GET /api/invoices/eligible-orders` | 返回 `items/total`及不可申请原因；全量资格汇总从summary取得，不可申请区用eligibility=unavailable独立分页；请求期间保留选择，旧筛选响应不得覆盖新筛选。 |
| U01 快捷预选、下一步/提交前重核 | `POST /api/invoices/quote` | 返回当前逐项资格/原因、合并组及金额；不创建申请/占用，失败保留选择并定位失效项，创建仍重验。 |
| U01 checkbox/选择本页/移除已选 | 不写服务端 | 只修改当前身份的内存草稿；不由前端产生实付事实。资格变动在下一步/提交时重新核验。 |
| U02 常用抬头 selector/编辑详情 | `GET /api/invoice-profiles`、`GET /api/invoice-profiles/:id` | 列表脱敏，选定后按本人授权详情填充；已删除或冲突保留手填资料并提示重选。 |
| U02/U05 新建、编辑、删除抬头 | `POST /api/invoice-profiles`、`PATCH/DELETE /api/invoice-profiles/:id` | 成功后更新列表并提示；失败字段下反馈，不触发申请提交。 |
| U03 提交 | `POST /api/invoices` | 显示成功编号并导航详情；资格/版本冲突保留草稿、逐笔解释；超时重放同一幂等请求。 |
| U04 记录和详情 | `GET /api/invoices`、`GET /api/invoices/:public_id` | `404` 不泄露其他人对象；可恢复错误显示重试，不当作“没有申请”。摘要采用独立全量统计值，不对当前页求和。 |
| U04 预览/下载 | `GET /api/invoices/:public_id/files/:file_id` | 每次服务器授权后输出文件；图片/PDF 使用合适查看器，下载响应由服务端指定安全文件名；失败显示原因和重试。 |
| U04 确认无误 | `POST /api/invoices/:public_id/confirm` | 带当前 `delivery_version + version`，更新已确认和时间线；新版本冲突时重新查看新版本后才能确认。 |
| U04 佐证上传/提出异议/继续反馈 | `POST /api/invoices/:public_id/attachments`（purpose=dispute_evidence），随后 `POST /api/invoices/:public_id/disputes` | 文件暂存成功后取得用途受限 ID；提交描述与附件引用；请求失败保留文字和仍有效的暂存引用，成功进入异议处理中。 |
| U04 异议处理中补充说明/佐证 | `POST /api/invoices/:public_id/disputes/:dispute_id/messages` | 使用已上传佐证ID和当前version，追加当前未解决轮次，保持disputed，不再调用创建disputes接口。 |
| 进度通知入口/未读/已读 | 用户`/api/invoices/notifications`、管理员`/api/admin/invoices/notifications`的GET及POST `/:event_id/read`、`/read-all` | 进入申请、只更新当前reader已读；不等于确认发票，通知未读不作为待办计数。 |
| A01 队列/筛选/详情 | `GET /api/admin/invoices/summary`、`GET /api/admin/invoices`、`GET /api/admin/invoices/:public_id` | 队列counts按q/日期/币种/来源过滤，列表total再包含当前queue/status；切换申请不能残留上一笔的上传文件、回复或弹窗确认目标。 |
| A02 通过/拒绝/暂停/恢复 | `POST /api/admin/invoices/:public_id/approve`、`reject`、`hold`、`resume` | 基于当前版本提交；刷新后显示真实状态。并发处理冲突提示“申请已被更新”，不自动替用户重复审批。 |
| A03 上传暂存/正式交付 | `POST /api/admin/invoices/:public_id/attachments`、`POST /api/admin/invoices/:public_id/deliveries` | 暂存不代表交付；交付成功才更新用户可见版本；冲突重新核对当前详情，不能把旧暂存文件交到另一申请。 |
| A04 查看用户佐证/票据 | `GET /api/admin/invoices/:public_id/files/:file_id` | 按用途授权；未交付暂存仅授权管理员可见，不能通过用户路径绕过交付。 |
| A04 回复/补发 | `POST /api/admin/invoices/:public_id/disputes/:dispute_id/reply`、`reissue` | 回复同版本进入待重新确认；补发先上传暂存，reissue 正式交付后产生新版本。两者不是同一个按钮或同一种结果。 |

### 通用错误动作

| 错误 | UI 必须行为 |
| --- | --- |
| `400/422` | 对应字段/订单行显示可读错误并定位；保留其余有效输入。 |
| `401` | 沿用登录处理，清理身份相关缓存；不把 PII 草稿拼入重定向地址。 |
| `403/404` | 显示无权限/不可访问的统一状态；去除当前敏感详情缓存。 |
| `409` | 读取最新摘要并解释资格、版本或幂等冲突；任何重试都不得生成新申请来掩盖冲突。 |
| `413/415` | 显示文件大小/类型错误，允许重新选择；未成功上传的文件不得显示为已校验。 |
| 网络超时/服务异常 | 区分“提交结果未知”和“明确失败”；查询或重放同一幂等操作；页面保留输入，提供重试。 |

## 7. 失败、响应式与验收证据

所有页面覆盖 skeleton、真实空态、筛选无结果、可重试请求失败、无权限、schema/财务配置未就绪。`409` 刷新当前状态并保留仍合法输入；上传失败不丢失文本；导航切换后旧请求返回不得覆盖新申请。对长抬头、长订单号、6 种语言、金额较大和时间线较长的数据做布局验收。
