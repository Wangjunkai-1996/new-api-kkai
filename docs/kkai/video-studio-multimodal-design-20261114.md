# 视频工作室多模态参考：产品设计方案

日期：2026-11-14。状态：多角色评审后，按单一新流程收敛的产品设计基准；本地实现与验证进展另见[实现与验收记录](video-studio-multimodal-development/implementation-qa.md)。设计目标不代表真实供应商能力已验收或已上线。

本方案由产品经理、UX/前端/QA、后端架构三个角色独立评审并交叉讨论，主设计者汇总取舍。交付重点是完整 Web 生成页设计稿，本文明确页面交互、状态、数据与实现边界。依据当前应用源码与供应商特价版文档，不代表真实用户访谈、生成质量测试或生产状态核验。

页面评审以[完整 Web 生成页设计稿](video-studio-multimodal-web/index.html)为准，替代此前只展示局部交互的示意稿。新页面采用统一创作表单，不设“文生 / 图生”顶层模式标签。

## 1. 推荐方向

在现有视频工作室创作台内，增加一个**支持图片、视频、音频混合添加的“参考素材”区**。用户仍先选模型，明确知道哪些素材参与本次生成、为什么暂时不能生成、实际使用哪个模型以及预计费用。

第一版完整交付图片、视频、音频组合参考。开发可以拆分，产品上线不再把音频遗漏到下一版。单图、单视频及混合素材统一进入新参考生成流程，不保留旧页面、旧请求协议或旧草稿重放。旧样片与草稿不自动转换，需要使用时按新格式重新配置；已有作品、素材和账目保持完整，已受理任务继续完成处理与结算。

核心体验原则：

- 参考音频不是独立的“音生视频”模式：它必须搭配图片或视频。
- 单张参考图与首帧控制不是同一种意图，不根据数量自动转换。
- 不因用户添加视频而静默切换模型、分组或价格。
- 不因模型或方式切换而静默删除素材、截断列表或覆盖提示词。
- 上传成功、媒体校验通过、任务已受理、结果可播放是不同状态。
- 产品展示的能力必须是供应商支持、本站实现、当前用户可用渠道的交集。

## 2. 解决谁的什么问题

目标用户是当前工作室的创作者：已准备产品图、角色图、动作视频或背景音乐，希望组合这些素材生成新视频。以下是设计场景，尚无访谈数据证明占比。

| 场景 | 用户输入 | 期望 | 产品边界 |
| --- | --- | --- | --- |
| 产品短片 | 产品图片 + 提示词 | 保留外观并生成运动 | 不承诺每帧精确复刻商品细节 |
| 动作/镜头参考 | 图片 + 视频 | 参考主体与运动/构图 | 不把上传视频等同于编辑原视频 |
| 配乐与节奏参考 | 图片 + 音频 | 视频与声音风格相符 | 不承诺逐拍同步或原声完整保留 |
| 综合创作 | 图片 + 视频 + 音频 | 同时提供视觉、动作、声音条件 | 各类型分别校验，不能静默漏传 |
| 继续调整 | 已上传素材 + 修改提示词/参数 | 复用素材并重新生成 | 新生成有新费用；未知提交先查状态 |

首版不包含：时间线剪辑、裁剪与转码、声音克隆、自动口型同步、多轨混音、批量任务、新素材管理中心、模型家族自动路由。

## 3. 能力事实与采用的边界

### 3.1 文档支持与本站现状

截至本次查阅，2.5 和 2.0 特价版均声明支持图片、视频、音频参考。旧特价接口也给出了三类素材组合的例子，并非只有新版 model-center 接口支持。

实施前本站源码具备图片、视频上传和单个视频参考，但将视频参考也归入 `image_to_video`；后端角色、请求组装和样片快照限制多素材组合，音频上传和纯音频探测尚未接通。这是本方案提出时的问题基线，后续本地改造状态见实现记录。“生成音频”开关表示输出音轨，不能替代参考音频。

| 媒体 | 供应商详细场景限制 | 首版建议 |
| --- | --- | --- |
| 图片 | 参考场景最多 9 张；单张 <30 MB；宽高比在 (0.4, 2.5)，宽高在 (300, 6000) px | 先支持现有可可靠处理的 JPEG/PNG/WebP；不一次性承诺文档中的所有图片格式 |
| 视频 | MP4/MOV；最多 3 个；单个 2–15 秒；总计 ≤15 秒；单个 <50 MB；24–60 fps | 接受经过实际容器/编码校验的 MP4/MOV；不沿用现有 WebM 作为 Seedance 支持承诺 |
| 音频 | WAV/MP3；最多 3 段；单段 2–15 秒；总计 ≤15 秒；单段 <15 MB | WAV/MP3，经真实内容与时长校验后可使用 |
| 组合 | 音频不能单独输入；至少有一张参考图或一个参考视频 | 可先上传音频，组合完整前不报价、不生成 |
| 方式 | 首帧、首尾帧、多模态参考互斥 | 每次请求只选择一种意图，不混传互斥角色 |

这些是能力上限候选，不是默认接受值。实际限制取模型约束、本站上传上限、适配器已验收范围三者中的最严格值。大小在后端以字节校验；显示 MB 与实际字节值保持一致。时长保留精度，不能把 15.01 秒四舍五入为 15 秒后放行。30/50/15 MB 的严格“小于”边界不能写成“小于等于”。

### 3.2 不应由设计稿擅自确定的事实

| 待确认项 | 已知证据 | 决策与负责人 |
| --- | --- | --- |
| 2.5 数量上限 | 字段表写 30/10/10，详细场景写 9/3/3 | 首版不超过详细场景上限；接入负责人向供应商核实后才能提高 |
| 三类素材合计上限 | 所查页面没有给出清晰的一致总上限 | 启用能力前明确已验收的 `max_total_count`；不能直接推断可同时放满 9+3+3 |
| 当前特价模型路由支持哪些组合 | 本站精确模型名与供应商 model-center ID 不同 | 接入负责人逐个型号验收；不得仅按名称后缀宣称能力 |
| 音频参考与关闭输出声音的组合 | 文档分别列出两个能力，未给出足够的组合保证 | 未验证时阻止该组合，提示移除参考音频或开启视频声音；不静默改开关/丢素材 |
| 输入视频自带音轨与参考音频的优先级 | 没有足够明确的声音选择契约 | 不增加“优先音轨”等未经支持的控件，也不承诺声音结果 |
| 提示词素材编号语义 | 旧接口示例使用“视频1、音频1”，不是完整的结构化引用规范 | 首版普通提示词；专门的引用芯片待映射契约验证后再做 |
| 外置适配器 | 应用插件向兼容 `/v1/videos` 转发；同级 infra 有 `seedance-special-adapter` 路由引用，未定位实现源码 | 技术负责人定位维护方、源码与版本；完成契约验收再开放，不以应用插件改完代替整条链路完成 |
| 新组合的价格口径 | 现有普通/视频参考型号可能是不同计价 SKU | 以真实计价配置与接入验收为准；不自行按素材数或输入音频时长添加倍率 |

这些事项不影响设计评审，但属于开放对应生产能力前的明确依赖。本次没有访问生产或进行付费验证。

## 4. 页面与主要流程

### 4.1 保留创作台布局

沿用现有“创作 / 作品库 / 任务”分工和桌面编辑器、结果区布局。本次扩充编辑器，不另建多模态页面或改变用户找作品的路径。创作区使用一个表单，用户无需先切换文字生成或参考生成。

编辑器顺序：

1. **模型**：保留当前精确型号选择，旁边展示已验收能力摘要。
2. **参考素材**：一个混合素材区，按类型组织卡片与额度；是否必填由当前模型决定。
3. **提示词**：说明要生成的内容及如何使用素材；仍使用现有文本输入。
4. **输出设置**：时长、比例、分辨率、视频声音。
5. **费用与生成**：显示实际型号、有效素材摘要、报价及阻断原因。

没有参与生成的参考素材时，按文字生成处理，但仅当前型号支持文字生成时可提交；有参考素材时按参考生成处理，并验证组合是否完整。视频必填型号即使素材区为空，也继续提示补充视频，不自动切换型号或放宽要求。

仅当当前模型已支持并验收时，在参考素材区提供明确的高级“画面引导”选项，区分仅首帧和首尾帧；首尾帧使用固定槽位。该选项不是顶层模式标签，且与多模态参考互斥，不能根据只有一张图片便自动开启首帧控制。本次三类参考是必交范围，不顺带承诺所有 Seedance 型号开放新的帧控制能力。

### 4.2 典型完整流程

用户选择一个已支持三类素材的模型 → 在同一表单添加产品图、动作视频和背景音乐 → 各文件上传并校验 → 查看分类额度与参与素材 → 填写提示词与输出参数 → 收到服务端报价 → 点击生成 → 保存提交回执并进入既有任务/结果流程。

若用户先添加音频，素材可正常上传；区域提示“请再添加至少一张图片或一个视频”。补充视觉素材后自动解除该组合错误，不要求重传音频。

### 4.3 素材区结构

一个添加入口提供“图片 / 视频 / 音频”，桌面支持混合拖入。支持类型由能力声明决定，未支持项给出明确原因。不要放三个长期空白的大上传框。

有素材后按图片、视频、音频分组。每组展示数量；视频和音频额外展示分类总时长，例如：

`图片 2/9 · 视频 1/3，8/15 秒 · 音频 1/3，5/15 秒`

两类时间分别计算，不能将输入总时长当成输出生成时长。若已确认存在跨类型合计上限，另显示总体数量。

| 卡片 | 必须展示 | 操作 |
| --- | --- | --- |
| 图片 | 缩略图、文件名、上传/校验状态 | 预览、替换、移除 |
| 视频 | 封面、时长、文件名、状态 | 打开原生播放、替换、移除 |
| 音频 | 音频标识、文件名、时长、状态 | 原生播放、替换、移除；首版不做波形 |
| 失败项 | 文件名、明确原因 | 对应阶段的重试、移除 |

当前活动媒体互斥播放，切换卡片暂停上一个，音频不自动播放。移动端不压缩原生控件至不可用，可展开播放区。

### 4.4 替换、删除、排序

- 替换采用“旧素材保持有效，新素材上传校验通过后再切换”。失败保留旧素材；替换进行中暂停新报价/提交，防止用户以为替换已生效。
- 移除只从本次草稿解除绑定，不直接删除对象存储文件。垃圾回收遵守既有引用和生命周期机制。
- 同一文件/资产重复添加时提示“已添加”，不默默重复消耗额度；帧槽位是否允许同一图片复用按既有角色规则处理。
- 顺序具有请求语义。组内排序提供“前移/后移”，拖拽仅为增强；不强求跨类型交错排序。
- 首版不引入富文本编辑器、提示词 AST 或自动 `@素材` 引用。卡片以文件名识别，可以显示本次顺序，但不能把 UI 编号宣传为已验证的供应商引用语法。
- 删除、替换或重排后提示用户检查提示词中的素材描述，不擅自解析、改写自然语言“图1”。后续若提供结构化引用芯片，必须使用稳定绑定身份，删除引用目标后阻止提交，不能偷偷指向另一张图。

## 5. 模型与参考素材调整

### 5.1 明确型号与价格

第一版继续保留现有模型选择。给模型增加“支持参考图片 / 视频 / 音频”等真实能力说明，不要求用户通过 `_with_video_ref` 猜能力，也不先实现隐藏型号的智能路由。

当前模型不支持已选视频时，显示具体可用候选，例如：“当前模型不支持这些视频。切换到 Seedance 2.5 720p · 视频参考”。候选必须同时满足用户权限、分组、输出设置、素材数量与媒体验证要求。

用户点击后才改变模型，提示哪些输出设置发生变化，并重新报价。无兼容候选时保留素材并说明原因；不建议不可见模型，不自动更换 Token 或分组。

### 5.2 素材不丢失，也不能暗中排除

当前模型或明确选择的高级参考方式不支持的素材保持可见，标记为“待处理”；此时禁止报价/生成。用户可以选择切换兼容模型、调整高级参考方式，或明确点击“本次不使用”。

只有用户明确排除素材后，它才进入折叠区“本次未使用（N）”，不计入有效素材和费用摘要。可恢复、移除；切回兼容模型不偷偷重新加入已排除素材。

统一表单保存提示词、参数、参与素材和已排除素材，不维护文生/图生两份模式草稿。移除或排除全部参考素材后，当前模型支持文字生成才允许无参考提交；视频必填型号继续阻断并提示添加视频。调整模型或高级参考方式时保留草稿，互斥素材必须由用户明确排除或重新选择，不能暗中转移到未使用区。每次发送前摘要准确显示真正参与的素材。

任何有效素材、角色、顺序、模型、参数或提示词变化都会使旧报价失效。暂存区的纯 UI 操作若不改变请求语义，不需要重报价。

## 6. 校验、错误与可恢复状态

校验分三层：选文件时检查已知的类型/大小/数量；服务端按真实内容探测媒体；报价和提交时重新验证组合、权限、素材状态与能力。前端预检不能代替后端验证。

| 状态/问题 | 用户看到的反馈 | 可执行动作 |
| --- | --- | --- |
| 上传中 | 文件进度、暂停/取消等现有能力 | 保留已完成素材；不生成 |
| 校验中 | “正在检查素材” | 查询状态；等待较长时仍保留草稿，不重复上传 |
| 可使用 | 类型、时长、缩略图/播放 | 可进入报价 |
| 只有音频 | “参考音频需要搭配至少一张图片或一个视频” | 添加视觉素材 |
| 视频总时长超限 | “视频总时长 17.2 秒，最多 15 秒” | 替换或移除；首版不提供在线裁剪 |
| 数量/大小超限 | 当前值、模型上限及出错文件 | 调整该文件，其他文件保留 |
| 伪装类型/损坏编码 | “无法读取该音频，请换用有效的 MP3 或 WAV” | 替换文件；不以扩展名强行放行 |
| 音频 + 输出声音关闭 | 未验收组合时说明不支持 | 用户选择开启声音或移除音频 |
| 模型不兼容 | 指出不支持的素材与可用候选 | 切模型或明确排除素材 |
| 素材不可访问/已删除 | 指出该文件无法使用 | 重传/替换；不得提交仍有效的子集冒充完整请求 |
| 报价过期或能力变化 | “配置已变化，正在重新计算费用” | 成功后重新点击生成；不自动代用户提交 |
| 新生成请求超时、受理不明 | “正在确认任务是否已受理” | 按本次提交回执或幂等键查询；不自动创建新请求 |

文件错误放卡片内，组合错误放素材区下方，主按钮附近展示最关键的阻断原因。避免用多个 toast 作为唯一反馈。

恢复重试必须区分上传、查询校验状态、重新报价、查询已提交任务和新建生成。上传重试不应新建视频任务；任务受理不明不能通过“重新生成”悄悄再次扣费。

## 7. 最小可落地的产品技术契约

### 7.1 能力由后端统一声明

扩展现有模型 specification，声明支持的创作方式、每类媒体的格式/数量/大小/时长、分类总时长、合计上限和少量明确组合规则。能力定义带版本，管理员使用已验证预设，不直接编辑任意请求字段映射。

只需要当前业务的有限规则：需要视觉素材、必须包含视频、参考方式互斥、参考音频与输出声音的已验证组合。不要制造任意 `requires_any/forbidden_with` 表达式或通用规则引擎。

型号只是显示和路由身份，不能作为前端推断能力的唯一依据。同名模型的候选渠道必须都支持所选输入，或由分发层限制到匹配能力的渠道；不能报价成功后随机分到不支持音频的渠道。

### 7.2 有序参考集合

统一表单按实际参与的输入确定请求语义：无参考素材时使用文字生成，有参考素材时使用 `reference_to_video`；模型能力和必填素材要求仍由后端校验。仅已验收的高级帧控制由用户明确选择，不要求在页面展示对应的顶层模式标签。素材为明确的有序集合，最小字段为 `asset_id / role / position`。`position` 表示每类角色内顺序；后端按固定角色次序及 position 规范化，既不依赖前端数组偶然排列，也不再按 asset ID 重新排序。

媒体类型从服务端真实素材记录取得，不能相信客户端填入的 MIME。前端可以有稳定的客户端条目 ID 管理上传与替换，但首版无需将其变成新的数据库实体。

报价及幂等判断必须覆盖实际型号、能力版本、模式、参数、提示词和有序素材绑定。签名下载 URL 会变化，不进入语义指纹；素材对象验证后不可原地改写，替换产生新的 asset ID。

同一幂等键携带相同语义只恢复原提交；携带不同素材顺序或内容不能当成同一请求。新生成只使用这一套规范化与哈希规则，不维护旧请求的解析或重放分支。已经受理的任务依据现存任务记录继续处理，不通过重新提交旧请求延续任务。

### 7.3 上传、存储和任务

复用现有 Uppy、分片上传、签名访问、资产校验、任务关联和清理设施，并提供新流程内的上传恢复。音频仍是参考资产，使用 MIME 区分，不新增一套素材库，也不为旧上传草稿建设转换层。

纯音频探测需要单独的合法分支；验证后进入 ready，不生成视频海报和视频预览。首版只接受经验证的 MP3/WAV 编码组合；为输入资源设置时间、体积、解码资源限制，延续当前安全媒体处理边界。

现有资产含 MIME、时长、大小、codec，任务关联含 role、position，先复用。是否增加媒体元数据字段要由实际校验需求决定，不能把“无数据库变更”作为未经验证的承诺。新生成只接受具有所需媒体验证证据的资产；缺少证据时要求重新上传，不增加存量素材批量重检或迁移工程。

### 7.4 适配器与计费

应用服务把规范化后的资产绑定转成上游引用，供应商适配器负责投影为 `content[]` 或分类数组。只选一种已验证的上游协议路径完成首版，不同时重写两套接口，不把新 model-center ID 直接当本站客户型号。

应用插件和外置适配器必须共同验收：媒体类型、顺序、数目、签名 URL 生命周期、上游拉取时机、失败原因及任务结果归档。不能只把 `reference_audios` 加入白名单便宣称支持。

实际模型在报价前确定。沿用现有报价、预扣、结算、退款安全链路；参考素材是否改变计价以真实契约为准。服务端对输出时长、输入时长、数量和任何计费倍率实施上限，禁止用未校验媒体元数据直接乘出费用。

### 7.5 新样片、草稿与存量数据

新样片保存引用角色、顺序及能力版本快照，返回真实媒体类型和可用状态；不按最新 profile 猜测每个 asset 是图片还是视频。旧样片不自动转换或提供一键重放，需要展示为新流程样片时由管理员重新配置并验证。

“使用样片”仅适用于按新格式配置的样片，先恢复参数和全部引用，逐项检查仍可用。能力降低或素材缺失时给出修复动作，不用截取前几个素材实现看似成功的复用。覆盖当前新流程草稿前明确提示，避免丢失用户正在编辑的内容。

新流程草稿只保存和恢复新格式，不读取或重放旧草稿。旧草稿与旧样片不作为上线转换任务，也不在切换时批量删除；用户需要继续创作时按新格式重新配置。

已提交任务保存当时实际输入快照，当前编辑器继续修改不影响该任务。已有作品、任务、素材关联和账目保持完整，历史记录可查看结果与状态；不承诺旧输入可重新生成，也不承诺永久保存全部上传文件。已经受理的任务继续查询上游、归档结果，并按实际结果完成结算或退款。

### 7.6 单一新流程与切换边界

页面、服务端与适配器统一使用新参考集合和校验规则。能力版本用于识别当前模型约束，不用于协商两套传输协议；不保留旧单图/单视频专用流程、旧公共标量协议、旧页面适配或自动降级。

前后端与适配器完成同一新契约验收后开放入口。过时页面或旧格式请求在预扣费和创建任务前明确拒绝，提示刷新页面后重新配置，不自动转换或重发。切换不清空存量数据；已受理任务的后台处理和结算独立于新建生成入口，不要求保留旧客户端操作流程。

## 8. 管理端与运行边界

管理端提供按精确模型维护的已验证能力预设、可收紧的限制、启用状态和简洁验证记录。管理员不能把限制提高到适配器合同之外；提高能力或改变语义产生新版本，重新校验按新格式发布的样片；失效样片暂停使用，修正后再开放。

优先复用当前工作室 `off/admin/all` 与 profile 启用能力。已有合适的权限/分组机制时用于小范围放量；否则先管理员后全量，不为本功能建设新的灰度平台。

关闭生成入口时阻止新建请求，同时保留已有作品、任务记录、素材关联和账目，已受理任务继续完成处理、归档与结算。故障处置优先关闭新增入口并修复，不通过删除数据、重发任务或重复扣费恢复服务，也不为回退建设新旧协议双轨。

## 9. 响应式、文案与无障碍

沿用当前浅深色 token、控件和上传库。桌面维持现有创作/结果分栏，小屏保持一个编辑器实例并按页面顺序折叠。

素材卡在小屏按宽度变为双列/单列；文件名、错误文本可换行，音频控件可展开。添加、移除、替换、排序都有键盘操作路径，不依赖 hover。删除后焦点返回相邻素材或添加按钮；上传状态适度播报，不随每个进度更新打断读屏。

“参考音频”和“视频声音”使用不同标签。限额文案参数化；动态数量、时长、错误信息在 en/zh/fr/ja/ru/vi 六个语言中完整支持，测试长文本与 200% 缩放。原型中的中文只用于设计演示，不能直接作为业务硬编码交付。

## 10. 角色分歧与最终取舍

| 讨论点 | 候选意见 | 最终选择及原因 |
| --- | --- | --- |
| 音频何时上线 | 先多图/视频，再音频 | 内部可拆阶段，首次完整公开交付同时包含三类；音频是本次核心缺口 |
| 三个上传框还是一个区 | 三个框直观但占据创作台 | 一个混合区 + 分类计数/卡片，既紧凑又能表达约束 |
| 顶层模式 | 文生/图生标签切换 / 统一表单 | 统一表单按有效素材确定文字或参考生成；高级帧控制仅在已支持模型中明确选择，音频不是独立可提交模式 |
| 模型自动匹配 | 添加视频后自动切 SKU | 首版显式选择兼容型号并重报价；防止隐藏费用变化 |
| 不兼容素材 | 自动清除或自动排除 | 保留并阻断，用户明确排除后才进入“本次未使用” |
| 引用编辑器 | 首版做 `@素材` 和提示词 AST | 首版普通文本，准确传递顺序；不伪造上游引用语义 |
| 能力配置 | 任意逻辑 DSL | 少量固定字段与规则，覆盖当前真实模型 |
| 存储 | 新建通用素材中心 | 复用现有资产与 task link，必要元数据按证据补充 |
| 格式与裁剪 | 尽可能接受所有文件并转码 | 支持已验证格式，文件级说明；避免引入媒体编辑工程 |
| 新旧流程 | 双协议、旧页面适配和旧草稿自动恢复 | 统一新流程；旧样片与草稿按需重新配置，已有数据与在途任务结算安全独立保留 |

## 11. 交付顺序与完成标准

| 阶段 | 交付物 | 结束门槛 |
| --- | --- | --- |
| A：锁定能力 | 精确型号/适配器版本的组合矩阵、数量/时长/格式/报价合同、单一新请求契约 | 第 3.2 节中影响首批型号的未知项有负责人和明确结果；不能以推测开放 |
| B：内部贯通 | 音频上传探测、有序引用、组合校验、适配器、报价/幂等、新格式样片 | 接口和媒体针对性测试通过；字段不得遗漏，费用路径不变形 |
| C：完整产品 | 完整 Web 生成页、混合素材区、声音语义、模型切换保护、逐文件错误、六语种、可访问性 | 新流程创作、上传恢复、报价和受理状态可端到端演示；真实上游验证后才可称完整 |
| D：受控开放 | 管理员验证、已授权范围内放量、监测与关闭入口 | 新流程、存量数据完整性、在途任务处理、计费和结果归档均有证据 |

可以单独提前修正当前视频参考模式的错误标签，但该修正不算本需求完成。这里不承诺无依据的工期；A 阶段结束后才能根据外置适配器和协议差异估算实施排期。

验收矩阵：

| 类别 | 必须覆盖 |
| --- | --- |
| 正常输入 | 单图、多图、视频、图+视频、图+音频、视频+音频、三类组合；对每个精确型号，支持矩阵内组合应成功，矩阵外组合应明确拒绝并引导调整，不要求所有型号支持全部组合 |
| 数量与边界 | 各类型与合计上限前/等/超过；2 秒、15 秒、15.01 秒；严格字节大小边界、尺寸与帧率边界 |
| 错误组合 | 音频单独输入；删除最后一份视觉素材；帧控制与参考素材混用；声音开关不兼容 |
| 素材安全 | 伪造扩展名/MIME、损坏文件、超大解码内容、越权资产、已删除/未 ready、签名过期/上游抓取失败 |
| 上传恢复 | 部分失败保留成功项；断网；刷新；重复完成回调；校验较慢；替换失败；上传中换模型 |
| 请求一致性 | 换序/替换/排除/换型号使旧报价无效；签名刷新不改变语义；同键不同请求拒绝；同键重试不重复扣费 |
| 用户数据 | 调整模型/高级参考方式保留统一表单草稿；新格式样片恢复类型/顺序正确；旧样片/草稿不自动重放；已有作品、任务、素材关联与账目不被切换删除 |
| 新契约与切换 | 页面/服务端/适配器使用同一新契约；旧格式请求在预扣和创建任务前拒绝；不支持的渠道不会收到请求或漏字段；已经受理的任务继续处理、归档与结算 |
| 展示 | 320px/390px/桌面；浅深主题；长文件名、六语种、键盘/读屏、200% 缩放；媒体互斥播放 |
| 真实验收 | 上游收到完整顺序和素材类型；公开费用与实际型号一致；成功结果归档；失败按既有计费契约处理 |

技术负责人负责契约/适配器/费用正确性；前端与设计负责交互/可访问性；QA 负责矩阵和回归证据；产品负责范围、能力文案与上线门槛。角色表示职责分工，不代表已指定真实人员。

## 12. 如何判断上线有效

按模型及素材组合观察：上传完成率、校验失败分类、获取报价成功率、受理成功率、生成成功率、上传到受理耗时和实际费用分布。音频采用率用于判断功能使用情况，不凭它单独证明价值。

发布前建立基线，首版不编造提升百分比或任意错误率阈值。素材被静默丢弃、费用与实际型号不符、越权访问、重复收费属于立即关闭新增入口的问题；供应商普通内容拒绝与本站回归需区分归因。

日志只记录必要的数量、类型、时长档位、错误码、契约/模型版本与任务关联；不把签名 URL、音频内容或用户提示词写入新增产品分析字段。
