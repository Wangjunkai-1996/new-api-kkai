# KKAI 代理品牌站与分润系统产品需求文档

状态：产品规则冻结 1.0；本地实现，待试点上线验收
日期：2026-10-19
首期范围：单代理试运行

## 1. 目标与结论

KKAI 在现有 NewAPI 应用上增加代理品牌站能力。每个代理获得一个二级子域名，在自己的品牌下服务客户；客户充值和模型调用仍由 KKAI 统一承接，代理只负责选择可售模型、设置销售倍率、查看客户与收益并申请提现。

首期采用一套中心 NewAPI 应用、共享数据库和多租户逻辑隔离，不为每个代理部署独立 NewAPI 实例、数据库或渠道。

所有上游渠道和供货模型由 KKAI 管理。代理不能添加外部渠道，也不能接触 KKAI 向上游渠道的采购成本；代理可以看到 KKAI 对该代理的结算供货价和供货倍率。

## 2. 用户角色

### 2.1 KKAI 管理员

- 审核代理申请、创建和暂停代理站。
- 管理根域名、二级域名、HTTPS、可售模型/分组和 KKAI 供货成本。
- 管理代理品牌配置、风险控制、收益冻结和提现审核。
- 保留对代理站的最终管理权，可在低于成本、违规品牌、异常提现或其他风险情况下调整价格、暂停功能或冻结收益。

### 2.2 代理

代理使用原有 KKAI 账号申请代理资格。一个账号首期只能拥有一个代理站。审核通过后，该账号增加代理身份，不创建第二套登录账号。

代理可以：

- 从 KKAI 可售清单中选择展示的模型/分组。
- 查看 KKAI 给自己的供货成本和供货倍率。
- 为开放分组设置销售倍率。
- 修改站名、Logo、联系方式、公告和模板化首页介绍。
- 查看自己租户的客户概况、余额、消费汇总和逐笔收益明细。
- 查看预估收益、待结算收益、可提现收益和累计收益。
- 提交提现申请。

代理不能：

- 创建 KKAI 未开放的模型、分组或渠道。
- 配置外部渠道。
- 修改客户密码、余额、状态或 API 密钥。
- 查看客户密码、完整联系方式、支付资料或 API 密钥。
- 提供客户自助退款能力。
- 使用代理账号同时作为该代理站客户；测试必须使用独立客户账号。
- 开通第二个代理站。

### 2.3 客户

- 从代理二级域名自主注册。
- 注册后自动归属该代理租户，并进入代理设置的默认销售分组。
- 只能看到代理选中的模型/分组和代理销售价格。
- 使用充值余额进行 API 按量消费。
- 查看自己的余额、API 密钥、调用记录和价格信息。
- API 密钥、余额、调用记录和价格只对所属代理租户生效。

## 3. 申请、域名与站点生命周期

1. 用户注册并登录 KKAI 主站。
2. 用户提交代理申请，包括期望站名、联系方式和期望二级域名前缀（选填）。
3. KKAI 审核申请，可通过或驳回并记录原因。
4. 审核通过后，KKAI 配置可售模型/分组和域名。
5. KKAI 为代理分配一个二级子域名，例如 `kimi.example.com`。
6. KKAI 统一管理 DNS、HTTPS 证书、域名续费和域名回收。
7. 二级域名开通后默认不更换；特殊情况由 KKAI 处理。
8. 代理和客户都从该二级域名登录，但根据账号角色进入不同界面。
9. 网页控制台和 API 调用均使用该二级域名。

首期只开通一家代理站进行完整试运行。

## 4. 品牌与内容

代理可以在模板允许的字段内自行维护：

- 站点显示名称。
- Logo。
- 联系方式。
- 公告。
- 首页介绍内容。

保存后立即生效。Logo 仅支持 JPEG/PNG/WebP，最大 2MB、最大 1024×1024；首期不开放任意 HTML/CSS/脚本。

代理品牌作为运营品牌展示，但项目要求保留必要的 New API / QuantumNous 归属与项目身份信息。

## 5. 模型广场与价格

代理站保留现有模型广场形态，但内容和价格按租户计算：

- 代理从 KKAI 可售模型/分组清单中选择展示内容。
- 租户目录以销售分组为边界，并保存唯一默认销售分组；首期客户只使用该默认分组及其模型白名单。
- 如果同一模型出现在多个分组，系统必须保存唯一映射或明确优先级，不能让 Token、自动分组或重试绕过代理售价。
- 客户只看到代理选择的内容。
- 代理看到 KKAI 供货成本和供货倍率。
- 客户看到代理设置后的销售价格。
- 代理销售倍率是相对于共同基础价格的绝对倍率，不自动叠加供货倍率。
- 代理可以独立设置每个开放分组的销售倍率。
- 保存倍率后，新请求立即使用新价格。
- 已受理或进行中的请求继续使用请求开始时锁定的价格。
- 供货成本上涨导致现有销售倍率低于最低可售价时，系统自动将新请求价格调整到最低可售价。
- 系统不得允许代理以低于最低可售价的价格销售。
- 价格历史必须可追溯，历史账单不能因后续调价而重算。

最低可售价必须覆盖 KKAI 供货结算成本和 1.6% 支付手续费。整数分底价为 `ceil(supply_minor × 125 / 123)`；销售倍率底线为供货倍率除以 `0.984`。请求报价锁定实际生效倍率，供货涨价自动保底只影响新请求。微额消费按实付充值批次累计分摊，精确结余跨请求保留，避免每个微额请求分别取整造成虚增收益。

## 6. 充值、消费与收益

### 6.1 资金归属

- 客户充值继续使用 KKAI 现有支付渠道，资金由 KKAI 统一收取。
- 统一按人民币结算，内部以人民币最小单位记账。
- 客户充值余额属于客户预付款，不在充值时直接形成代理收益。
- 代理普通用户余额和代理收益必须使用独立账本，不能互相抵扣或转移。

### 6.2 收益结算

代理收益按客户实际消费产生：

- 客户实际消费后，按请求开始时锁定的租户、客户、销售倍率版本、KKAI 供货价版本、币种和舍入规则计算。
- 结算结果先进入“待结算收益”。
- 结算满 24 小时后进入“可提现收益”。
- 退款、冲正、拒付或异常消费需要生成关联的反向流水。
- 结算流程必须幂等，不能因重复回调或重复任务重复增加收益。
- 部分输出已产生时按上游确认用量结算；最终用量不明时保留预扣并阻止继续消费，由 KKAI 核对证据后处理，不能当作免费失败请求。

代理后台至少展示：

- 预估收益：按客户剩余付费余额和当前价格估算，不能提现。
- 待结算收益：已产生但未满 24 小时的收益。
- 可提现收益：已满 24 小时且未被冻结或提现的收益。
- 累计收益：历史已确认产生的收益，包括已经提现的部分。

代理可按客户、日期、模型/分组查看逐笔明细，包括消费金额、KKAI 供货成本、销售金额、支付手续费和最终收益；不展示请求内容、密钥等隐私数据。

### 6.3 手续费

- 正常充值对应的 1.6% 支付手续费由代理承担，并纳入收益和最低售价计算。
- 客户未消费余额申请退款时，如果支付渠道不退手续费，实际不退部分从退款金额中扣除。
- 提现产生的实际转账手续费由代理承担，从提现金额中扣除；没有实际手续费时不扣。

### 6.4 首期关闭的资金功能

代理站首期只支持“真实支付充值 + API 按量消费”，关闭：

- 邀请奖励。
- 赠送额度。
- 兑换码充值。
- 订阅套餐和会员利润分成。
- 代理手动加余额或补单。

首期只对普通文本/兼容 API 按量计费路径产生代理收益；图片、视频、异步任务和其他尚未完成现金映射的计费模式不进入代理可售目录。

## 7. 退款、提现与停站

### 7.1 退款

- 代理站不提供客户自助退款、客服或工单系统。
- 客户退款沿用现有外部联系方式和人工处理流程。
- 退款规则只作为 KKAI 内部账务处理规则，需同步撤销未结算或预估收益。

### 7.2 提现

- 最低提现金额为 100 元。
- 只支持支付宝。
- 代理提交申请后冻结申请金额。
- KKAI 人工审核、人工转账并登记结果。
- 驳回申请释放冻结金额；确认打款后核销冻结金额。
- 付款结果未知时必须先查单，不能盲目重复打款。

### 7.3 代理站暂停或终止

- 停止新注册、充值和 API 消费。
- 客户余额由 KKAI 人工按规则退款或迁移处理。
- 代理待结算和异常收益先冻结核对。
- 不自动把代理客户迁移到 KKAI 主站。
- 客户资产处理必须记录处理状态和操作流水。

## 8. 数据隔离与安全边界

- 所有客户共用一套用户表，通过 `tenant_id` 做租户隔离。
- 账号、余额、API 密钥、调用记录、价格和收益均按租户隔离。
- 租户归属必须由认证账号/API 密钥确定，不能只信任请求 Host 或客户端传入的代理 ID。
- Host 负责选择品牌和入口，不能改变已认证账号的计费归属。
- 代理后台所有查询和写入都必须自动限定为当前代理租户。
- 代理客户的自动分组、模型白名单和重试流程不能绕过租户可售清单。
- 注册必须沿用 KKAI 现有验证码、频率限制和必要的邮箱验证。
- 客户用户名和规范化 email 在同一代理站内唯一；不同代理站允许重复。
- 已解冻或已提现收益发生拒付/退款时，追加代理债务并冻结后续提现和必要业务，不能将负数截为零。

## 9. 明确不做的内容

- 每个代理独立部署一套 NewAPI。
- 每个代理独立数据库、独立渠道或独立收款账户。
- 代理接入非 KKAI 渠道。
- 代理创建任意模型/分组。
- 完整网页建站系统。
- 代理站内置客服、工单或退款页面。
- 图片工作室、视频工作室等首期非必要能力。
- 多品牌站、多级代理和跨站账号迁移。

## 10. 首期验收目标

首个代理站必须完整跑通以下链路：

1. 申请、审核和二级域名开通。
2. 品牌名称、Logo、联系方式和公告展示。
3. 客户注册、充值、模型广场和 API 调用。
4. 代理选择模型/分组并修改销售倍率。
5. 供货价格上涨后的最低价保护。
6. 客户消费、预估收益、逐笔结算和 24 小时解冻。
7. 退款/冲正对收益的反向处理。
8. 提现冻结、人工审核、打款登记和失败释放。
9. 跨租户访问、跨站 API 密钥和权限越界验证。
10. 代理站暂停后的客户资产保护。

## 11. 本地实现与上线边界

本地代码已实现申请、品牌、目录、定价、客户隔离、付费批次、结算、24 小时解冻、人工提现及平台冲正/用量核对。详细代码边界和定向检查见[详细设计](./reseller-multitenant-detailed-design.md)及[实现与验收记录](./reseller-multitenant-implementation.md)。

上线前仍须独立验收 wildcard DNS/TLS/Edge、真实支付回调、双 Host 浏览器与 Cookie、首家代理的完整链路。当前没有生产部署或生产数据库变更。

数据库 v12 是显式维护迁移。开关关闭只关闭代理入口，不会恢复旧的全局用户名唯一语义；迁移后不能直接切回 v11 旧二进制。须在上线前完成旧实例排空、备份恢复与 v12 兼容回滚版本准备。
