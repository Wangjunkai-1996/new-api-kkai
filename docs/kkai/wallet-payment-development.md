# 钱包充值订单开发总纲

**2026-10-24 交互修订：** 主动确认结束成功后，在同一次用户操作内串行精确 acknowledge，成功直接回充值页，无需再点返回；失败保留 ended 与返回重试。自动超时仍保留超时提示和“返回充值”按钮。自动确认只作用于原身份、flow/revision 与原订单均仍一致的 ended 结果，实际收款、身份变化、另一当前流程和迟到旧响应不能自动清理。以下条款按此区分主动结束与自动超时。

## 1. 开发依据与文档分工

| [后端开发规格](./wallet-payment-backend-dev-spec.md) | 唯一 API／DTO 契约、数据权威、幂等与并发、各渠道接入、账务、任务、兼容和迁移设计 |
| [前端开发规格](./wallet-payment-frontend-dev-spec.md) | 现有组件改造、互斥页面阶段、支付新标签页、记录与管理员、响应式／无障碍／i18n、文件计划 |

接口路径、枚举、字段与错误码只在后端规格定义，前端和验收引用同一契约。实施中改变接口时必须同时更新引用与契约测试，不能各维护一套近似协议。技术实现若发现产品要求与渠道事实冲突，先标记受影响渠道和缺失证据，保持未验证能力关闭；不能擅自改变已确认的 UI 或用假成功补齐按钮。

实现前以这四份开发文档完成一次契约走查，逐项确认请求、响应、状态、权限和故障分支；前后端使用同一组契约夹具。任何任务拆分不得使“暂未接接口”变成永久遗漏，也不得以渠道能力不足替代受限状态的 UI 交付。

## 2. 已确认且不可遗漏的主流程

1. 进入钱包先恢复服务端当前流程；恢复未完成、失败或断网时，不提前显示可购买表单，也不把查询失败解释为没有订单。
2. 空闲时按原租户和配置展示既有钱包功能。提交下单后立即进入创建中；创建、当前订单、处理中、结果与空闲互斥。订单阶段主区只显示当前订单详情，不额外堆余额卡、在线充值、Creem 产品购买、订阅购买或兑换入口。
3. 先可靠保存订单、冻结金额和原支付会话，再在外部新标签页打开支付。钱包始终保留当前订单；关闭支付标签页不是取消，也不会清掉订单。被浏览器拦截时，当前详情仍提供手动打开原支付页面。
4. 有效待付款页直接提供“重新打开支付页面”“结束本次充值”“取消订单”（按真实能力）和“刷新结果”。重新打开只能使用原单原会话，不新建、不重新报价、不延长有效期。详情中同时显示币种金额、充值额度、付款方式、完整订单号、创建时间与可靠截止时间。
5. 渠道取消在当前订单内确认，取得可靠证据后才显示取消结果；“结束本次充值”独立结束本站操作，不宣称渠道已关闭。不支持在线取消仍提供本地结束及期限内核实／客服路径。
6. 本站期限统一为创建后 30 分钟，取已知更早渠道截止；未确认收款时到期保留“本次充值已超时”和 **“返回充值”**；主动 end 成功同次串行精确 acknowledge 后直接回充值，无需额外点击，失败保留 ended 与返回重试。均不等待渠道关单。说明原支付页可能仍可付款、已付款继续核实，提醒关闭旧页及避免重复付款；自动超时不跳回表单，不在结果下同时放表单。
7. 主动 end 成功在原用户操作内串行精确确认；超时、已到账、可靠取消／过期或可靠失败保留结果，由用户点击“返回充值”。请求经服务端确认后才结束这一当前流程并恢复表单；该请求不是取消、退款、删除或创建新单。请求失败保留结果和重试按钮。
8. 未结束且未到期的结果未知、关单中、支付确认中不可绕过当前流程，但无已确认收款时允许本地结束／到期并精确返回。已确认收款／credit_review 继续核实，不能被超时／取消覆盖。
9. 历史记录是二级入口；查看历史不得替换当前流程。旧 pending 依相同期限投影为超时废单并保留历史，移出未完成计数，不提供续付、恢复、取消、人工核实或补单；已确认收款继续核实，不把所有旧单自动绑定为当前。
10. 回调或认证查单形成可信收款后幂等入账；迟到款、重复款、金额币种／商户差异、入账受限都须保留资金事实和可处理责任。管理员核实不等于无凭据补额度。

合法空闲但在线充值不可用，与当前流程恢复失败是两种状态。前者保留可读钱包及独立配置允许的兑换／订阅能力，并解释购买限制；后者不得凭失败响应解锁表单。可变税费或支付页合法优惠必须明确金额口径，不能把尚未确定的数值标作最终应付。

## 3. 范围与现有功能保护

本期修改钱包余额充值（`TopUp`）生命周期，以及本人／管理员订单查询与核实；不把订阅订单、会员购买、退款或通用支付重试平台并入新模型。现有共享 webhook 的订阅／会员分流必须保持正确，不能因为修钱包迟到款而改变其他业务的记账语义。

| 对象 | 本期要求 |
| --- | --- |
| `web/default` 钱包 | 完成全部现行 PRD 与 UI；复用既有页面壳、Base UI 组件和主题 |
| 空闲钱包既有模块 | 保留余额、会员摘要、兑换码、外部购买链接、Creem 产品、订阅等既有能力及租户／配置约束；原型没画出的模块不因此删除 |
| 订单阶段 | 隐藏非当前流程的独立卡和购买入口，返回空闲后恢复；阶段判断先于挂载，防止隐藏 DOM 仍触发购买或弹窗 |
| `web/classic` 与旧浏览器 | 不机械移植 default 整套视觉；后端所有旧创建入口仍必须遵循统一门禁、幂等与错误兼容，不能形成绕过。发布兼容验收按两端实际支持状态执行 |
| 平台／租户 | 本人和租户隔离贯穿查询、续付、取消、返回和创建；平台管理员范围、租户管理员范围依既有权限，不能由请求参数扩大 |
| 发票、返佣、租户现金批次、信用纪元 | 复用现有账务事务和 outbox，不引入第二套发放额度路径；与并行发票工作核对接口和唯一性 |
| 历史订单 | 保留超时废单只读历史；人工批次报告、选单与执行前均排除废单，旧补单 API 同样拒绝。可操作范围的批量核实须独立授权，不能随发布扫旧单；可信晚款继续处理 |

本地证据：`Wallet` 当前挂载 `WalletStatsCard`、平台会员摘要、`RechargeFormCard` 和平台订阅卡；创建支付分散在普通／Stripe／Creem／Waffo／Pancake hooks；`submitPaymentForm` 存在 Safari 同标签分支；`getStatusConfig` 对未知状态回退 Pending；旧历史普通查询存在 30 天窗口。这些都是改造点，不能只新增独立详情组件而保留原旁路。

## 4. 交付拆分与依赖

以下均为待实施任务。一个任务完成必须同时有代码、相应行为验证及审查记录；文档或模拟通过不计为功能完成。

| 工作项 | 负责人职责 | 实施内容与产物 | 进入下一项的条件 |
| --- | --- | --- | --- |
| D01 渠道契约与范围确认 | 后端／支付接入 | 对实际易支付服务商及每个拟启用渠道核实原会话恢复、查单、关单、期限、回调与幂等语义；形成脱敏证据 | 按渠道区分已验证与未支持；未验证能力不能默认为支持 |
| D02 API 与数据契约 | 后端主责，前端／QA 会审 | 固化 DTO／状态／动作／错误、服务端流程权威、创建和返回的竞争规则、增量 schema 与旧协议兼容 | 前后端可基于同一夹具开发；不存在“前端隐藏即解锁”或双份金额真相 |
| D03 可信收款底座 | 后端／资金安全 | 持久可信收据、迟到款、并发终态保护、幂等入账、异常处理责任、修正各 webhook 状态分流 | 关单与成功竞争、重复／第二笔款、账务异常下证据不丢失；自动关闭仍未启用 |
| D04 当前流程与新单会话 | 后端／前端 | 统一所有创建入口；先持久化再外跳；恢复、报价有效性、创建不确定恢复、服务端返回充值 | 重复提交／跨设备不产生第二个可支付会话，本地结束／超时或可靠结果经精确确认后返回 |
| D05 钱包主流程 | 前端／UI 审查 | 互斥阶段、完整订单详情、直接重开／结束／按能力取消、超时结果主按钮、恢复与错误状态、原有空闲功能恢复 | 按 UI 对照逐态核验；不会一边显示订单一边继续购买 |
| D06 查询、取消与到期任务 | 后端／渠道接入 | 本站期限与本地结束、按能力查单／关单、独立关闭证据、有界自动核实、租约和观测；前端同步结果 | 新渠道模拟及受影响真实路径验收，已付款不被关闭、后台不依赖网页 |
| D07 历史与管理员 | 前后端／QA | 六筛选、全龄本人精确定位、分页与计数、权限分离、证据核实入账、授权历史批次的报告／启动／暂停续跑 | 废单只读保留且禁止人工补单／核实，管理员无凭据不能走支付成功；暂停历史批次不影响新单与收据处理 |
| D08 兼容与交付审查 | 技术负责人／QA | 旧客户端、旧创建 API、共享回调、三数据库迁移、当前与回退版本、全部启用语言和 UI 回归 | 验收规格各项有结果和证据；未通过事项明确阻止相应能力启用 |

D03 与 D04 的契约定稿后，前端可以用固定契约夹具并行实施 D05／D07；模拟接口只用于测试，不携带进正式支付路径。D06 自动取消／到期的启用依赖 D03 资金底座、D04 流程约束和 D08 回退兼容，不以“按钮已经能点”为启用条件。

## 5. 代码质量与审查门禁

| 质量项 | 必须满足的要求 | 不接受的实现 |
| --- | --- | --- |
| 范围与复用 | 沿用 Router → Controller → Service → Model；复用任务、组件、统一请求实例和账务事务；新增函数／表对应稳定业务责任 | 每渠道一套状态机、通用支付平台重构、新依赖或全局 store 只为本页便利 |
| 服务端权威 | 所有变更重新鉴权与校验阶段；跨实例靠数据库约束、行锁／条件更新 | 仅靠进程锁、localStorage 或禁用按钮防重复 |
| 数据与金额 | 冻结报价、币种、最小货币单位与额度分离；整数边界、合法优惠及账务容量重复校验 | 以浮点展示金额结算、当前汇率重算旧单、JS 精度丢失、溢出发负额度 |
| 并发与事务 | 网络调用不长时间占数据库事务；保存 intent／claim，外呼后重锁检查版本与状态 | 外呼成功直接覆盖整行、关单失败抹掉收款、租约丢失后继续写入 |
| 数据库／JSON | 支持 SQLite／MySQL／PostgreSQL；用 `lockForUpdate(tx)`；使用 `common` JSON wrapper | 靠 SQLite 测试代替数据库锁证明、业务代码直接 marshal、生产启动顺带 AutoMigrate |
| 前端状态 | 清楚的阶段与 discriminated DTO；统一 query/mutation 生命周期；抑制并发，旧结果不覆盖新流程 | 散落布尔量拼状态、`any`、未知回退 Pending、乐观显示已取消或到账 |
| UI 一致性 | 布局、按钮层级、文案、字段及交互按前端规格对照；浅深色、窄屏、键盘、Safari 验收 | 订单卡叠充值表单、缺少返回主按钮、自动跳回表单、记录替换未完成当前单 |
| 安全与诊断 | 支付 token 仅按本人授权恢复；列表不泄露 checkout 数据；日志、客服和监测脱敏 | 日志记录原始 webhook／签名／支付 URL、任意跳转、未经校验的 HTML 表单注入 |
| 国际化 | 采用项目现有英文源字符串 key、各组件 `t()`；按运行配置覆盖全部启用语言 | 中文硬编码、状态常量直接当文案、只检查 en／zh 就宣称全部语言通过 |
| 测试价值 | 验证用户行为、API 契约、权限、资金不变量和明确回归；确定性输入与可解释断言 | 凑覆盖率、sleep／随机压力循环、只测 helper 内部结构、把原型状态当渠道事实 |

每次代码评审附本任务文件清单、对应 PRD 编号、影响到的支付渠道／旧客户端、测试结果和 UI 对照图。发现高风险资金或权限问题必须先修；一般重构不得趁本期扩展至无关账务模块。已有版权与项目身份信息按仓库规则保留。

## 6. UI 对齐的检查方式

前端开发从现有应用壳构建，不把原型 HTML／脚本直接搬进 React。原型中的演示场景选择、模拟支付窗、示例比例和数据不属于产品功能。具体像素、图标与圆角沿现有组件实现，以下行为和信息层级不得变化：

| 页面检查点 | 必须看到 | 必须不存在 |
| --- | --- | --- |
| 空闲 | 按既有权限可用的钱包与充值功能 | 误绑定的历史待核实当前卡 |
| 恢复／创建 | 明确进度、可恢复错误或核实说明 | 可重复下单入口和先闪一下的充值表单 |
| 待付款 | 单一订单详情、原单重开／结束本次充值／按能力取消／刷新 | 独立余额、充值或其他购买卡片 |
| 取消确认 | 当前卡内说明、暂不取消／确认取消 | 第二层套娃弹窗或将取消等同退款 |
| 未结束且未到期的处理中／待核实 | 原详情与准确进度、按能力结束／刷新／客服；已确认收款继续核实 | 付款按钮、直接购买捷径、虚假成功 |
| 本地超时／结束 | 超时或未确认 ended 保留准确说明、显眼返回按钮和详情；主动 end 成功串行精确确认后直接回表单 | 未获渠道证据却宣称已关单、超时自动回表单、未经精确确认本地解锁、续付／人工核实／补单、结果下方的表单 |
| 已到账／其他可靠结果 | 对应结果、查看记录、返回充值 | 无提示消失、自动再创建订单 |
| 二级记录／管理员 | 六筛选、精确查询、可操作分页、相应权限动作 | checkout token、无证据支付成功、覆盖当前流程的历史切换 |

对照图至少包含内容宽度 320／375／736／1024px 的关键页面、浅深色以及中文和较长翻译文案。结果页“返回充值”在手机上必须直接可见、可键盘操作；不能只藏在记录菜单。UI 偏差若影响信息或动作，先修正再判完成，不能用“组件库不同”作豁免。

from pathlib import Path
import re
import subprocess

files = sorted(Path('docs/kkai').glob('wallet-payment-*.md'))
assert len(files) == 7

    for target in re.findall(r'!?\[[^\]]*\]\(([^\n]+?)\)', body):
        target = target.strip('<>').split('#', 1)[0]
        if not target or re.match(r'^[a-z][a-z0-9+.-]*:', target):
            continue
        target = re.sub(r':\d+$', '', target)
        destination = Path(target) if target.startswith('/') else path.parent / target
        assert destination.exists(), (path, target)
        link_count += 1
expected = {f'A{i:02}' for i in range(1, 33)}
for name in ('wallet-payment-lifecycle-prd.md', 'wallet-payment-acceptance-spec.md'):

    rows = re.findall(r'^\| (A\d{2}) \|', body, re.M)

print(f'PASS: {len(files)} documents, {link_count} local links, A01-A32=32/32')
