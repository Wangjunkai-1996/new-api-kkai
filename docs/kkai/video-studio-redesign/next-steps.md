# 视频工作室后续实施计划

2026-10-28。当前实现和本地验收见[实施记录](implementation-qa.md)。本计划在 KK 商城**确认完成生产发布**后启动；本文件不表示商城已上线，也不替代届时的现场检查。

## 启动条件

1. 从商城任务的最终交付记录确认生产发布、发布后状态与回滚门禁已完成，而非仅看到本地提交、构建或候选服务。商城仍有发布故障或未完成迁移时继续等待，不与其并行修改生产 checkout。
2. 保留当前隔离 worktree `/Users/tokk/.codex/worktrees/video-studio-v2/new-api-kkai` 的全部未提交代码与证据。启动时重新读取 NewAPI 发布入口和实际目标 checkout/infra 手册；只用当时的 Git 与现场状态，不复用本文的版本、控制器能力或槽位假设。

## 执行顺序

| 阶段 | 动作 | 完成条件 |
| --- | --- | --- |
| 1. 更新基线与审查 | 核对商城发布后的 `production/kkrich`、干净状态和前后端契约；三方比较当前隔离实现与最新基线。按 JSON 键合并七份 locale，保留商城翻译；保留商城的导航和生成路由。主分支已有设计文档，只带入新增实施记录、验收脚本及实现截图。对最终 diff 再做一次提交/媒体权限/删除/回退审查 | 没有覆盖商城代码、翻译或用户改动；最终文件清单和冲突处理可审查；发布范围确认为仅 default 前端，若发现后端/API 变化重新定范围 |
| 2. 整合后本地回归 | 在**整合结果**上运行受影响 Video Studio、共享媒体及图片消费者测试；前端类型检查、改动文件 lint/格式、七语言完整性、diff 检查。按设计稿复核暗色/浅色、桌面和 320/390px，检查真实视频、单编辑器、状态、作品库/任务和减少动效 | 所有相关检查通过；缺陷修复后仅重跑受影响范围；记录精确命令、退出码、截图和最终提交 ID。此前隔离版本的 251 项通过不能代替此阶段 |
| 3. 无付费真实联调 | 在合适的隔离测试环境和账号上读取真实权限、模型规格、报价、历史分页、任务详情及媒体签名；核对 Image Studio 共享媒体行为。用浏览器检验 1440/1024/768/390/320px、侧栏、键盘/焦点、200% 文字、长标签和对比度；可用时补 Safari/真机软键盘 | 权限、金额、查询与签名行为符合实际 API；无跨账号媒体暴露、错误空态、遮挡或不可达操作；保存脱敏网络和视觉证据。只读阶段不发起生成 POST |
| 4. 真实业务闭环 | 在有明确测试账号、费用范围和业务数据边界时，验证真实上传/分片恢复、一次付费生成、任务定位、归档播放、签名续期和账单。受控环境注入断网/未知回执、切账号和撤权场景 | 每次明确操作最多一笔生成请求；任务、作品、扣费与回执可对应；未知状态只读恢复，不自动重发；失败不推断退款。保留脱敏任务号、请求次数和账单证据。若真实付费/生产写入未获授权，标为待验，不用 fixture 冒充通过 |
| 5. 交付与发布 | 依据实际安装的控制器及前端 manifest 选择 format 2 或 legacy format 1 的**纯前端**流程；完成届时必需的构建、兼容性、激活、页面/API 验收及回退准备。format 2 不走后端 stage/canary/promote；format 1 保持精确后端配对 | 用户明确进入提交/发布阶段后执行；报告实际产物、版本、检查与回退状态。未获发布授权时止于可审查的整合和验收成果，不宣称上线 |

## 关键停止条件

- 商城尚未完成发布，或最新代码/生产 API 与当前 Video Studio 契约不一致。
- 付费 POST 可能被自动重试、认证刷新重放，或未决记录可能在回退后被旧前端忽略。存在待核实请求时不得靠清空本地记录回退。
- 真实服务显示权限/报价/账单不一致、跨账号可见私有媒体、无法确认任务与费用关系，或测试账号/费用边界不清楚。
- 发布前发现前后端联合变化、schema 变化、控制器能力不符或 runbook 门禁失败；重新选发布路径，不把纯前端流程硬套到新范围。

本计划沿用现有 React Query、Zustand、Base UI、签名媒体和上传协议；不为视觉重构新增依赖或扩展取消任务、退款、跨标签页原子互斥等无后端支持的能力。商城发布完成只触发重新核对，**不自动证明视频工作室已经验收或可上线**。
