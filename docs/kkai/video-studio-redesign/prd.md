# 视频工作室产品需求文档

版本：1.2（2026-10-28，纳入技术开发审查的契约及视觉一致性勘误）。产品方向：精致创作台；设计基线不等同用户已批准所有细节。

本文件是本轮设计的需求基线。上一轮[优化方案](../video-studio-redesign-proposal.md)记录讨论背景；发生冲突时以本文件修订版为准，视觉数值以最新[UI规范 v1.2](ui-spec.md)为准。当前交付已扩展至[开发文档](development.md)，仍不包含业务代码实施、付费生成或生产部署。模型、任务与金额在设计稿中使用明确标注的演示数据。

## 1. 目标、用户与范围

目标：让用户在同一创作上下文中完成配置、提交、等待和查看成果；视觉与图片工作室保持同一产品气质；保留视频工作室已有模型规格、素材、报价与任务安全边界。

面向两类已有控制台用户：已有提示词、需要连续调整的创作者，以及依靠样片寻找灵感的初次用户。此划分是产品假设，尚无访谈或埋点统计证明，不虚构效率提升百分比。

一期设计覆盖创作、作品库、任务三个用户页面、浅/深主题、移动端和关键异常。管理端模型/样片配置保持既有能力，本轮不重做管理端。工作室历史仅对应 `KKAIVideoGeneration`；全站 `/usage-logs/task` 的视频作品另含公共 API 视频任务，本轮不合并。

非目标：视频剪辑、取消上游任务、批量创作、素材管理中心、新模型接入、调整计费、数据库迁移、全历史全文搜索、未获接口支持的完整状态筛选、完整历史输入复刻。

## 3. 页面和信息架构

保留 `/video-studio/create`、`/video-studio/library`、`/video-studio/tasks` 及现有样片、任务深链接。顶部三个入口保持可发现。创作页为默认入口。

桌面：常态 400px、受限空间缩至 380px 的左侧创作卡，右侧弹性成果区。创作卡顺序为模型→可用模式→提示词→所需素材→常用输出参数→高级参数→费用→生成。右侧为当前任务/成果→适用动作→近期任务→灵感。

无作品时右侧采用紧凑引导与可套用样片，不放巨大黑框。有结果后突出当前成果。灵感首访可展开，提交后可收起，入口始终可见；用户主动展开后不得被后台刷新反复收起。

内容容器小于约 850px 时自然单栏，编辑器直接可见，结果在下，提供“查看结果 / 返回编辑”。真实断点由控制台侧栏占用后的容器决定。桌面/手机共用一个编辑器实例。

三个页面分工如下；返回创作页保留草稿，历史详情为只读，不隐式套用历史参数。

| 页面 | 主要职责 | 跨页动作 |
| --- | --- | --- |
| 创作 | 编辑、提交、当前成果与紧凑近期选择 | 更多作品进入作品库，完整状态进入任务页 |
| 作品库 | 视觉浏览、播放、下载、终态删除 | 保留全部/可播放服务端筛选，使用公共 Dialog 基座新增 Studio 只读详情内容；当前 Studio 为卡内播放，并无可直接复用的独立详情弹层 |
| 任务 | 时间、状态、公开失败原因、任务号 | ready 的“查看作品”进入作品库定位入口；不重复画廊和管理操作 |

成果区初始选择顺序：明确目标 → 当前会话仍有效的主动选择 → 首次成功列表的最新记录。加载用骨架；首次读取失败局部重试；只有成功返回空列表才显示首次引导。目标定位期间不以其他历史作品冒充目标。后台更新不改变用户选择；历史读取失败不阻断独立可用的创作表单。

## 5. 提交、恢复和状态规则

一次提交以用户、规范化请求内容和幂等身份界定。正常受理后结束该次未决保护，后续明确新提交使用新身份。网络结果不确定时不能因为刷新、改稿或重挂载误当作新请求。

当前代码的 idempotency ref/submissionLock 在组件内，不能宣称已跨刷新持久化。本期实施补足范围限定为：**跨刷新保留未决提醒＋已有任务号的只读查询/有限列表发现；恢复动作不产生生成请求。**

1. 在 POST 发出前持久化用户隔离的“提交中”记录，包含操作身份、请求指纹、可用任务号与时间，不保存密钥、媒体签名或二进制。持久化失败阻止该次发送并说明恢复记录无法保存。发送后立即刷新、关闭页面、断网、超时、无法解析响应、服务端 unknown，均将没有明确结果的操作视为待核实，不能当明确失败。
2. 未决记录独立于选中的成果与当前草稿；切模型、编辑、查看其他作品或新提交不得覆盖它。创作页持续显示紧凑提醒；有任务号可复制，无任务号说明无法精确定位。等价未决请求不得换新身份再次提交；改稿后改回仍受原保护。不同内容仅在用户明确点击后作为新操作；不宣称已实现跨标签页原子互斥。
3. 视频默认幂等窗口为首次服务端预留起 **24小时**（`service/idempotency.go`）；过期记录可能被删除并重建，图片专属延长不适用于视频。本地时间不能证明服务端记录仍有效；窗口届满或时间证据不可靠时，只保留待核实与只读任务入口，不能自动清除提醒或重放 POST。
4. `quote.request_hash` 是含过期时间的 **5分钟报价签名**，不是稳定请求指纹。请求指纹要体现原 token、有效 group、model、mode、prompt、parameters、素材及角色、sample；报价刷新不能生成新提交身份。只存摘要的最小记录无法重建原请求，“查状态”绝不调用 POST `/pg/videos`。原 token/group 失效时不自动换令牌补发。
5. 换账号隐藏旧用户未决记录并清理选择/媒体/私有缓存；迟到回执不能写入新用户上下文。未决记录生命周期依据明确受理/拒绝证据处理，不能仅因旧报价过期、草稿改变或列表暂未发现而结束保护。实施时需对完整指纹一致性和存储失败定向验收，设计稿不证明这些机制已实现。

6. generation 可能在上游提交前已经创建；未知上游结果在现有投影中可能表现为 processing 或 failed。因此“列表发现了同 task_id 的记录”只证明记录已存在，不单独证明提交正常受理，不自动解除 unknown 保护。明确有效的提交回执或同一目标已进入可证实上游成功的 archiving/ready 阶段，才可作为受理/完成证据；其他明确拒绝证据按[开发契约](api-and-state-contract.md)逐项判定。不依据提示词相似度、创建时间或费用猜测关联。

终态删除是本期 UI 产品限制；当前后端删除服务尚未强制校验状态，不将其写成已有服务端保证。本期不增加后端接口；如需服务端强制限制，应独立补充契约与验证。

任务定位只复用列表发现与既有活跃任务补查。未被发现且已移出最新页的任务可能不能精确定位：保留回执号与任务历史入口，不无限扫描所有历史。按 task_id 精确查询作为明确的后续只读接口补足，不作为当前已有能力。

刷新失败/断网保留草稿和已展示内容，但标注“状态暂未更新”，提供局部重试；恢复连接后重新查询，不能根据轮询中断推断完成、失败或退款。

失败处理区分：提交明确拒绝、生成失败、归档/媒体准备失败、临时读取失败、未知结果。只显示后端明确的公开原因；未提供可区分字段时采用“暂时无法提供结果，请查看任务状态”，不推导已退款。归档失败不能让“刷新”再次付费生成。

| 状态 | 主动作 | 费用/素材约束 |
| --- | --- | --- |
| 草稿有效、报价ready | 生成视频 | 明确付费动作，显示预计费用 |
| 素材未ready或报价无效 | 补充/恢复素材或刷新报价 | 生成按钮禁用并解释原因 |
| 提交中 | 等待提交结果 | 禁重复提交 |
| 定位中 / 定位超时 | 查状态 / 查看任务 | 不产生新提交 |
| 未知结果 | 核实原任务 | 不解锁同次请求重复付费 |
| 排队 / 生成 / 归档 | 查看状态，可编辑下一次输入 | 当前任务不可取消/删除，归档不等于ready |
| ready | 播放 / 下载 | 短期签名、完整画面 |
| failed | 查看原因 / 状态，终态可删除 | 不默认已退款，不默认可重试归档 |

## 6. 视觉规范与交互设计交付

浅色采用图片工作室冷灰、白色与靛蓝体系；暗色采用第二轮“精致创作台”分层石墨黑。色值、字体、间距、素材和动效的唯一视觉基准为[UI规范 v1.2](ui-spec.md)及对应暗色 V2 设计稿，第一轮尺寸不再作为开发要求。

核心卡12px圆角、桌面28px页面留白、22px栏间距、约20px卡内边距；页标题桌面26px/手机23px、正文14px、手机编辑文字16px。主操作46px高，触屏操作≥44px。主色集中在主要动作和选中态，画面优先，保持细边框、轻阴影及清晰分组。原型默认暗色仅为审查偏好，正式产品跟随既有应用主题设置，不另存一套主题或强制全站暗色。

设计稿包含一个推荐方向和下列审查场景，供用户直接切换。审查控件置于产品画面之外，明确“交互设计演示，未连接生成服务”。演示可用本仓库已有设计封面，不能把示例媒体当生产默认结果，不发起付费请求。
