# 视频工作室视觉与交互设计规范

版本：1.2 · 2026-10-28。依据：[PRD](./prd.md)（当前 v1.2 技术勘误版，未改变本规范视觉数值）。角色视角：视觉艺术指导、交互设计、无障碍与体验验收。第二轮暗色视觉方向为开发文档基线，不等同用户已批准所有细节。

本规范约束本轮设计稿及后续实现的视觉目标，不表示业务功能已实现或用户已批准。参考色值已核对 [图片工作室样式](../../../web/default/src/styles/image-create.css)；继承其有效设计变量，不复制历史叠加样式。演示数据、样例封面与审查控件属于原型，不能进入生产默认内容。

## 1. 推荐方向与视觉理由

采用“精致创作台”：浅色延续冷灰页面与白色编辑卡；第二轮暗色稿使用中性墨色页面和稍亮的工具表面，靛蓝集中于生成按钮、选中项和焦点，极少量暖金只提示报价与画面主题。结果画面是右侧最大视觉元素。表单以留白组织，不为每个字段增加一层卡片。

这样安排的原因是：输入与结果持续共存，符合视频的长等待流程；复用图片工作室的色彩、圆角与控件密度，减少两个创作工具之间的切换成本；画面本身提供色彩和质感，界面不用装饰渐变、巨大口号或泛滥徽标争夺注意力。

信息优先级固定为：当前操作和结果 → 与操作直接相关的状态/费用 → 最近作品 → 灵感。未决提交是安全提示，独立于当前成果持续可见，不因用户换作品而消失。

正文和有效控件文字对比度至少 4.5:1，必要控件轮廓/焦点指示至少 3:1；实际组合需按渲染背景验收。禁用按钮之外，禁用原因保持完整文字对比度。

## 4. 页面构图与控件层级

### 创作页

顶部为页名、简短说明和“创作 / 作品库 / 任务”导航。三个入口保持可发现；手机可自然换行，不能把全部导航藏入无标签图标。

左侧只有一张编辑卡，顺序固定：模型 → 当前可用模式 → 提示词 → 模式所需素材 → 常用参数 → 高级参数 → 费用 → 生成。只有一个有效模式时展示静态说明，不伪造可切换选项。高级字段默认收起，必填/错误字段存在时自动展开。

费用区与生成按钮同组，报价数值和状态单独一行。模型/参数变化后，旧报价失效清晰可见。生成按钮被禁用时，旁边给出最直接的原因及可执行恢复动作，不能只降低透明度。

右侧按当前成果、近期作品、灵感排列。成果标题与状态在播放器之外，播放控制不遮住主要状态。历史详情只读；选择缩略图只更换成果，不重写草稿。近期列表不展示无依据的“全部 N 项”统计。

首次无作品时采用约 180–240px 的紧凑引导，配合样片入口；不出现巨大的空播放器。生成到完成阶段保留稳定的成果卡边界。已有作品作为等待背景时需明确标注“已有作品”，新任务阶段在独立区域表达。

### 作品库

先展示页标题与“全部 / 可播放”，再按已加载记录日期分组。卡片优先封面、两行以内提示词摘要及必要状态；更多信息进入详情弹层。缩略封面可裁切，详情播放完整画面。

新内容提示占紧凑一行，由用户刷新置顶；后台插入不打断正在浏览的位置。加载更多保持当前滚动位置，失败在分页尾部重试，不清空已有作品。

终态记录的删除使用低强调度危险动作；点击后弹层说明删除对象及不可撤销影响，不称为“取消生成”。确认后失败保留原项，成功清除当前选择并回到可达的相邻项或列表。

### 任务页

采用列表而非第二套画廊。主要列为状态、创建时间、模型/摘要及动作；任务号和公开失败说明可展开或放次级行。`ready` 才有“查看作品”；未知和定位超时的动作是查状态/任务入口，不使用“重新生成”。窄屏改为单列信息块，保留相同阅读顺序。

## 5. 媒体与素材

主播放器内的媒体使用 `contain`。16:9、9:16、1:1 均保留完整画面，不拉伸、不把竖屏裁成横屏。播放器区域使用 `stage` 自然留边；缩略封面才可使用 `cover`。

第二轮原型的桌面成果舞台采用约 1.9:1 的稳定区域，随容器宽度适配；手机默认 16:9，竖屏媒体在完整画面内居中留边。后续真实播放器可依据媒体元信息提高竖屏舞台，但须单独验收视口高度、操作可达和稳定性，不能让单个视频吞掉全部操作。未有可信媒体比例时使用默认稳定容器，取得元信息后避免反复变高。

原生或等效可达的播放、暂停、音量、时间进度、全屏保留。任一时刻最多一个活动媒体：主成果、灵感预览、作品详情相互暂停；关闭弹层/离页停止播放。只有图片封面的原型不能用计时器伪装视频在播放。

素材槽用真实角色名。首尾帧从左到右标记“首帧 / 尾帧”，手机自上而下，角色不依赖图标位置猜测。上传中、检查中、就绪、失败用同一槽位内的状态切换；恢复/重试在该槽位出现。上传错误不清空提示词及其他有效素材。

## 6. 状态与动作规范

每种状态只在其所属区域呈现，保持可用内容；禁止用全页遮罩替代局部错误。以下覆盖 D01–D09 中必须表达的状态，不等于原型已验证后端行为。

| 状态 | 所在位置与表现 | 主动作 / 限制 |
| --- | --- | --- |
| 令牌/模型准备中 | 编辑卡结构占位，说明正在准备 | 等待；不先展示无模型 |
| 无权限/分组不可用/令牌上限 | 编辑区域明确限制原因；区分文案 | 返回可用入口或已有说明路径；不增加不存在的购买流程 |
| 无模型 | 编辑区域独立空态 | 查看说明/刷新；不把读取失败归为无模型 |
| 历史初次加载 | 成果区结构骨架 | 不提前显示首访引导 |
| 历史初次失败 | 成果区局部错误 | 重试；可用表单保持可编辑 |
| 历史真正为空 | 紧凑引导和样片入口 | 开始创作 |
| 筛选后为空 | 作品库内说明筛选条件 | 返回“全部” |
| 无样片 | 灵感区域紧凑说明 | 自主创作继续可用 |
| 草稿恢复含失效素材 | 对应素材槽提示恢复要求 | 选择原文件/按现有流程恢复；不伪装 ready |
| 字段无效 | 字段下的具体说明，关联字段 | 修正输入；隐藏必填项所在高级区展开 |
| 覆盖非兼容草稿 | 确认弹层列明将替换的内容类别 | 取消/确认替换；默认焦点不放破坏性确认 |
| 上传/媒体检查/就绪 | 素材槽内文字和图标，可信上传进度可显示 | 仅 ready 素材参与生成 |
| 上传/校验失败 | 对应素材槽错误 | 采用现有续传/重选动作 |
| 准备报价 | 费用区占位与文字 | 不显示旧金额为当前金额 |
| 报价就绪 | 费用、币种和有效性说明 | 可付费生成；其他校验仍必须通过 |
| 报价过期/失败 | 费用区警告或错误 | 刷新报价，不提交旧报价 |
| 提交中 | 按钮显示提交状态 | 禁止同次重复触发，草稿不清空 |
| 受理后定位中 | 当前任务占位及回执号 | 获取任务；不构造可播放作品 |
| 定位超时 | 当前成果区说明“暂未定位” | 手动刷新/任务入口；不标生成失败 |
| 提交未知/恢复待核实 | 独立紧凑提醒，任务号存在时可复制 | 只读核实原任务；切成果不能隐藏提醒 |
| 排队/生成中 | 明确阶段；仅可信百分比可显示 | 可编辑下一次输入，不提供取消/删除 |
| 归档中 | 单独说明正在准备可播放文件 | 不提前播放或下载 |
| ready | 完整画面与下载、详情 | 无默认有声自动播放 |
| 明确失败 | 安全公开原因与任务入口 | 不承诺退款，不默认可重试归档 |
| 原因不可区分 | “暂时无法提供结果，请查看任务状态” | 查状态，避免自行推断失败阶段 |
| 媒体加载/签名失败 | 保留作品信息，仅播放器局部错误 | 一次自动恢复后手动重试，不触发生成 |
| 刷新失败/断网 | 保留已读内容，标“状态暂未更新” | 局部重试；恢复后重新查询 |
| 删除确认/删除中/删除失败 | 模态确认、明确进行中、局部失败 | 失败保留原项；成功后处理焦点与选择 |
| 无权限/已删除深链接 | 对应目标的不可用说明 | 返回作品列表；不闪现旧媒体或改选后冒充目标 |

未决提交恢复的持久化、请求指纹与 24 小时幂等边界严格以 PRD 第 5 节为准；它们必须通过实施验证，不能由视觉控件“查状态”模拟完成来宣称已交付。

## 7. 响应式、焦点和动效

以控制台侧栏之后的内容容器宽度决定布局。可用宽度 ≥850px 为双栏；不足 850px 使用单栏，编辑器在前、成果在后。全程保持同一个编辑器实例；不得为移动/桌面各复制一份输入状态。

手机提供“查看结果 / 返回编辑”锚点，提交后可滚动到结果，但不夺走仍在编辑的输入焦点。主操作在文档流内可达，避免固定页脚遮挡软键盘或内容；若后续采用吸底按钮，必须单独验收键盘、短视口和安全区。

弹层最大宽度 560px（纯确认可为 420px），宽度不超过视口减两侧 16px；最大高度不超过视口减 32px，并计入安全区。内容可滚动，标题和确认/取消操作始终可达；不能让背景与弹层同时滚动。

键盘顺序遵循视觉顺序。焦点为 2px `accent` 外轮廓，偏移 2px；不因隐藏轮廓破坏键盘识别。模态限制焦点在内部，Esc 关闭；关闭回触发项，删除后回相邻项/列表。字段错误程序化关联；受理、失败、完成只做一次克制播报，不随每次轮询重复播报。

长任务号、公开错误和多语言标签允许换行；摘要截断时提供完整详情，操作按钮不靠省略号表达。200% 文字缩放仍可完成操作。长提示词不能撑破卡片，必需说明不裁掉。

动效用于说明操作已生效和状态正在变化，主交互以 160–260ms 完成，避免所有控件同时运动。模式选中、按钮按下及焦点确认使用颜色、边框、轻微位移或缩放；当前作品切换使用短暂透明度和 4–8px 入场；高级设置、灵感区及弹层开合可使用局部高度/位移和透明度过渡。让操作前后的内容保持可追踪，不移动整页，也不因动效改变固定控件的尺寸和位置。

排队、生成、归档使用各自清晰的文字和静态形态作为第一信息；只有确实处于进行中的状态可添加克制的进度呼吸或线性流动，不能伪造百分比、可播放视频或任务已完成。报价准备可使用一次性的骨架提示；背景循环不得成为主要视觉元素。进入 `prefers-reduced-motion: reduce` 时停用上述位移、缩放、循环与自动预览，立即显示最终状态并保留焦点和文字反馈，默认静态封面。审查时实际触发模式切换、作品选择、折叠、弹层和任务状态变化，不能只凭 CSS 存在判定动效已交付。

| D07 任务 | 状态列表、任务号、公开失败原因、ready 作品入口 | 列表不变画廊、不重复取消/管理能力 |
| D08 深色/移动 | 同一 token 系统，320–390px、小屏长表单与确认弹层 | 暗色按钮前景、键盘/安全区/长文/焦点 |
| D09 系统状态 | 准备/受限/无模型/初次失败/真空/筛选空/刷新失败/断网 | 每种状态有准确解释和动作，保留可用内容 |

审查顺序：首先检查付费动作与恢复语义，其次检查编辑/结果上下文，再检查三页分工、媒体、响应式和无障碍，最后检查色彩、密度与细节。美观不能通过隐藏必要费用、状态和恢复提示获得。

## 9. 本轮评审记录与交付边界

UX 首轮提出的五项缺口在 PRD v1.1 文档层已关闭：D09 系统状态、断网旧快照、模态焦点与关键状态播报、媒体双向互斥、小屏/软键盘/200% 文字。实际原型仍须逐项核对；文档关闭不等于生产功能完成。

用户审查稿将使用独立演示控件切换 D01–D09、浅深主题和视口。审查控件位于产品画面之外。静态封面、假数据与按钮反馈必须明确为演示；不连接付费生成、真实删除或生产服务。

设计交付通过的标准是：推荐方向的主要画面可直接审查，关键状态有可达示例，行为与 PRD 不矛盾，剩余演示限制被明确列出。上线验收、真实浏览器兼容、媒体与上传、身份/费用安全仍属于后续实施验证。
