Token 是否能支撑代码助手工作流。</li></ul><h2 id="前置条件" tabindex="-1">前置条件 <a class="header-anchor" href="#前置条件" aria-label="Permalink to &quot;前置条件&quot;">​</a></h2><ul><li>已安装 Codex 或 Codex CLI。</li><li>已创建 KKRICH API Token。</li><li>已确认目标模型支持 Codex 所需的接口形态。</li><li>本页配置键参考 Codex CLI <code>0.106.0</code> 本地帮助和配置格式，其他版本需重新确认。</li></ul><h2 id="配置-kkrich" tabindex="-1">配置 KKRICH <a class="header-anchor" href="#配置-kkrich" aria-label="Permalink to &quot;配置 KKRICH&quot;">​</a></h2><ol><li>先完成 <a href="./codex-cli">Codex CLI</a> 的命令行验证。</li><li>如果桌面端读取同一份 Codex 配置，保持 <code>model_provider</code>、<code>base_url</code> 和模型名称一致。</li><li>将 Base URL 设置为 <code>https://api.kkrich.ltd/v1</code>。</li><li>使用 API Token 登录或配置密钥，具体方式以当前 Codex 版本为准。</li><li>在一个非关键项目中发送简单任务，例如“总结这个目录结构”。</li><li>到 KKRICH <a target="_self" href="https://api.kkrich.ltd/usage-logs/common">使用日志</a> 确认请求记录。</li></ol><p>如果通过 CC Switch 管理 Codex 配置，先在 Codex 页签中新增供应商，再填写 KKRICH 的 API Key、Base URL 和模型名称。截图中的 Provider 表单对应 Codex 桌面端或 CLI 复用配置时需要核对的字段。</p><p><img src="/images/feishu/feishu-07.png" alt="在 Codex 供应商配置中填写 KKRICH API Key 和 Base URL"></p><p>配置完成后，启用对应供应商，再回到 Codex 发送一次低风险任务，最后用 KKRICH 使用日志验证请求来源。</p><h2 id="成功验证" tabindex="-1">成功验证 <a class="header-anchor" href="#成功验证" aria-label="Permalink to aria-label="Permalink to &quot;常见失败&quot;">​</a></h2><ul><li>Codex 要求 Responses API：确认 KKRICH 当前模型和网关是否支持对应接口。</li><li>配置后仍走默认服务：重启 Codex，并确认当前 profile 或配置文件被加载。</li><li>模型无法工作：换用 KKRICH 控制台确认可用的模型名称。</li><li>认证失败：重新执行登录或检查 API Token 是否完整。</li></ul><h2 id="下一步" tabindex="-1">下一步 <a class="header-anchor" href="#下一步" aria-label="Permalink to &quot;下一步&quot;">​</a></h2><ul><li>想让 Codex
