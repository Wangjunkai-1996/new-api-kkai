&quot;安装后检查&quot;">​</a></h2><ul><li>打开 Cursor，确认能进入 IDE Settings。</li><li>确认当前版本支持自定义 OpenAI Base URL 或 OpenAI Compatible Provider。</li><li>在 KKRICH <a target="_self" href="https://api.kkrich.ltd/keys/">令牌管理</a> 创建一个 API Token。</li><li>在 KKRICH 控制台复制要用于代码任务的完整模型名称。</li></ul><h2 id="配置-kkrich" tabindex="-1">配置 KKRICH <a class="header-anchor" href="#配置-kkrich" aria-label="Permalink to &quot;配置 KKRICH&quot;">​</a></h2><p>Cursor 的配置入口在 IDE 设置里。不同版本字段名称可能变化，请以当前界面为准，按下面的关系填写：</p><ol><li>打开 Cursor Settings 中的 Models、AI Provider 或 API Key 相关页面。</li><li>新增 OpenAI Compatible Provider。</li><li>Base URL 填写 <code>https://api.kkrich.ltd/v1</code>。</li><li>API Key 填写你的 KKRICH API Token。</li><li>模型名称填写 KKRICH 控制台可用模型名称。</li><li>保存后，在 Cursor Chat、编辑或 Agent 入口选择刚添加的 KKRICH 模型。</li></ol><p>如果 Cursor 当前版本的界面字段名称不同，可以按下图的通用映射处理：API 请求地址对应 <code>https://api.kkrich.ltd/v1</code>，API Key 对应 KKRICH Token，模型名称以控制台可用模型为准。</p><p><img src="/images/feishu/feishu-07.png" 能返回模型回复。</li><li>代码编辑或 Agent 功能能使用所选模型。</li><li>KKRICH <a href="./../guide/usage-log">使用日志</a> 中出现 Cursor 请求，能看到 Token、模型名称和消耗记录。</li></ul><h2 id="常见失败" tabindex="-1">常见失败 <a class="header-anchor" <code>/v1/v1</code>。</li><li>请求很慢或中断：降低上下文规模，或选择更适合代码任务的 KKRICH 模型。</li><li>设置没有生效：重启 Cursor，并确认当前 workspace 没有覆盖配置。</li><li>使用日志没有记录：请求可能没有发到 KKRICH，重新检查 Provider、Base URL 和当前选中的模型。</li></ul><h2
