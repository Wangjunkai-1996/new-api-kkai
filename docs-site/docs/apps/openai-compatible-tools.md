<div><h1 id="openai-兼容工具" tabindex="-1">OpenAI 兼容工具 <a class="header-anchor" href="#openai-兼容工具" aria-label="Permalink to &quot;OpenAI 兼容工具&quot;">​</a></h1><p>OpenAI 兼容工具不是一个需要下载的客户端，而是一套通用字段映射规则。凡是目标工具支持自定义 OpenAI Base URL、API Key 或 OpenAI Compatible Provider，通常都可以把它的字段映射到 KKRICH。</p><h2 id="适用场景" tabindex="-1">适用场景 <a class="header-anchor" href="#适用场景" aria-label="Permalink to &quot;适用场景&quot;">​</a></h2><ul><li>文档中没有列出你正在使用的工具。</li><li>工具界面写着 OpenAI Compatible、Custom OpenAI、API Host 或 Base URL。</li><li>需要排查不同客户端之间的配置差异。</li></ul><h2 id="下载和官方入口" tabindex="-1">下载和官方入口 <a class="header-anchor" href="#下载和官方入口" aria-label="Permalink to &quot;下载和官方入口&quot;">​</a></h2><p>本页没有独立安装包，也没有所谓“OpenAI 兼容工具客户端下载”。请先从目标工具自己的 HTTPS 官网、官方文档、官方应用商店或官方 GitHub 仓库安装，不要把非官方镜像当作主要下载来源。</p><p>如果目标工具已经在本栏目中有单独页面，优先阅读对应页面；如果没有，再按本页字段规则手动配置。</p><h2 id="平台支持" tabindex="-1">平台支持 <a class="header-anchor" href="#平台支持" aria-label="Permalink to &quot;平台支持&quot;">​</a></h2><p>平台支持取决于目标工具本身。只要它在 Windows、macOS、Linux、浏览器、IDE、服务器或移动端提供以下能力，就可以尝试接入 KKRICH：</p><ul><li>支持自定义 OpenAI Base URL、API Host、Endpoint 或 NewAPI 接口。</li><li>支持填写 API Key、Token、Access Token 或 Bearer Token。</li><li>支持选择或手动输入模型名称。</li><li>支持 OpenAI Compatible、Custom OpenAI、NewAPI 或含义相同的 Provider 类型。</li></ul><h2 id="安装后检查" tabindex="-1">安装后检查 <a class="header-anchor" href="#安装后检查" aria-label="Permalink to &quot;安装后检查&quot;">​</a></h2><p>安装目标工具后，先不要急着填 Token，按下面顺序确认：</p><ol><li>确认应用来自官方入口，且能正常打开设置页。</li><li>找到模型、Provider、API Key、Base URL 或 Endpoint 设置。</li><li>确认工具允许使用自定义服务地址，而不是只能使用官方 OpenAI。</li><li>如果工具能自动拉取模型列表，确认它也允许手动填写模型名称。</li><li>准备好 KKRICH API Token 和控制台可用模型名称。</li></ol><h2 id="配置-kkrich" tabindex="-1">配置 KKRICH <a class="header-anchor" href="#配置-kkrich" aria-label="Permalink to &quot;配置 KKRICH&quot;">​</a></h2><table tabindex="0"><thead><tr><th>字段类型</th><th>常见名称</th><th>KKRICH 填写值</th></tr></thead><tbody><tr><td>服务类型</td><td>Provider / API Type</td><td>OpenAI Compatible / Custom OpenAI / NewAPI</td></tr><tr><td>接口地址</td><td>Base URL / API Host / Endpoint</td><td><code>https://api.kkrich.ltd/v1</code></td></tr><tr><td>密钥</td><td>API Key / Token / Access Token</td><td>KKRICH API Token</td></tr><tr><td>模型</td><td>Model / Model Name / Deployment</td><td>KKRICH 控制台可用模型名称</td></tr></tbody></table><p>配置顺序建议如下：</p><ol><li>新增一个 Provider，名称填 <code>KKRICH</code>。</li><li>Provider 类型选择 OpenAI Compatible、Custom OpenAI 或 NewAPI。</li><li>Base URL 填写 <code>https://api.kkrich.ltd/v1</code>。</li><li>API Key 字段填写 KKRICH API Token。</li><li>模型名称填写控制台可用模型名称。</li><li>保存后先关闭复杂功能，只发送一条普通聊天请求。</li><li>基础请求成功后，再开启流式输出、工具调用、多模态或长上下文等能力。</li></ol><p>大多数 OpenAI Compatible 工具都会出现类似的三个输入区：API Key、API 请求地址和模型名称。把 API 请求地址设置为 <code>https://api.kkrich.ltd/v1</code>，再选择或手动填写 KKRICH 控制台可用模型名称。</p><p><img src="/images/feishu/feishu-07.png" alt="OpenAI Compatible 工具中的 API Key、Base URL 和模型名称字段"></p><p>如果目标工具会自动拼接 <code>/v1</code>，最终请求不应变成 <code>/v1/v1/chat/completions</code>。遇到重复路径时，再把工具里的地址改为 <code>https://api.kkrich.ltd</code> 复测；公开推荐的 KKRICH Base URL 仍然是 <code>https://api.kkrich.ltd/v1</code>。</p><h2 id="成功验证" tabindex="-1">成功验证 <a class="header-anchor" href="#成功验证" aria-label="Permalink to &quot;成功验证&quot;">​</a></h2><ul><li>工具能返回模型回复。</li><li>KKRICH <a target="_self" href="https://api.kkrich.ltd/usage-logs/common">使用日志</a> 中出现请求。</li><li>使用日志里的请求时间、模型名称、状态和消耗与工具中的操作一致。</li><li>更换或关闭 Token 后，工具认证状态能随之变化。</li></ul><h2 id="常见失败" tabindex="-1">常见失败 <a class="header-anchor" href="#常见失败" aria-label="Permalink to &quot;常见失败&quot;">​</a></h2><ul><li>Base URL 重复：最终请求不应变成 <code>/v1/v1/chat/completions</code>。</li><li>工具只支持官方 OpenAI：无法接入自定义网关，需要更换工具或插件。</li><li>模型列表接口不兼容：手动填写 KKRICH 控制台可用模型名称，或在工具中关闭自动拉取。</li><li>Token 填写方式错误：API Key 字段通常只填 KKRICH API Token 本身，不要额外加 <code>Bearer </code>，除非工具明确要求。</li><li>流式输出失败：关闭 stream 后先验证普通聊天请求。</li><li>工具调用失败：确认当前模型和网关是否支持 tool calling。</li><li>使用日志没有记录：请求没有到达 KKRICH，优先检查 Base URL、当前 Provider 和代理设置。</li></ul><h2 id="下一步" tabindex="-1">下一步 <a class="header-anchor" href="#下一步" aria-label="Permalink to &quot;下一步&quot;">​</a></h2><ul><li>用 <a href="./postman">Postman</a> 或 <a href="./apifox">Apifox</a> 验证同一请求。</li><li>回到 <a href="./../guide/playground">Playground</a> 调整模型参数。</li><li>在 <a href="./../guide/usage-log">使用日志</a> 中定位认证、模型和额度问题。</li></ul></div>
