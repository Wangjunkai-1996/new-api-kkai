<div><h1 id="security-and-materials-policy" tabindex="-1">Security and materials policy <a class="header-anchor" href="#security-and-materials-policy" aria-label="Permalink to &quot;Security and materials policy&quot;">​</a></h1><p>KKRICH documentation must help users complete tasks without exposing private data, operational details, or copyrighted material. This policy applies to all docs pages, examples, screenshots, diagrams, downloadable files, and deployment notes published on the docs site.</p><h2 id="content-sources" tabindex="-1">Content sources <a class="header-anchor" href="#content-sources" aria-label="Permalink to &quot;Content sources&quot;">​</a></h2><p>Allowed source material:</p><ul><li>KKRICH product behavior verified in a sandbox, local build, staging environment, or approved release.</li><li>Original explanations written for KKRICH docs.</li><li>Synthetic examples created for documentation.</li><li>Public standards, protocol names, command names, and vendor UI labels when needed for accuracy.</li><li>Short third-party configuration references when they are necessary to help users connect KKRICH.</li></ul><p>Not allowed:</p><ul><li>Copied third-party or reference-site text, screenshots, diagrams, page structure, or original images.</li><li>Customer tickets, support chat logs, account exports, production database rows, or live transaction records.</li><li>Internal runbooks, unpublished incident notes, private architecture diagrams, or staff-only dashboards.</li><li>Screenshots that reveal real balances, orders, logs, IP addresses, invitation links, admin data, emails, API keys, or credentials.</li><li>Legal, compliance, or financial claims that have not been approved by the responsible owner.</li></ul><h2 id="sensitive-data-rules" tabindex="-1">Sensitive data rules <a class="header-anchor" href="#sensitive-data-rules" aria-label="Permalink to &quot;Sensitive data rules&quot;">​</a></h2><p>Never publish real secrets or private identifiers. tabindex="-1">Incident response <a class="header-anchor" href="#incident-response" aria-label="Permalink to &quot;Incident response&quot;">​</a></h2><p>If sensitive material is found in published docs:</p><ol><li>Remove or unpublish the affected page or asset immediately.</li><li>Revoke, rotate, or invalidate any exposed credential or link.</li><li>Capture the affected URL, commit, asset path,
