<div><h1 id="screenshot-checklist" tabindex="-1">Screenshot checklist <a class="header-anchor" href="#screenshot-checklist" aria-label="Permalink to &quot;Screenshot checklist&quot;">​</a></h1><p>Use this checklist for every screenshot, screen recording frame, terminal capture, dashboard crop, and tool-configuration image that appears in the KKRICH docs site. The goal is to keep documentation useful without exposing customer data, credentials, account state, or private operational details.</p><h2 id="capture-sources" tabindex="-1">Capture sources <a class="header-anchor" href="#capture-sources" aria-label="Permalink to &quot;Capture sources&quot;">​</a></h2><p>Prefer screenshots from controlled KKRICH sandbox accounts and demo environments. Do not use production customer accounts, real balances, real orders, real invitation links, or internal admin dashboards unless the content has been recreated in a safe sandbox.</p><p>Allowed sources:</p><ul><li>KKRICH sandbox or demo tenant configured only for documentation.</li><li>Local development UI with mock data.</li><li>Approved screenshots from owned reference documentation, after confirming the image supports the current KKRICH page and contains no secrets.</li><li>Self-made diagrams, annotated workflows, and synthetic UI states.</li><li>Minimal third-party tool configuration screenshots when text instructions alone are not enough.</li></ul><p>Avoid:</p><ul><li>Live customer sessions, production dashboards, production logs, and support inboxes.</li><li>Images copied from third-party or unapproved reference documentation.</li><li>Screenshots containing personal accounts, browser profiles, bookmarks, extensions, desktop notifications, or unrelated tabs.</li><li>AI-generated images that imply real KKRICH product behavior that has not been implemented.</li></ul><h2 id="required-redactions" tabindex="-1">Required redactions <a class="header-anchor" href="#required-redactions" aria-label="Permalink to &quot;Required redactions&quot;">​</a></h2><p>Before publishing, redact or replace all sensitive material:</p><ul><li>API keys, access tokens, session cookies, private keys, OTPs, webhook secrets, and authorization headers.</li><li>Email addresses, phone numbers, usernames, customer names, recipient names, and account identifiers.</li><li>Balances, deposits, withdrawals, invoices, transaction IDs, order IDs, and payment state.</li><li>Invitation links, referral codes, invite QR codes, campaign links, and admin deep links.</li><li>IP addresses, hostnames, ports, log paths, stack traces, request IDs, trace IDs, and internal service names.</li><li>Admin menus, staff-only settings, moderation controls, privileged roles, and unannounced feature flags.</li><li>Browser chrome that reveals a personal profile, saved bookmarks, notifications, or unrelated URLs.</li></ul><p>Use realistic placeholders instead of blur when the value must remain legible:</p><ul><li><code><a href="/cdn-cgi/l/email-protection" class="__cf_email__" data-cfemail="4b2f2e26240b2e332a263b272e65282426">[email&#160;protected]</a></code></li><li><code>sk_test_************1234</code></li><li><code>ORDER-DEMO-001</code></li><li><code>203.0.113.10</code></li><li><code>https://docs.example.test/invite/demo</code></li></ul><h2 id="capture-setup" tabindex="-1">Capture setup <a class="header-anchor" href="#capture-setup" aria-label="Permalink to &quot;Capture setup&quot;">​</a></h2><p>Use repeatable capture settings so screenshots remain consistent across the site.</p><ul><li>Viewports: capture desktop at 1440 x 900 and mobile at 390 x 844 unless a page needs a different size.</li><li>Theme: use the site default theme unless the page documents dark-mode behavior.</li><li>Browser: use a clean browser profile or automation context with no personal extensions.</li><li>Data: seed only synthetic demo data, preferably matching the page text.</li><li>Zoom: keep browser zoom at 100%.</li><li>Cropping: crop tightly enough to focus the reader, but keep enough surrounding UI to preserve context.</li><li>Format: use PNG for UI screenshots and SVG or PNG for self-made diagrams.</li><li>Names: use lowercase kebab-case names such as <code>api-key-create-redacted.png</code>.</li></ul><h2 id="review-checklist" tabindex="-1">Review checklist <a class="header-anchor" href="#review-checklist" aria-label="Permalink to &quot;Review checklist&quot;">​</a></h2><p>Each screenshot must pass this checklist before merge:</p><table tabindex="0"><thead><tr><th>Check</th><th>Pass criteria</th><th>Status</th></tr></thead><tbody><tr><td>Source</td><td>Captured from sandbox, local mock UI, self-made diagram, or approved minimal third-party config.</td><td>[ ]</td></tr><tr><td>Originality</td><td>Does not copy third-party images, text-as-image, diagrams, or vendor screenshots beyond necessary third-party UI configuration.</td><td>[ ]</td></tr><tr><td>Secrets</td><td>No visible key, token, cookie, password, webhook secret, private key, or authorization header.</td><td>[ gate&quot;">​</a></h2><p>A screenshot can be published only when:</p><ul><li>The page owner has completed the review checklist.</li><li>A second reviewer has inspected the image for secrets and copied material.</li><li>The screenshot has meaningful alt text or a nearby text equivalent.</li><li>The image path is referenced from the docs page that owns it.</li><li>Any third-party UI shown is limited to what readers need to configure KKRICH.</li></ul><p>If a reviewer finds sensitive content after merge, remove the image immediately, rotate or revoke any exposed credential, open an incident note, and replace the asset only after a fresh review.</p></div>
